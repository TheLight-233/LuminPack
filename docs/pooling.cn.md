# 缓存池与内存保留

[English](pooling.md)

## 设计

Core 使用线程本地快缓存和有界、无序的共享溢出缓存。`AtomicSlotPool<T>` 通过原子交换移除对象、转交独占所有权，通过比较交换将对象发布到空槽。独立的首槽处理普通共享复用，无须扫描溢出数组。取出和存入各自维护扫描起点提示；提示只影响查找顺序，不表示所有权，也不能提供精确的空/满快照。

该设计面向短时、通常同步的序列化操作和浅层嵌套，不需要 FIFO 顺序、队列分段、每槽序号或后台维护，预热后的成功租还不分配内存。竞争中的操作可能错过可用对象，随后正常创建新对象。每次溢出操作最多扫描配置的槽位数；大容量池在全空或全满时仍然是 O(容量)。容量应贴近同时持有的租约数量，而不是累计序列化的对象总数。

Crossbeam 有界 MPMC 队列维护 FIFO 位置和每槽发布序号；分段队列还会分配数据块。这些能力适合生产者/消费者管线，但复用缓存并不要求它们。队列同样使用原子操作，也不能消除竞争。本地测量过其 C# 参考实现，结果记录在不纳入版本控制的缓存池选型实验中。

## 保留量与生命周期

| 缓存 | 线程本地保留 | 共享保留 |
| --- | --- | --- |
| `ObjectPool<T>` | 每个闭合 `T`、每个线程一份，同类型池实例共用该槽并核对池身份 | 每池 `maxSize`，默认 16 |
| `LuminBufferWriterPool` | 普通构建每线程一个 writer | 最多 32 个 writer |
| 不可变集合 builder | 每个闭合 builder 类型、每线程一个已清理 builder | 每个闭合类型最多八个 |
| Frozen 构造暂存 | 无 | 每个闭合类型最多四个容器，并受容量准入限制 |

可选构建符号 `LUMINPACK_BUFFERWRITER_SECOND_TLS` 增加第二个线程本地 writer。正在租用的 writer 即使仍被 TLS 引用，也由租约状态阻止重复租用。嵌套租借会解除前一个活动 writer 的缓存归属，使其随后可以归还共享池。普通对象和 builder 池会在租出时移除 TLS 引用。

TLS 在线程存活期间持有强引用。空闲线程池线程可能长时间保留缓存，使用很多闭合泛型类型也会增加保留量。托管 TLS 本身不等于永久泄漏，但这里没有空闲超时或全进程 TLS 清理。线程终止后，不可达托管对象可以被回收；这**不保证**调用 `IDisposable.Dispose`。需要确定性清理时，应在每个工作线程调用本地清理 API。池实例变得不可达也不会自动清除该类型的 TLS 对象。

writer 归还时重置负载和引用状态。逻辑缓冲容量达到 `MaxPooledBufferSize`（4 MiB）时，线程缓存 writer 释放缓冲；非线程缓存 writer 则被释放。这些是对象数量和准入限制，不是整个进程的内存预算：数组池桶大小、上下文表容量、活动租约以及独立的框架 `ArrayPool<byte>.Shared` 保留量仍占内存。通用 `ObjectPool<T>` 依靠归还策略清理引用，并拒绝过大或资源过重的对象。

## 所有权与维护

- 使用结束后，将租约恰好归还一次到原池。归还后不得访问对象或其借用 Span。池的线程安全不代表租出对象线程安全。
- `ObjectPool<T>.Return` 在发布前调用策略。策略拒绝或无空槽接收的对象会被释放。若策略抛异常，对象尚未发布，调用者仍负责所有权和清理。
- `ObjectPool<T>.MaxSize`、`AvailableCount`、`GetAllItems()` 只涉及共享存储。容量为零时 TLS 仍然启用。并发计数是近似值；快照只是诊断引用，不是租约，不得据此修改、归还或释放对象。
- `ObjectPool<T>.ClearThreadLocalCache()` 清除调用线程上该闭合 `T` 的槽，不论槽属于哪个池。调用释放回调前先移除引用，支持释放重入和异常。
- `LuminBufferWriterPool.ClearThreadLocalCache()` 只清除调用线程的 writer 槽。活动 writer 只解除缓存归属，租约继续有效，直到后续归还。该操作不清理其他线程或共享存储。
- `ObjectPool<T>.Resize` 要求静默期，不能与其他池操作并发。它先发布替代存储，再释放多余对象，因此释放回调可以重入池。它会处理所有多余对象，再以 `AggregateException` 汇总释放异常。TLS 不变。

.NET 8 及以上由 `T` 实现静态 `IPooledObjectPolicy<T>` 成员和 `IDisposable`。`netstandard2.1` 构造时传入 `IPooledObjectPolicy<T>` 策略实例。共享算法仅依赖可移植的引用原子操作和有界数组访问，不依赖 SIMD、指针宽度或原生队列布局。
