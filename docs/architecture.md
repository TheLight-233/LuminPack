## Runtime execution model

Modern Core assets provide typed JSON writer overloads for `DateOnly`, `TimeOnly`, `Int128` and `UInt128`. They format into bounded stack buffers and retain their JSON string representations (`O` for dates/times, invariant decimal for 128-bit integers). Their formatting bodies remain outside generated callers. The generator checks the referenced Core API before selecting them; consumers referencing an older or netstandard asset retain the existing string conversion path, regardless of the consumer's framework symbols.

The private formatted-scalar path also serves `DateTime`, `DateTimeOffset`, `Guid` and `TimeSpan`. These exact formats produce bounded, escape-free ASCII. On .NET 8 and later, UTF-8 profiles format directly into bounded byte scratch and publish the complete payload through a shared outlined copy. The fixed 36-byte Guid representation formats into the same validated destination reservation, using the value captured before output callbacks. Other scalars finish formatting before callbacks and reserve their actual payload length. Older targets retain the shared outlined character encoder; UTF-16 copies the formatted characters directly. Output capacity checks, quotes, comma state and failure publication remain in effect.

`StringBuilder` binary writes copy into the complete reserved character payload when the referenced framework exposes the span `CopyTo` API; older framework fallbacks remain available. JSON writes take a complete snapshot before publishing output, using bounded stack storage or a returned pooled character buffer. Null and empty writes stay outside the snapshot frame. `LuminPackJsonWriter.WriteStringBuilder` and `WriteStringBuilder<TOptions>` expose this operation without changing null-literal binding for `Write`. The matching `LuminPackJsonReader.ReadStringBuilder` overloads keep decoding and construction in a shared runtime entry. Generated calls check the referenced runtime API. JSON reads consume complete unescaped token spans. UTF-8 content decodes through bounded stack storage or a returned character lease, using the ordinary decoder replacement behavior. Fresh builders receive the original string constructor capacity and are populated before publication; reused builders clear and append only after complete decoding. Both encodings avoid intermediate strings after pool warmup; pool misses can allocate.

`Version` keeps its fixed binary record and the two-, three- or four-component JSON string. Named `WriteVersion` and `ReadVersion` JSON operations, including their compiled-profile overloads, avoid changing `Write(null)` binding. Writers format into bounded stack storage, directly as UTF-8 on .NET 8 and newer, and as characters otherwise. Generated readers parse complete UTF-16 token spans; .NET 10 and newer also parse UTF-8 spans directly. Older UTF-8 readers decode through bounded or pooled character spans before calling the BCL parser. The modern unselected-token path likewise keeps the original character-parser exception behavior without constructing a token string. Formatting and parsing stay in shared runtime bodies selected by actual API availability, with existing BCL validation, fresh result identity and failure publication.

`Type` writers remove the established assembly qualifiers into bounded stack or returned pooled character storage, then encode that snapshot directly. The shared matcher preserves the original Unicode digit and word categories, non-newline version separators and token alternatives. Binary output retains the existing length/token/VarInt and compact Latin-1 representations; JSON uses the normal string-content kernels. An unchanged-name binary fallback is outlined to keep the regular string writer out of the normalization budget. Generator selection requires both default and compiled-profile writer signatures in the actual runtime; older assets retain regex replacement. Type resolution, culture identity, URI construction and lazy value forcing remain unchanged. Long-name pool misses and BCL resolution allocations remain possible.

`BigInteger` retains its signed little-endian binary payload and invariant quoted decimal JSON representation. Binary readers select `LuminPackMarshal.ReadBigInteger` when the referenced runtime exposes it. The shared constructor normalizes negative sign extension and converts sign-only upper limbs through bounded stack or returned pooled bytes, avoiding temporary BCL trimming arrays while keeping only the final magnitude allocation. Large negative powers use a validated zero-prefix scan and public integer construction. Positive and already compact representations retain the BCL constructor; payloads near the signed bit-count limit also retain it to preserve runtime arithmetic-limit behavior. Vector work is outlined before construction; 32-bit accesses use individual four-byte values. Header and payload checks, wire bytes and failure publication stay unchanged. Named `WriteBigInteger` / `ReadBigInteger` operations and their compiled-profile overloads avoid changing numeric `Write` overload resolution. Formatting uses bounded stack storage or a returned pooled character buffer. Before .NET 10, the formatter converts public magnitude bytes into base-10 groups with bounded or pooled scratch to avoid BCL formatter arrays; complete UTF-16 token spans parse directly, while UTF-8 tokens decode into bounded or pooled characters. Older targets parse ordinary invariant decimal text with bounded or pooled limbs, retaining BCL validation fallback and its large-value parser. Generated callers select these shared operations from the referenced runtime metadata and retain the previous string-based fallback for older runtimes. Null strings still fail through the BCL parser, and failed reads do not publish a replacement value. Retained-buffer writes avoid temporary managed allocations after pool warmup; reads retain BCL parsing and construction behavior, including runtime-specific temporaries for very large numbers. Pool misses and newly created output buffers can still allocate.

`TimeZoneInfo` JSON reads compare complete decoded snapshots with the existing bounded cache before creating a string. UTF-16 uses the decoded token span; UTF-8 uses a 256-character destination for cache-eligible text and retains the original string decoder for longer snapshots. UTF-8 payloads longer than three times the character limit bypass the admission count. Cache misses keep the original parser, admission and replacement rules. Hidden `ReadTimeZoneInfo` default and compiled-profile entries keep this work outside generated callers; the generator checks both APIs in the actual Runtime reference and retains the string-based fallback when they are unavailable. Selected-null branches, token validation, decoder replacement, failure publication and binary operations are unchanged. Warmed cache hits avoid the intermediate snapshot string; misses, first-use operation state and unescape scratch growth can allocate.

Shared UTF-8-to-character token decoding preserves the host's replacement grouping. On the portable asset, the legacy default `UTF8Encoding` implementation uses bounded scalar and packed-word kernels without temporary replacement-fallback objects. Modern or unrecognized default encoding subclasses keep their BCL decoder. This selection has no cached policy object and introduces no native hook invocation. Complete output windows need no per-scalar output check; short constrained tokens stage at most 768 characters on the stack before copying a successful result. Bounded admission also uses this staging on modern targets, avoiding the separate BCL character-count pass and its malformed-input fallback allocations. Modern targets reject oversized ASCII prefixes through the BCL ASCII validator before staging. Capacity failures retain the BCL exception and partial-write behavior. These operations serve builder and legacy scalar reads, character reads, time-zone snapshots and UTF-16 property names; their binary representations remain unchanged. Pool misses, parser failures and longer constrained BCL fallback paths can still allocate.

- **Cursors.** Each reader and writer advances a single cursor: `ref byte` on modern targets, `byte*` on `netstandard2.1`. The retained `Buffer` window supplies lengths and back-patching.
- **Two registers.** Beside the cursor, each state caches the end of its window (`_end`, or the writer's `_recordLimit` growth threshold). Range checks are one subtraction and one signed comparison. Setting `Buffer`, `BufferCheckLimit` or `Owner` (internal setters) refreshes the cache.
- **Cursor-local generated writes.** Generated object writers keep the cursor in a `ref byte cursor` local, which the JIT keeps in a register, and call `ref`-returning writer operations. Consecutive bounded members share one `ReserveRecord` check and are then stored unchecked. The cursor is published with `CommitRecords` before any operation that uses the writer itself.
- **Reader checks.** `EnsureReadable(count)` compares against the cached end before every unsafe load; it is active in Debug and Release.
- **Failure paths.** Simple exception helpers contain a direct throw and leave inlining policy to the runtime. RyuJIT can inspect that IL, recognize a nonreturning call and shorten success-path value lifetimes; forcing `NoInlining` can prevent that analysis. Checked JSON cursor diagnostics run inside the throw helper, preserving overflow and bounds exceptions without expanding every successful advance.
- **JSON floating-point reads.** The fast numeric scanner remains eligible for aggressive inlining. Scaled single-precision mantissas use Int32 conversion after their 24-bit range check. Complete numeric rescanning and fallback parsing run in separate non-inlined methods, keeping their local state out of generated callers while preserving grammar, rounding, finite-value checks and cursor publication. Older targets send integer magnitudes vulnerable to intermediate rounding to the exact parser. Modern UTF-8 fallbacks retain the legacy parser for tokens of at most nineteen bytes whose mantissa ends in a nonzero digit; other tokens use the invariant floating-point parser shared with UTF-16. This avoids ambiguity from untrimmed zero tails. netstandard2.1 widens the already validated ASCII token into bounded stack storage or a returned pooled buffer.
- **Validated text narrowing.** ASCII classification tests the high bits of UTF-16 lanes directly, avoiding unsigned-comparison adjustments in short encoders, reuse comparisons and the long-run loop. ASCII runs, medium short-string encoding and medium compact Latin-1 records share a 256-bit narrowing primitive after character classification. On AVX2 without AVX-512BW, saturated packing and lane reordering omit the truncation masks required for unrestricted UTF-16 values. Other platforms retain the generic vector lowering. Range checks, overlapping bounded tails and fallback semantics remain with the callers; Burst projects the same primitive from Core.
- **Options** are stateless value-type profiles (`ILuminPackOptions`) passed as generic arguments, so profile decisions fold to constants.
- **Buffers.** `LuminBufferWriter` is an `IBufferWriter<byte>` over one `ArrayPool<byte>.Shared` array, together with the binary/JSON reference states of an append session. Its usable range starts on a 64-byte boundary observed at rent time. Logical capacity and growth thresholds remain independent of pool bucket sizes; a growth that fits the rented array extends the range in place. Writers take a `ref byte` when they bind to the storage or refresh it after growth; on netstandard2.1 they take a `byte*`, and the buffer keeps the rented array pinned with a `GCHandle` from rent until return.

Binary and JSON readers constructed from a buffer bind its reader reference context. Writers resolve an explicit reference context first, then the associated buffer context. `OptionState` provides an initialized context.

### Operation pipeline

`NamedBinaryMemberKernels` gives eligible source-owned positional classes one `RootWriteMember` body. Its payload-specific state forwarder is named `SerializeMember_<identity>`, so callers bind one concrete method. The member body keeps the original null/member header, adjacent-field address proofs, architecture-specific fixed stores and string operations. It does not substitute the standalone root's fused capacity reservation. This path requires at least one string field and accepts public raw fields alongside strings, excluding generic types, inheritance, callbacks, property/private storage and bounded declarations. Other contracts keep their existing emitters. Explicit member profiles continue through the bound operation path; they must not be replaced with the caller's document profile.

When an ordinary public-field root consists only of complete runtime record kernels and named members without a separate profile boundary, `SerializerCoreProjection` can lower the emitted write directly from the cached type metadata. It retains the original root/member methods, declaration options and final storage/cursor projections. Readers, JSON and more complex writes retain their existing checked operation pipeline. Member kernels remain eligible for aggressive inlining; a parent containing member calls leaves its root inline decision to the runtime even when extraction reduced its source call count. The allocating facade keeps `AllocateUninitializedArray` and its existing pool ownership and cleanup.

SourceGenerator files use `LuminPackGen.Namespace.Model.g.cs`, with `LuminPackGen.Layouts.` for storage views and `.UnionDispatch.g.cs` for Union support. They do not use the `Extension` suffix. Aggregate files retain descriptive families such as `LuminPackSerializer.System.Int32.g.cs` and `LuminPack.Formatter.System.Collections.Generic.List_Of_System.Int32_End_.g.cs`. Hint names contain no hash suffix: namespace and generic/array structure remain readable, punctuation is escaped distinctly, and long identities use bounded directory components instead of truncation. Private generated symbol identities remain independent of filenames.

Framework field classification uses CLR metadata names, such as `System.DateOnly`, in `CodeEmitterTypeCatalog`. These names do not include the C# `global::` qualifier used in emitted source. The same catalog classifies direct fields, nullable values and collection elements before considering user-defined object constructors.

1. Analyze the canonical type contract and freeze operation templates.
2. Lower eligible complete runtime-kernel writes directly from type facts; otherwise bind the root and compose nested operations, keeping recursive, `Custom`, virtual and specialized boundaries.
3. Bind calls to the serializer state bodies and propagate compiled profiles.
4. Normalize reader storage lifetimes and cursor slots.
5. Simplify blocks and choose readable local names (presentation only).
6. Format, add XML documentation, and publish the text through the cache boundary.

Operation templates remain immutable syntax between JSON helper extraction, input-check insertion, operation binding and serializer projection. These stages do not print and reparse their intermediate templates or format them before binding. Formatting belongs to final emission; the external JSON support text boundary normalizes its template before parsing it. Frozen plans retain syntax and value data without retaining a consumer compilation, semantic model or symbol. Syntactic name and argument-count filters only exclude impossible helper substitutions; candidate calls still use semantic identity. These generator-side changes preserve the emitted bodies and their native inlining policy.

Source composition and native inlining have separate budgets. `GeneratedExecutionPolicy` leaves binary and JSON state bodies with loops or more than sixteen invocation sites to the runtime's inlining policy; small bodies retain their aggressive inline hint. Removing this hint does not prohibit inlining or change nested binary source expansion. Complete JSON operations containing loops or exceeding the same call-site threshold reuse their existing concrete state entries instead of copying their parsing state into every parent or Union case. Local storage operations remain composed at their original access sites. The call-site threshold is a generator heuristic, not a RyuJIT limit; bounded composition also helps avoid the runtime's minimum-optimization fallback for overly complex methods.

In a binary root writer with at least 32 bound operation sites, eight or more sibling writes of the same framework collection can call its existing closed writer. This applies when the collection loop formats a compound element that itself writes nested values. The decision counts sites outside loops, local functions and reserved-capacity regions. Each call receives the original writer and member profile. Keeping the loop in one method gives its element accesses a separate native inline budget.

A binary read with at least 384 source locals can give large sibling member branches their own static local functions, including branches inside a collection element loop. At least two branches must qualify, each with at least 64 locals. The generator checks the class receiver and its exact storage type, rejects external bindings and control transfers, and passes the original reader by reference. Each function contains the original validation, reuse and publication statements.

After root projection, `RootInliningPolicy` can restore an inline hint to a small JSON framing wrapper whose traversals are explicitly non-inlined helpers. It excludes those helpers from its statement/local budget, rejects loops and anonymous functions in the remaining body, and preserves existing inline policies. This keeps an extra wrapper call from penalizing empty and short records while leaving iterator state in independent methods. The bounds are generator heuristics, not exact IL or native size estimates.

After scalar calls are bound, the same policy gives repeated floating-point reads in call-heavy JSON roots independent native budgets. A root with multiple parser sites and more than sixteen invocation sites in its own method scope uses a static, non-inlined local entry shared by scalar type and compiled profile. The entry calls the existing complete reader operation; the JIT can inline its scanner and small accessors without importing the parent object's locals. Small roots and single-site collection loops retain their original calls. Local functions and lambdas have separate scopes and do not consume this source budget. These entries capture no state, use the same reader by reference, and preserve validation, cursor updates and field publication order.

Fixed Union cursor kernels retain their aggressive inline hint: their optional framing and architecture branches specialize using the caller's constants, so the un-specialized source call count is not a useful size estimate for these kernels.

The same execution policy uses the element contract to specialize fresh Union containers. A null list or array enters its existing fresh operation; reused storage retains its ordinary operation. Fresh lists, arrays and immutable arrays read each Union through a zero-initialized local and publish it to the element slot after success. This makes the fresh value visible during JIT optimization, removes element reuse decisions, and avoids keeping an element address live across payload construction. Union dispatch, registered cases and publication on failure remain unchanged. Ordinary objects and Custom formatters keep direct element storage because their earlier publication is observable. The policy does not infer physical object layout or replace runtime bounds checks.

Binary and JSON reads of immutable lists and queues, including their interfaces, select span factories from the actual referenced API signatures. When only enumerable factories are available, a completely filled pooled array is passed directly; a partial buffer retains its counted `ArraySegment<T>` adapter. Older JSON list factories still use a single-element factory for one item and builder insertion for two or three items. The factories copy into final collection storage before the lease is returned. Element reads, null/empty behavior, failure publication and reference-buffer clearing retain their existing order and contracts.

Portable BitArray binary operations validate the actual backing-array representation in addition to its probed field offset. Supported writes copy directly into the writer and preserve public CopyTo padding in the destination, without renting temporary storage or mutating the source. Reads fill a fresh word-rounded result, apply the original public length adjustment and publish after successful payload reading. Empty and extreme counts and retained-capacity write cases keep the established fallbacks. The generator requires exact optional helper signatures from referenced metadata; older Core assets retain their original code. Modern generated reuse and both JSON paths are unchanged. All remaining temporary leases continue to use native ArrayPool policies, including pressure-driven trimming.

Immutable queue writers use validated stack views in binary and JSON. The front stack and an existing reversal cache are enumerated directly. An uncached multi-element back stack is reversed into a pool lease; a generated non-inlined helper writes it and returns the lease in `finally`, clearing references. Empty and singleton back stacks need no lease. Serialization leaves the framework's lazy cache uninitialized, so later application enumeration may still create it. Unknown layouts and arbitrary interface implementations retain public enumeration. Generator capability checks require both complete runtime helper signatures and invalidate when referenced metadata changes. Zero extra allocation applies after runtime/pool warmup; initialization and pool misses can allocate.

Immutable list and queue reads in both formats select the public span factory from the actual referenced API, including older target frameworks whose collection package already exposes it. References without the unconstrained span overload retain their enumerable or small-list construction. This shared capability applies to concrete and interface declarations and is recomputed when the consuming compilation changes. JSON immutable stacks consume the completed buffer from last element to first through `Push`, matching the binary path without reversing the buffer or boxing an enumerator. These paths keep top-first stack order and publish only the completed result. Null/empty behavior, element callbacks, validation and pooled-reference clearing remain unchanged. When the span factory is available, construction allocates only the returned collection and its result nodes; older factory fallbacks and pool misses can allocate temporary storage.

JSON readers that assign directly to constructed objects track recognized writable fields until the original missing-member reset point. Four or more such fields share unsigned 32-bit presence masks; smaller contracts keep Boolean flags. Members already staged in default-initialized locals need no presence flag. This reduces generated local state without changing field read order, object publication, reuse, constructors or Local + As storage access.

Untrusted binary reads, the default, are the ordinary read templates with checks inserted at their read sites (`SafeReadProjection`): object markers, Boolean loads and batches, collection counts and strings call small `LuminPackInputPolicy` adapters with the root's limits as constant arguments. Plans of nested types are keyed by the root's limits, so a nested type inherits them. Raw primitive arrays and lists keep their runtime kernels, with the count and Boolean checks after the call. A nested user record inside an untrusted record keeps its own checked helper, so each body stays within the JIT's inlining budget. Version-tolerant, reference-tracked and Union templates pass through the same projection; back references are type-checked and compressed counts checked before allocation. Undeclared limits are `int.MaxValue` constants, which the JIT folds away. Recursive types with a declared depth limit count their depth on the Reader. `SafeContract` rejects input-selected types; their operations fail closed. Write-only projections ignore the input policy, and Union write slots use a trusted profile identity. A nested binary read whose own entry applies the same frozen limits keeps the trusted reuse decision and calls that checked entry; raw framework scalars other than Boolean keep the trusted call that is lowered to a direct load. Writes and JSON never change under the input policy. An untrusted parent expands a nested ordinary record exactly like a trusted one, checking its member marker in the same branch. A Boolean array is read by `ReadCanonicalBooleans`, which copies and validates its storage in one vector pass. A fixed field batch whose Booleans lie in one four- or eight-byte window tests their input bytes with a compile-time mask in `ReadCanonicalBatch`. Rejection helpers throw directly, so the JIT treats them as no-return calls and keeps them out of the hot path. The recursion stack guard compares the frame address with the lowest frame the runtime already accepted on the thread and asks the runtime only below it. Untrusted facades are the trusted facades plus the input cap, and JSON facades of explicit hostile-input declarations select the strict depth-bounded profile.

Version-tolerant writers copy one cached revision-2 prefix (header, metadata and member widths) and write the members in one pass, reserving and patching the `int` length of each variable member. Records of fixed-width members are direct records with a constant width. Version-tolerant writers write the table only in the first record of a model per operation and a fingerprint in later ones; evolved readers cache tables by fingerprint in the reader state. Reference-tracked writers store the constant slot table and the reference id into the record's first reservation and write the members like an ordinary object. Readers compare a matching table as constant words and read into the object directly; any other table takes a path that keeps slot widths in locals and reads unknown trailing slots again from the input. Reference identities use a short reference scan, then an open-addressing identity map; readers store sequential ids in an array.

Short block copies of seventeen through thirty-two bytes use two bounded 128-bit head/tail accesses inline on supported 64-bit targets. They avoid both a call boundary and dirty upper 256-bit state; the fixed 128-bit width is intentional even when wider vectors are available. Larger short vector copies run out of line: a 256-bit copy inlined into a large caller left the upper vector state dirty for the caller's next runtime helper (an allocation or block copy), which cost about a hundred nanoseconds. Cached version prefixes are copied with word stores for the same reason. Scalar, 32-bit and unsupported-target fallbacks remain separate.

Int32/UInt32 reference lengths and ids keep their positive one-byte path small, with the original tagged conversions in outlined helpers.

Immutable interface writers recognize exact framework implementations before selecting concrete traversal; custom implementations keep their interface enumeration. Static, non-inlined local entries keep concrete iterator state outside the calling root. JSON covers immutable lists, boxed immutable arrays, sets, queues, stacks and dictionaries. Binary interface sets and dictionaries use the same selection; boxed immutable arrays retain the existing count back-patch and default-value failure path.

JSON writers for concrete immutable lists, sorted sets and sorted dictionaries use the checked tree copy described below. The exact framework list behind `IImmutableList<T>` shares this path. Each nonempty write rents space for all elements or pairs and returns the array in `finally`, clearing references. This costs O(n) temporary space, and a pool miss may allocate. The list probe verifies its closed node fields and empty sentinel, then compares three item addresses with the public `ItemRef` results before enabling the in-order walk. Unknown layouts use public enumeration. Generators targeting an older runtime check for the matching copy overload before emitting the call.

Hash-set and hash-dictionary JSON writes, plus their interface binary writes, reuse the checked `LuminTreeStorage.CopyTo` path into a returned array lease. This preserves immutable enumeration order and element formatting while avoiding the BCL collision-bucket enumerator's temporary allocations. References in the lease are cleared on return, including after element failures. Concrete binary raw and staging paths retain their existing selection. Known layouts and warmed pools avoid temporary managed allocations; pool misses, first-use BCL caches, custom implementations and the retained public-enumerator fallback for unavailable layouts can allocate.

Binary `SortedList<TKey, TValue>` writes retain the original storage selection and captured count. Validated key and value spans keep array-out-parameter state and repeated bounds checks out of the normal loop. The compatibility copy runs in a non-inlined local function and returns both staging arrays in `finally`, clearing references; the first lease is protected while acquiring the second. Collection capacity planning binds the nearest function's payload and count symbols, never an outer function's locals. Canonical zero-based helper loops may use their captured count parameter after verifying that the body cannot modify the iteration range.

Concrete JSON sorted-list writes select checked storage traversal when the referenced runtime exposes its complete optional API. The existing storage and mutation-version probes validate the key/value ranges. Every iteration captures the entire pair before either formatter runs and checks the version at each original enumeration boundary, including after the last pair. Mutation failures retain `InvalidOperationException` and use the library's collection-modified diagnostic. Unknown layouts use the original public enumerator in an outlined fallback; older runtime references keep the previous generated operation. Validated warmed writes avoid the boxed enumerator allocation, including concretely declared fields inside generated objects. First-use probes and the public enumeration fallback can allocate. Interface-declared collections, JSON reading and binary operations retain their existing contracts.

Concrete `ConcurrentQueue<T>`, `ConcurrentStack<T>` and `ConcurrentDictionary<TKey, TValue>` JSON writers use the public `IsEmpty` query for the existing empty branch. They retain the public enumerator and its snapshot or concurrent-observation behavior. This avoids counting an entire stack or acquiring all dictionary locks solely to test emptiness. `ConcurrentBag<T>` retains its count query because `IsEmpty` can initialize thread-local storage when first queried from a foreign thread. Binary counted traversal, collection construction, element callbacks and reader publication are unchanged; enumerator and snapshot allocations remain subject to the BCL and runtime.

Set-interface writers select the public value-type enumerator for exact `HashSet<T>` and `SortedSet<T>` implementations. `IReadOnlySet<T>` also uses the public Frozen enumerator when the referenced framework metadata exposes it. Concrete loops are separate static operations. Derived and unknown implementations use interface traversal. JSON keeps its original count query and array framing, and binary fallback paths keep counted header publication. Empty exact sorted sets skip enumeration after the original binary header capacity check. Nonempty sorted sets still use the heap-backed traversal stack inside the public enumerator.

Empty Frozen reads return the framework's shared empty result after the existing binary header validation or JSON token consumption. Nonempty values retain their construction and failure publication. Singleton immutable hash and sorted sets use the established public single-item factories in the runtime storage constructors and staged JSON readers, avoiding an intermediate builder. Multi-item construction, duplicate/comparer behavior, pooled staging and the existing binary weak-candidate caches retain their own paths. These specializations do not imply that all set reads or arbitrary interface implementations avoid temporary heap allocations.

Tree construction owns each hash-ordering array from acquisition through comparison and node creation, including layout self-checks. The caller returns it on success, collision fallback, null-key fallback and exceptions; a fallback builder starts only after the rental is returned. Portable raw set writers likewise return their staging arrays when copying or output reservation fails. These cleanup boundaries preserve the original exception, callback order and result publication without adding managed allocations to warmed successful operations.

Shared hash ordering retains each signed hash above its original element index. Already ordered keys with hash collisions skip sorting while still selecting the original collision fallback. The portable asset uses a bounded, nonrecursive heap sort when the core library is `mscorlib`, avoiding the legacy BCL range-sort delegate allocation; modern core libraries retain their BCL sorter. Only the initialized array prefix is read or moved. Hash callbacks, duplicate order, constructors, cleanup and generated binary/JSON operations retain their existing contracts. The warmed sorter needs no managed allocation or additional scratch; initial runtime classification and existing layout/pool initialization can allocate.

Direct immutable tree construction retains the original single-item factory, then completes that fresh, unpublished result and its root node instead of cloning the owner and discarding the first node. This applies to the existing distinct-hash set/dictionary paths and ordered portable set/dictionary paths. Modern sorted-tree constructor bindings remain selected where available. Shared empty nodes and previously published collections are never modified. Hash/comparison calls, fallback construction, result publication and binary candidate caches retain their existing behavior; JSON builder paths remain separate. Warmed eligible construction allocates only the returned collection and its result nodes. Layout probes, comparer initialization, pool misses, user callbacks and fallback builders can still allocate.

Framework scalar and string `ImmutableHashSet<T>` / `IImmutableSet<T>` reads also select a validated constructor for collision buckets. The generator checks the element's actual core-library identity and both runtime overloads. Two-element interface binary reads use two locals without staging; longer reads return their pooled element arrays in `finally`. Completed inputs are ordered by hash and original index, deduplicated within buckets while retaining the first representation, and linked into final nodes. Collision lists reproduce sequential AVL append topology to retain later removal and enumeration behavior. Portable nodes clone the established empty sentinel when a validated direct allocator is unavailable. Concrete binary caches and exact reuse comparisons remain in place; JSON and interface results retain fresh construction. User-defined hashing and equality keep their original builder and callback order. Missing APIs or failed layout probes retain the prior path. Warmed supported construction allocates only the final owner and nodes; cold initialization, pool misses and builder fallbacks can still allocate.

Immutable sequence and dictionary JSON readers consume the original first token before acquiring temporary storage. An empty result returns the same concrete family's shared `Empty` value without renting a sequence buffer or creating a dictionary builder. Nonempty inputs retain their original token loop and construction. Reused mutable dictionaries with a validated zero element count consume the array end and clear the same instance before returning, preserving its comparer. Empty raw immutable-list binary writes and portable `BitArray` writes keep the existing empty-span writer without a pool lease; portable empty `BitArray` reads use shared empty staging while retaining their fresh result construction. Fresh empty concurrent-dictionary binary reads call the original construction helper with shared empty pairs. Nonempty staging, public enumeration, default concurrency, bounds checks and failure publication remain unchanged.

Select collection traversal and construction using storage layout, formatter capabilities and callback behavior. A benchmark key/value type combination must never select a separate algorithm. Generated JSON dictionaries frame every entry as an array and dispatch each component through its formatter. Existing generated assemblies retain their callable runtime signatures.

Read-only memory and array segments capture each JSON element before formatting it. Segmented sequences use a position cursor and preserve the separator across empty segments. Mutable memory reads each referenced element after separator callbacks.

Sequence interface writers select the public concrete enumerators of exact framework lists, arrays, queues, stacks and linked lists when the declared contract permits them. The individual loops remain outlined, so their iterator state does not accumulate in the dispatcher's inline budget. A checked runtime helper can also follow exact ObjectModel wrappers to the list or array that their public enumeration uses; derived types, unknown layouts and deeper wrapper chains keep public enumeration. The helper returns the existing storage reference without allocating an adapter. Binary interface framing and stack order remain distinct from the concrete queue and stack representations.

The same sequence traversal can unwrap the existing enumerable of a sealed `LuminPackGrouping` without constructing an adapter. Sealed `LuminPackLookup` writes use its unboxed dictionary entry enumerator, avoiding both the values view and enumerator box. The original public enumeration APIs remain available; arbitrary LINQ implementations keep their public traversal. Generated unboxed lookup loops remain separate from the dispatch body to contain iterator state and repeated element formatter expansion. All discovery and reachability graphs retain the closed enumerable dependencies that grouping and lookup operations use implicitly.

Priority-queue JSON writes can use a checked heap span and a separately validated mutation version. Each complete element/priority pair is captured before formatting, with version checks before each pair and after the last pair. Unknown layouts and older runtime metadata keep `UnorderedItems` enumeration. Binary writes retain their existing node-access semantics. Binary queue and priority-queue copying factories pass the existing staging array when its entire length is consumed, or the shared empty array for empty slices; partial slices retain `ArraySegment`. The same constructors, bulk heapification, capacity, reuse, staging cleanup and publication rules remain in effect. Concurrent-bag JSON writes enumerate the same `ToArray` snapshot directly, keeping the original count gate while avoiding its array enumerator object. Snapshot arrays and concurrent queue iterators remain allocation sources.

Fixed JSON property-name choices for groupings, `Complex` and `Plane` compare the reader's decoded UTF-8 or UTF-16 token spans through the hidden `ReadStringChoice` operations. The selected choice is saved before the next token invalidates those spans. Actual runtime metadata selects the default and compiled-profile overloads together; older assets retain string comparison. Escaped names, unknown names, duplicate properties and existing failure publication keep their original behavior.

Observable JSON readers omit notification payload construction only for an exact framework instance whose checked collection and property listener slots are both empty and whose backing storage is an exact list. Eligibility is checked after every element formatter; subscriptions, derived overrides and unavailable layouts retain public insertion. A new read-only observable result fills its unpublished backing list before wrapping it. Binary fresh observable construction uses the constructor-created list, while reuse keeps its existing clear-and-replace behavior. Warmed unobserved reuse avoids temporary heap allocations; notification subscribers, first-use layout probes, JSON capacity growth and unknown implementations can still allocate.

Binary state localization preserves the operation's entry snapshot and successful-completion publication. Void and integer-returning local helpers without additional byref parameters share one caller-side temporary across sequential calls; both publication copies remain. Counted sequence helpers return the number actually traversed, while their caller owns the original header reservation and final back-patch. This avoids duplicating complete Writer snapshots and framing inside every concrete loop. Unknown calls and helpers that can return aliases retain separate storage. This decision follows the generated operation graph, rather than the identity of a benchmark type.

### Incremental boundaries

Generation separates current semantic analysis from frozen output values. Each root's source, layout and diagnostics are compared before source production; unchanged values cause no output callback. Cross-compilation caches keep descriptions, syntax tree identities, copied settings and generated strings, never a `Compilation`, `SemanticModel` or symbol. Invalidation covers project-level facts (references, language settings, aliases, extension signatures) and source closures (observed types, members, attributes, partial declarations). `IncrementalGenerationMetrics` exposes internal counters for the incremental tests.

Type discovery filters declarations without attributes before semantic binding and selects the partial declaration that actually carries the packable attribute. Dependency closures are shared within their owning compilation across output caches. Project guards keep weak metadata-reference identities so compilation-backed references cannot retain old projects. Source-backed IDE project references are invalidated by those reference identities; their foreign syntax trees are never passed to the consumer's semantic model or retained as local source dependencies. Completed output batches discard obsolete file wrappers. Compilation-wide guards and aggregate planning still inspect current project facts after edits; incremental generation does not mean that every stage does zero work for an unrelated edit.

Within a compilation, the type and aggregate pipelines share frozen operation plans for the same type, complete generation settings and streaming decision. Concurrent requests publish one lazy plan without holding the publication lock during semantic construction. These contexts are weakly keyed by the compilation, hold completed plans weakly and discard failed factories; only symbol-free plans enter retained-driver output caches. Unchanged declaration-option overlays reuse their immutable values; input policy is copied only when an input setting is explicitly overlaid. Temporary operation syntax skips XML parsing while final caller-facing API documentation remains complete. Shared facade analysis also skips XML parsing and replaces only executable method spans in the original documented text. Final projected syntax supplies symbol-free Root navigation facts before it is discarded, avoiding a second complete parse; contributions containing conditional directives retain the text-parsing fallback.

Roslyn cancellation is checked before changed-type analysis and between aggregate formatter and facade contributions. Cancelling obsolete work propagates cancellation instead of reporting a generator failure. Completed contributions remain reusable; cancelled aggregate batches are not published. A single in-progress contribution or project-wide semantic guard can finish before the next cancellation boundary.

### Generated files

`LuminPackSerializer.g.cs` holds shared generic APIs. With [static interception](generation-modes.md#static-interception), `StaticSerializerBinding` binds a constant-size signature tree, records compiler-owned locations and emits shared methods in `LuminPack.Interceptors.g.cs`. Explicit profiles specify both payload and options, so this path adds no payload-specific profile overloads. Concrete conveniences live in `LuminEntry_<hash>` containers and state forwarders have unique payload names. The IL backend emits the same entries with build-only signature mappings; `LuminPack.ILPostProcessor` substitutes local calls after compilation. The opt-out compatibility backend retains concrete overload files. Every generated assembly owns a public `LuminPackSerializer`; generated files suppress CS0436 so a referenced assembly's copy is shadowed. Roots remain in `LuminRoots_<hash>` containers. Advancing calls with known payloads name their `Binary_<assembly>_<hash>` extension class, forwarding extensions call their recorded root, and concrete conveniences call that same root. User `Write`/`Read` extension signatures remain available. No new plan struct is emitted.

Static source wrappers are closed through an indexed reverse call graph, then copied once per complete method construction. Relocation preserves original method binding and argument conversions, captures caller-information defaults and rejects unsupported or inaccessible bodies. Fallback boundaries retain the original source and registration rules. Compilation-local semantic state is weakly held; aggregate cache identity includes interception locations and all specialized bodies, including nested dependencies. Root/convenience identities are independent of source locations.

The generator runs independent work on several threads: observing each source file for the compilation-wide type index, binding each source file for API usage, analyzing changed packable types before Roslyn's per-type step reads the results in order, building payload contributions, and rendering, sharing and root-retargeting each payload's `LuminPackSerializer` overloads. Memoized dependency facts are computed outside their locks and the first published result wins. Results are merged in their original order, so output does not depend on scheduling. Work stays sequential under Server GC with dynamic heap adaptation (DATAS, the compiler server's default since .NET 9), where parallel allocation made generation much slower in measurements.

Private shared facade helpers and adapters retain all 128 bits of their existing identity in a 26-character, identifier-safe base-32 suffix. This shortens generated source and metadata names without truncating identities or changing API signatures, operation bodies, file identities or dispatch.

Generic fallback bodies invoke only registered typed delegates. Intercepted closed generic calls bypass those bodies. `LuminPack.Dispatch.Formatters.g.cs` has constant-size dispatch and assembly policy helpers, independent of the payload list; no `LuminPack.Dispatch.Lazy.g.cs`, per-payload factory or delegate cache is emitted. Its cache depends on assembly constants and whether generic staging needs an input limit. Concrete roots and their XML navigation facts remain independent of registration.

Closed generic payloads discovered through reachability are indexed before state-call projection. Generated calls to these known types bind their concrete state operations rather than the public registration-only generic APIs. Generic Union overrides retain their original virtual call and cached slots; observed closed cases use the same wire tag and their closed concrete operation.

### Documentation of generated code

`GeneratedSourceDocumentation` and `LuminPackSerializerDocumentation` add compact XML documentation only to directly callable `LuminPackSerializer` APIs and the facade type. API comments describe the same analyzed type, member order and filters, CLR versus wire layout, buffer semantics and return units. Internal state forwarders, execution roots, Union slots, layout helpers and private facade adapters omit XML; their executable code is unchanged. CS1591 is suppressed in generated files so enabling documentation warnings does not require XML on these implementation details.

Concrete model API remarks and built-in overloads with recognized execution roots link directly to the appropriate nested binary or JSON Root through a compiler-bound `cref`. Built-in navigation reuses the completed formatter's symbol-free forwarding facts, and those facts are included in facade cache identity. Raw unmanaged binary readers without a separate Root, Custom entries and size evaluation do not acquire fictitious read/write links. Final presentation removes internal prefixes from proven local roles, gives captured record members descriptive snapshot names and labels cursor record groups with field comments. These changes preserve user member names and executable statements.

Local helper functions use PascalCase with collision-safe numeric suffixes. Scalar and Union call projections retain their original operand syntax and annotations so the presentation pass can still prove which identifiers belong to generated locals; names observed through `nameof` remain unchanged.

Generated identifiers avoid two consecutive underscores, which the C# specification reserves for the implementation. Name sanitizers map a punctuation run to one separator, and JSON support fields of members starting with an underscore gain a `U` prefix through an injective mapping. The last projection renames any remaining reserved local; identities that exist only during projection may keep their spelling inside the generator, and names a user declares stay as written.

Publication applies `GeneratedSourceLayout`: a line wider than 140 columns breaks at its outermost logical chain, conditional, argument list, parameter list or expression body, and XML comments put each paragraph on its own line. Each long line is parsed alone because parsing whole output files cost too much of a generator run. Files containing multi-line literals keep their code lines. These changes affect whitespace and comment text only, and the same projection removes nested blocks that declare nothing, so Release IL is unchanged. Qualified names stay `global::` qualified, so some lines remain wider than the limit. The generated-code contract suite turns this layout off because its assertions read statements as single lines.

Static entry classes, interceptors and specialized wrappers use four spaces per nesting level. `GeneratedSourceIndentation` places existing syntax fragments at their destination depth without another full-source parse or normalization pass. Multiline string tokens and inactive source keep their exact contents; XML comments align with their owning members. Both compiler and IL backends use the same presentation rules.

Write-proof eligibility is memoized only within its projection's unchanged type and settings. Canonical runtime-profile checks use a weak compilation key and retain only a Boolean result; a new compilation always checks its own profile identities, including consumer-defined shadow types.

Final contract documentation is rendered as text changes limited to method-leading trivia. This avoids constructing XML syntax trees that would immediately be converted back to text, while preserving the exact comments, directives, indentation and executable source.

Root links use names relative to their containing serializer to avoid repeating its namespace on every overload. The compiler binds them to the same methods and emits complete canonical method identifiers in the documentation XML.
