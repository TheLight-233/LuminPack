# 机制契约

[English](mechanism-contract.md)

本文列出 LuminPack 的硬性约束，适用于整个仓库：运行时代码、生成器、生成的代码、可选模块以及各条件编译目标。往返测试通过、文件变小或基准变快，本身都不能成为替换下列机制的理由。

每次批准的历史记录保存在 Git 中。如果本文、代码和历史三者不一致，请带着证据报告差异，不要擅自选一种设计。

## 1. 变更管控

1. **默认保留机制。** 第 2 节中的每个机制都保持原样，除非所有者明确批准一个具体的替换方案。
2. **先做实验。** 更快的替代方案在 `experiments/`（不纳入版本控制）中准备，需要包含：
   - 与相同参照库（如 Nino、MemoryPack、System.Text.Json）的耗时比值，改动前后都要有，且在同一台机器、同一份数据、同一运行时和选项下于同一次运行中测得；
   - 多次采样及其离散度，以及分配量；
   - 必要时提供生成的源码、IL 或原生代码；
   - 语义、API、数据格式、状态归属和平台方面的取舍。
3. **只有所有者明确批准该具体方案，才能替换。** 性能目标、重构、删除死代码或减小体积都不等于批准。
4. **正确性修复单独对待。** 已复现的 bug 可以在保持原有协议的前提下修复。请作为修复记录并附带回归测试，不要声称实现没变。
5. **记录批准的差异。** 把批准的规则写进本文（写规则，不写带日期的叙述），并在提交说明中描述改动。
6. **默认提交已完成的工作。** 完成一个功能或修复并进行相应验证后，按[提交规范](CONTRIBUTING.cn.md#提交规范)直接提交本任务的改动，无需询问提交权限。排除无关或未完成的改动。提交后询问是否推送；所有者已授权该次推送时直接执行。打标签和重写已发布历史仍需明确授权。

## 2. 必须保留的机制

### 存储访问

- **Local + As 视图。** private、protected、readonly 以及自动属性 backing field 的存储，通过生成的布局镜像和 `Unsafe.As` 访问，绝不使用反射。镜像复刻继承链和 `LayoutKind`（包括显式偏移）。可访问的可写字段直接访问。
- **存储占位。** 镜像字段、padding 成员和隐藏存储不能因为普通的调用点搜索找不到引用就删除。
- **相邻字段批量复制。** 连续的非托管字段只在 64 位上、且证明实际字段地址与紧凑偏移一致、排除 volatile 字段并保留逐字段回退时，才可以整块复制。
- **按架构区分的固定值访问。** 在 32 位上，只有 `Unsafe.SizeOf<T>() <= 4` 的单个非托管值可以使用类型化的 `Unsafe.ReadUnaligned` / `WriteUnaligned`。更大的值和字段批次使用 `LuminPackMarshal.CopyBlockUnaligned` 和紧凑存储视图，因为对它们做类型化非对齐访问可能让 IL2CPP 崩溃。所有成员都不超过 4 字节，也不代表可以对整体做类型化访问。64 位上类型化访问和块复制都允许。
- **原始复制。** 不重叠的块复制（包括生成代码中的）都经过 `LuminPackMarshal.CopyBlockUnaligned`；只有这个辅助方法直接调用 `Unsafe.CopyBlockUnaligned`。允许重叠的 span 复制保持 memmove 语义。

### 数据表示

- **Object 模式**按位置写成员，成员数为 1 字节（0 到 249，`255` 表示 null）。
- **版本容忍**使用带 UTF-8 元数据的命名成员、成员宽度表和按字节的元数据比较；`LuminPackOldName` 写入时保留最早的名称。修订版 2 的记录单遍写出：原始成员按表中宽度写出，变长成员前带 `int` 长度。读取方继续接受修订版 1 的记录。
- **引用跟踪**（`CircleReference`）保留槽位表和显式引用 id。表中每个槽位一个宽度字节（原始宽度；空槽位为 `0`；`255` 表示值前带 `int` 长度），因此记录可以单遍写出；表与自身一致的读取方按常量字比较后直接读入对象。未知的尾随槽位会被跳过，显式 id 保证跳过之后的回引用仍然准确。写入方先用引用扫描查找一次操作中的前几个对象，之后才使用哈希；读取方用数组存储顺序分配的引用 id，并用一次探测同时检查和登记可复用的候选对象。
- **非托管结构体**遵循 `StructLayout` 契约：`Tagged`（默认）、`Packed`、`Native`。
- **字符串**默认使用固定宽度的 UTF-16 长度记录，带紧凑 Latin-1 形式；UTF-8 和 Token 配置保持可用。可选的 `VarInt` 记录将每个原有长度头加一，再以规范的无符号 base-128 编码，保留负载编码及 null 与空字符串的区分；UTF-8 保留两个长度字段。默认固定宽度格式及其字节保持不变，读写双方选择相同配置。Token 记录二者共用空终止符。
- **JSON** 保持其包络格式（`$type`/`$value`、`$id`/`$ref`、`Lazy`、多维数组），并拒绝非有限数字。
- **引用追踪 JSON 属性头。** 在 64 位现代 .NET 上，生成的写入方法在连续输出和分段输出时都可以把完整的静态属性头复制到当前窗口，并一次推进游标。属性头沿用文档编码和当前分隔符状态。窗口不足或配置不受支持时沿用原有属性写入方法，保留输出回调、已提交前缀和引用注册顺序。
- **普通 JSON 整数字段组。** 对于连续、可直接写入的非 volatile `Int32` 字段，生成的 Reader 可以在有界的局部托管窗口中匹配完整静态字段头并解析纯整数。分块结束或回退前，只发布已成功消费的前缀。保留逐字段赋值、分隔符语法、复用行为及首个失配字段上的普通解析路径。
- **字节序**为小端。任何模式都不做字节序转换。
- **压缩**采用 `LUM2` 帧：小于 255 的长度扩展占一个字节，较长扩展使用转义字节及规范的无符号 base-128 余数；保留 64 KiB 匹配窗口及每线程位置表。高压缩率的分配式读取在分配前验证完整序列结构。拒绝旧的 `LUMZ` 帧。匹配钩子、有界 SIMD 尾部、解码检查及 32 位访问规则仍然有效；参见[压缩](compression.cn.md)。
- 改变任何线上字节都需要明确批准，并更新数据格式测试夹具。

### 派发

- **具名成员内核。** 源码内定义、不含继承、回调或有界记录声明的非泛型位置类，在成员都是公开原始存储或字符串、且至少含一个字符串成员时，可以共享一个具体的静态成员写方法。纯定长记录保留现有紧凑存储。保留原有成员头、字段地址证明、定长存储、字符串操作和编译期成员配置，不用独立根方法的容量融合替换成员语义。成员内核保留内联提示，其调用方的根方法交由运行时决定是否内联。仅包含运行时记录内核和无独立配置边界的具名成员调用的完整公开字段写入，可以直接使用已有类型事实生成。其余契约沿用现有操作投影。此机制不增加运行时计划、格式化器见证或载荷派发，也不删除现有入口。
- **Next 嵌套记录入口。** JSON 嵌套字段使用具体 Formatter 的文档配置入口。二进制位置记录仅在原有头部、输入校验策略、字段地址证明和部分读取行为保持一致时调用子类型已有的对象或载荷读取入口。先在局部变量中读取子对象，成功后才将新对象写回成员。可直接调用已有的二进制成员写入入口，也可调用存储操作等价的独立写入入口。独立入口的输出预留方式不同时，保留原有的成员写入方式。
- **静态入口**在编译器支持带版本的拦截位置且使用 C# 11 或更高版本时使用 Interceptor。闭合负载调用（包括显式泛型写法）直接绑定既有具体 Root，不经过负载类型分发、反射或委托缓存。显式配置同时指定负载和配置类型；任何后端都不在公共门面生成负载专属的配置便捷重载。静态接入路径的具体状态转发方法使用负载专属名称，便捷入口位于负载专属容器中。不增加 Runtime Plan 或格式化器见证类型。旧编译器通过已安装的 IL 后处理器使用相同具体入口和精确签名映射，替换本程序集静态调用操作数，校验栈类型并保留 Portable PDB；签名产物需要原始签名密钥。两种接入均关闭时，默认调用保留具体重载，显式配置调用使用已注册的泛型兜底。
- **应用程序内的状态转发。** 启用编译器拦截且没有友元访问的可执行项目中，只有一次调用的状态拦截器可直调现有嵌套 Root，保留原签名、配置和参数传递方式。仅当所有已生成贡献和用户源码都未引用某个负载专属的内部转发方法，且其声明无歧义时，才可省略该方法。库、有友元访问的程序集和 IL 改写后端保留原状态转发和绑定契约。
- **源码泛型包装方法**在静态源码方法体可以安全迁移时，于闭合调用处生成特化实现。保留参数求值、重载选择、调用者信息、副作用以及方法与所属类型的关联类型实参。不透明或不支持的方法体保留原调用并使用注册兜底。拦截不会改写引用程序集或替换虚方法派发。
- **Next 静态入口。** Next 只拦截负载类型已闭合的门面调用。拦截器调用既有静态 Root 并处理相应的文档边界。显式配置共用拦截器的配置类型参数。源码泛型包装方法中的开放负载调用使用注册兜底，不执行过程间展开。生成的 XML 文档位于公开门面上。
- **泛型兜底入口** 使用显式注册和 `Custom` 注册。Next 还会在消费程序集的注册表中登记已发现闭合负载的生成操作，并使用 Core 中内置的标量和字符串注册。门面在首次使用时初始化注册，显式注册的操作优先。缺少注册或操作时抛出 `LuminPackException`。关闭注册同时禁用兜底。注册不依赖运行时类型发现或反射工厂。泛型兜底文档边界使用消费程序集默认值或显式配置，拦截后的具体 Root 保留声明所属的选项。
- **Union 派发**是在根类型上生成的 public 虚方法（`EditorBrowsable(Never)`）。泛型 Union 根在虚调用之后增加缓存槽位 switch。不使用泛型虚方法或替代用的 switch。
- **二进制 Union 精确写入。** 在所有目标上，符合条件的本地非泛型抽象类根的编译期二进制槽位按标签顺序精确比较运行时类型，选择已生成的 case。未命中时直接查找已有注册或报未知 case 错误。能够证明封闭且只有一个 sealed case 的路径可以继续直接调用该 case。生成的虚槽位仍可调用。JSON、泛型根、接口根、不满足条件的根和偏移计算沿用各自的分派。
- **Union 集合。** 列表、一维数组、`ImmutableArray<T>` 和字典均按输入顺序逐元素使用根选定的写入档位。密集字典在既有的固定 Union 游标协议中应用同一档位。负载是否定长不改变档位或字符串表示。
- **Fresh Union 元素。** 新分配的 Union 集合存储可以先通过初始化为 null 的局部变量读取，再赋给元素，保持 Union 操作在负载成功读取后发布结果的既有行为。已有元素保留复用路径；普通对象和 Custom 格式化器保留各自的发布契约。
- **新建固定 Union case 的读取。** 在 64 位新版目标上，Next 可对不经池租赁、无回调的新建固定 case 使用现有带校验的块读取。连续字段须可直接写入、非 volatile、无托管引用，且不涉及布尔值校验。使用块读取前证明实际字段地址连续，并保留逐字段兜底。已有目标保留原读取路径。推进游标或写入批次前校验完整输入，负载读取成功后才发布新建 case。
- **注册**传入强类型委托（`LuminPackFormatter`），不要求 unsafe 上下文。条件弱表使完整注册项随载荷类型存活，方法表索引只保存弱引用，因此可回收的载荷程序集可以卸载。委托及其捕获对象在载荷注册项存活期间保持存活；为不可回收载荷注册可回收程序集中的代码，会将该代码保留至载荷生命周期结束。注册在发布前校验标签、case 类型和必需操作。
- **`Custom`** 格式化器拥有完整的数据表示，通过注册的委托调用。

### 执行状态

- **前进式游标。** 二进制和 JSON 读写器在新版 .NET 上使用 `ref byte` 游标，在 `netstandard2.1` 上用长度为 1 的 `Span<byte>` 保存托管游标地址。该 Span 的长度仅用于表示游标，实际可访问范围由保留的窗口和结束缓存决定。底层调用方可用 `MemoryMarshal.GetReference` 取得游标引用。
- **缓存结束位置。** Writer、Reader、JSON Writer 和 JSON Reader 在游标旁缓存窗口的结束位置（或写入器的扩容阈值）。`Buffer`、`BufferCheckLimit` 和 `Owner` 的 getter 为 public、setter 为 internal，setter 会刷新缓存；每个构造函数和每次窗口变化都必须刷新。
- **游标发布。** 生成代码可以在两个会观察状态的边界之间把游标放在局部变量中。在调用格式化器、Union 或递归操作、回调或容量检查之前必须发布游标，之后从结果状态恢复。绝不能在扩容之后继续持有旧的缓冲区引用。
- **标量读取。** 生成的标量读取调用 `LuminPackReader.Read`。定长批次或序列窗口可以在校验完整区间后使用按地址读取的重载。32 位标量访问由 Reader 选择，批量读取和不可信读取仍遵循各自的存储证明和校验要求。
- **固定 Union case 写入。** 符合条件的本地、窄标签、非泛型类 Union 的普通虚 case 槽位可以在共享的返回游标方法体内一并写入标签和无回调的固定负载，并在返回前发布结果位置。该路径保留原有虚槽位和各配置槽位，排除外部输入策略 case；其他 case 保留原有写入路径。
- **大型固定 Union 记录。** 固定负载宽度加上最大 Union 头长度超过普通扩容检查保证的最小余量时，必须在该负载的无检查存储之前为整个负载预留容量。返回游标的方法体在该容量边界前发布绝对游标，并在扩容后重新取得输出存储。小型固定负载保留基于扩容阈值的预留契约。
- **每个操作一个状态方法体。** 每个保留类型对每个生成的操作（二进制写、二进制读、JSON 写、JSON 读，见自动生成）各有一个完整方法体；便捷重载转发到它。直接记录另为其分配写入保留一个精确长度方法体。 对于反复遍历同类复合元素集合的大型二进制写方法，循环和预留容量区域以外的同级调用可以复用该框架集合的闭合写方法，并传入原状态和已编译的成员配置。 特大型二进制读方法可以将完整的成员分支拆成静态局部函数，按引用共享原 Reader 并操作同一类实例，保留校验、游标推进及失败时的赋值顺序。
- **托管输出存储。** `LuminBufferWriter` 拥有一个 `ArrayPool<byte>.Shared` 数组。所有目标都先用 `GCHandle` 固定新租用的数组，再测量 64 字节对齐的起点。固定持续到归还数组，使 GC 在租期内保持其对齐。扩容保留 32 KiB 初始容量、1.5 倍增长和 87.5% 阈值。已租数组放得下时原地扩展，否则复制到新固定的数组，再解固定并归还旧数组，刷新游标与结束缓存。每个暴露的字节要么在获取时清零，要么由所有者写入。终结器为未释放的 writer 释放固定句柄。数组由显式释放或归还回收至池中。
- **调用方持有的追加会话。** 接收 `LuminBufferWriter` 的重载从其游标处追加，并保留引用状态直到调用方重置（`ResetForReuse`、`Reset`、`ResetCore`）。
- **独立的默认引用上下文。** 互相独立的默认读取器和写入器绝不共享引用身份。
- **新建 JSON 顺序集合容量。** 新建 List/Queue、普通序列接口、Collection/ObservableCollection 及只读包装可以在原逐项读取循环前使用只读结构容量提示；Grouping/Lookup 的元素 List 共用此规则。已有目标保留原复用、发布和回调；提示不可用或后续数量变化时继续扩容。短输入跳过扫描。新结果 Capacity 可以变化，额外扫描可能增加 CPU 成本，以避免增长分配为优先。数组、哈希集合/字典及 Lookup 字典保持原构造；生成前检查可选 helper 元数据。
- **Next ObjectModel 包装集合格式化器。** 精确匹配且由已知列表或数组提供存储的框架包装集合，以及密封的集合构建器，可复用已有跨度内核批写 UTF-16 长度字符串和 UTF-8 JSON 整数。带版本的存储在输出窗口边界检查枚举版本，并在容量变化后重新读取后备数组。其他存储和配置沿用原格式化器循环。JSON 可观察集合在每个元素格式化后检查实际类型和订阅状态。新建包装集合或构建器可在原元素循环前用容量提示分配存储。
- **Next 集合接口写入。** 精确匹配的框架列表、数组、集合和字典可以选用具体类型的遍历。派生类型和自定义实现沿用接口枚举。可变字典接口可以在一次完整的边界检查后写入每对无回调的原始元素，枚举结束后回填元素数，输出区间不足时沿用逐成员写入。JSON 可以在原有逻辑记录中合并分隔符与整数元素或整数键值对。 现代 .NET 的自有缓冲区二进制写入，对精确匹配的 List、内置 UTF-16 长度配置，以及变长成员只有字符串或原始标量列表且无回调的位置记录，可以使用旧版的已知长度跨度和逐对象完整预留。数组、自定义接口实现、自定义配置及跨度目标沿用现有路径。
- **Next 具体字典记录。** 二进制写入可对已验证的 SortedList 数组或 SortedDictionary 独占租约中的非空原始键值对一次校验整个输出区间。区间较短时沿用原逐值写入。由定宽整数键值对构成的新建字典，可以在验证完整负载后直接读入已确认的存储。JSON 可以合并整数键值对的定界与数字写入。精确匹配的 SortedList 在写任一成员前先读取完整键值对，并在包括最后一次在内的所有原枚举边界检查修改版本。 有界 UTF-16 成对写入器也识别由声明固定封装的内置 UTF-16 长度配置及默认配置。 在扩容阈值前能完整写入原始键时，稠密字典的二进制写入可省去值 Formatter 前的扩容检查。阈值边界的回退仍校验容量，并在值原有的阈值检查前取值。
- **字典的并行存储。** SortedList 和冻结字典的二进制写入器可在已校验的并行存储上，对固定 UTF-16 字符串与非托管值组成的整对数据一次验证输出容量。原逐值回退在输出扩容时仍先取键再取值。SortedList 的 JSON 遍历保留版本检查和取值顺序。
- **Next 连续集合批写。** 精确匹配的 `int` 和 `long` 跨度可在当前输出区间内使用局部游标写入 JSON 元素。区间不足或重叠、或者 UTF-16 区域性可能触发用户回调时，沿用原标量操作和取值顺序。分段字符串的二进制 UTF-16 长度记录可在存储边界和原有扩容阈值内使用已有的批写内核，保留累计数量回填和下一条记录的标量检查。多维 JSON 数组保留形状帧，并按行优先顺序将已验证的暂存跨度复制到结果。存储地址取自框架的数组数据 API，旧目标使用声明下界处的带类型元素地址。
- **Next 可变栈、队列和堆记录。** 精确匹配并经验证的栈可在确认容量的区间内按栈底优先顺序搬运无引用的二进制存储。直接填充的栈在校验完整负载后才发布。字符串栈和环形字符串队列可使用经边界校验的 UTF-16 长度记录批写。暂存字符串读取失败时，栈保持为空并清除引用槽。整数栈和队列可以跨输出窗口批量格式化 UTF-8。分隔符或数值可能回调输出方时，先捕获当前元素，再在继续时检查枚举版本，包括最后一个元素之后。优先队列保持堆的枚举顺序。整个二进制记录有足够空间时，可不含元组填充地写入两个字段；使用默认比较器的定宽标量读取可直接填充已校验的堆序前缀，再沿用常规插入。JSON 可复用有边界的整数键值对写入，并为含字符串成员的大型新堆使用容量提示，保留原比较器、键值对语法、部分读取的发布方式和回退路径。
- **深层 JSON 预读存储。** CountArrayElements 持有独立的深层语法副本，可以从 ArrayPool<byte>.Shared 租借和增长私有副本，并在成功或失败的 finally 中归还。原 reader 存储与状态保持不变。普通 reader 的深层语法仍保留原分配与生命周期。原生池缺失和裁剪机制照常运行。
- **Next JSON 数组池化读取。** 在内置的可信默认配置及 UTF-8/UTF-16 长度和标记配置下，共用的连续集合格式化器可以单遍解码到独占的池化存储，以构造替换 `T[]`、元素非 `string` 的 `ImmutableArray<T>`，或原值为默认值的 `ImmutableArray<string>`。确认数组结束标记处于外层深度后，才发布长度精确的结果。归还缓冲区时清除其中的引用槽。后续输入畸形时，合法前缀的元素回调可能先于错误报告执行。已有 `T[]` 只有在运行时类型精确匹配，且先行计数和校验确认长度相同时，才复用元素槽。严格配置与自定义配置在此格式化器中继续使用原有的完整前瞻校验。 非默认的不可变字符串数组仍以原字符串引用作为逐项读取的初值。
- **二进制队列与堆区间。** 队列读取器可在验证完整区间后一次推进三个存储字，遇到截断头部则逐字读取。采用已验证堆存储的精确优先队列可一次验证固定 UTF-16 字符串与非托管值组成的整对数据的输出容量。写入前先捕获整对数据，并在每个枚举边界检查修改版本，包括最后一次。不支持的配置和布局使用公开枚举，输出区间不足时使用原有逐值写入。
- **多维 JSON 数组形状。** 生成的读取器可在栈上保存固定秩的维度长度和下界缓冲区。校验完整形状和暂存元素数后，零下界数组可直接使用静态类型构造。非零下界仍将原长度和下界交给框架构造方法。
- **Next 具体集合格式化器。** 定宽且无回调的哈希集合可先校验完整二进制负载，再按线格式顺序同时读取条目和链接哈希桶。冻结集合可从同样经过完整校验的输入直接填充私有构建器，通过常规插入处理重复项。冻结集合写入可从不可变元素跨度批量处理兼容的元素。精确匹配的整数有序集合可遍历经验证的树写入 UTF-8 JSON，并在每个元素写入后检查版本。使用默认比较器的精确整数有序集合可从严格升序的暂存前缀构建树。输入错误时通过常规插入发布已完成的前缀，遇到乱序或重复项则按输入顺序恢复常规插入。派生集合、不支持的配置和无法绑定的存储布局沿用已有路径。
- **构造、池化与复用。** 构造函数选择、`[LuminPackPoolRent]`、对象/集合/字符串的 `ref` 复用，以及文档中描述的失败时发布规则都要保留。复用不是事务性的。
- **复用缓存所有权。** 共享池存储有界、无序，采用原子首槽和带起点提示的有界溢出扫描。只有槽位原子操作转移所有权，提示和诊断快照不转移所有权。保留既有 TLS 快缓存与池身份校验，在发布前重置对象，释放被拒绝的对象，并区分共享容量为零和禁用 TLS。对象池调整容量要求静默期，先发布替代存储，再释放多余对象，完成清理后汇总释放异常。本地清理在调用释放回调前解除所有权。
- **二进制字符串矩阵。** 完成所有维度及元素数量检查后，框架的默认 UTF-16 长度配置可以复用形状完全匹配、两个下界均为零的 `string[,]`。按行读取各位置，逐条检查边界与配置的字符串限额。内容相等的字符串保留原引用。旧矩阵的其他引用可以看到每个完成的位置，包括读取失败前已解码的前缀。其他配置、形状、数组秩或缺少相应辅助方法的运行时沿用原读取路径。
- **显式启用的二进制对象矩阵复用。** 在 .NET 8 及更高版本上，元素声明设置 `ReuseRectangularArraySlots` 后，Next 可把已有二维数组的各位置传给元素的普通对象复用读取器。目标的运行时数组类型和两个维度长度必须完全匹配，两个下界必须为零。调用方须为各位置提供独立的可变对象图。修改前先检查形状与元素数量。按行读取，失败时可能看到已解码的前缀。其他目标使用替换读取。
- **便携 BitArray 存储。** 经验证的整数或字节后备存储可以直接写出，同时保留实际运行时公开 `CopyTo` 的填充位行为，不修改输入。便携二进制读取可以直接填充尚未发布、按整数边界取整的最终 `BitArray`，再进行原有的公开长度调整，成功后发布。空值和极端长度、保留多余容量时的写入回退、载荷检查、缺失 API 或未知布局回退均保持既有行为。现代目标的复用及两种 JSON 表示不变。
- **不可变树集合的 JSON 写入。** 具体类型 `ImmutableList<T>`、`ImmutableSortedSet<T>`、`ImmutableSortedDictionary<TKey, TValue>`，以及通过 `IImmutableList<T>` 访问的框架列表，可以按枚举顺序将非空集合复制到独占的池化数组。写入器依次调用原有的编译期格式器，并在归还数组时清理其中的引用，发生异常时也会归还。引用的运行时缺少对应的复制重载时直接枚举。无法识别节点布局时，通过公开枚举填充数组。
- **不可变集合的原始记录。** 具体类型 `ImmutableList<T>` 可以将已验证的树直接复制到已确认容量的可写跨度。输出区间不足、无法识别节点布局或目标平台不支持所需的非对齐存储时，使用暂存写入。原始元素的 `ImmutableStack<T>` 可以在验证完整负载后从输入末尾向前构造节点，完成后再发布栈。
- **框架不可变队列写入。** 二进制和 JSON 可以遍历精确 `ImmutableQueue<T>` 经验证的前后栈，包括通过 `IImmutableQueue<T>` 引用访问的实例。已有反转缓存继续使用；未缓存的后栈通过池化缓冲遍历，归还时清理引用，不建立 BCL 的惰性缓存。空后栈和单节点后栈不需要租借缓冲。元素顺序、formatter 调用、格式和失败行为保持不变。不支持的布局、缺失辅助 API 及任意接口实现保留原遍历。
- **集合分发。** 集合的遍历和构造应按存储布局、格式器能力与回调行为选择。禁止根据基准使用的键值类型组合选择专用算法。JSON 字典生成代码对每项写入或读取数组边界，并分别调用键和值各自的格式器。保留旧生成程序集所依赖的运行时签名。在受支持的现代目标上，二进制读取精确的字典类型时，若使用默认比较器、定长键的框架相等比较没有用户回调，且值格式器支持安全原位读取，则可直接复用已有槽位。匹配键保留目标顺序；失败时可能看到已读前缀。自定义键行为、自定义比较器或无法安全原位读取的值沿用暂存重建。目标字典为空、键无用户回调且键值均为原始数据时，可使用经过范围检查的批量重建。
- **共享 unmanaged Root。** 同一泛型定义（或同一秩的数组）的闭合格式器 Root，若方法体只在 unmanaged 类型实参上不同，可以只生成一个约束为 `unmanaged` 的泛型 Root。每个闭合 Root 保留名称、签名和 `Preserve` 特性，改为激进内联的转发方法；泛型 Root 保留原有内联特性。只有当代入各成员的实参能还原该成员的方法体，且泛型方法体中每个表达式绑定到的定义、类型和常量都与成员自身方法体一致、并且没有错误时，才会共享。`Nullable<T>` 以及任一证明失败的成员保留闭合 Root。值类型实例化在 CoreCLR、NativeAOT 和 IL2CPP 默认设置下仍分别编译；IL2CPP 的完全泛型共享（"Faster (smaller) builds" 选项）可能通过共享代码执行。
- **新建二进制并发字典。** 在布局已验证的 .NET 10、11 x64 上，新建的 `ConcurrentDictionary<TKey,TValue>` 暂存至少 32 个条目后，可在发布前填写空桶并更新对应锁的计数。使用当前桶表的实际比较器计算一次键哈希。桶冲突和扩容交给框架插入方法，并传入已经算好的哈希；重新散列后重新获取桶表。保留构造器的重复键过滤、首值保留、键回调和空键异常。布局不受支持时使用框架构造器。已有目标按其原比较器和插入路径更新。
- **二进制原始并发队列复用。** 校验完整的原始载荷后，Next 可对精确类型且元素为受支持标量的 `ConcurrentQueue<T>` 调用 `TryClearConcurrentQueue`，适用元素数量为 33 至 4,096。在经探测的 .NET 10、11 x64 CoreCLR 上，先持有框架锁并冻结旧尾段，再发布新框架段的头和尾。段容量取大于或等于元素数量的最小二次幂。已有快照保留原先捕获的段。元素仍逐项校验、按序入队。其他数量、布局不受支持、缺少运行时支持及其他元素 owner 时，使用框架的 `Clear`。
- **并发集合遍历。** Stack 写入可遍历在创建枚举时捕获、经布局验证的不可变节点链。Dictionary 写入可使用值类型遍历，保留延迟桶捕获、acquire 读取、整对值复制以及当前运行时在 yield 前后的链接读取时机；缺失元数据或 helper API 时保留公共枚举。Bag 写入保留全局/局部冻结协议及公共快照顺序：原始非托管二进制载荷可直接复制到预留输出，其他二进制和 JSON 路径租借完整快照并在格式化器调用前释放锁。未知布局回退 `ToArray`，保留原生 `ArrayPool.Shared` 的所有权及回收策略。
- **并发集合标量记录内核。** 对字符串键和直接写入的非托管值，Next 二进制写入器可一次证明固定 UTF-16 键的容量上界与值均能写入，再使用原有标量存储操作并一次推进游标。其他档位或容量不足时沿用原来的计数写入。Next 的 JSON 并发序列和字典可为匹配的框架标量调用 Runtime 的完整整数元素或键值对写入操作。这些内核保留遍历、线格式、回调和验证，缺失 Runtime 操作时沿用原路径。
- **新建二进制并发包。** 在布局已验证的 .NET 10、11 x64 上，新建的精确 `ConcurrentBag<T>` 暂存 64 至 4096 项时，可在第一次常规 `Add` 后预设本地工作窃取队列的数组容量。操作持有既有的全局和局部冻结锁，并确认仅有一个初始队列、当前所有者线程、原始容量和首项索引。保留目标发布、输入顺序、计数及后续 `Add`。回调更换对象或队列不符合探测条件时使用普通插入。
- **框架类型并发栈 JSON 读取。** 无用户回调的框架标量、字符串及其 Nullable 可暂存元素并通过 `PushRange` 一次构建最终节点链。完成顺序、目标身份和原来的失败前缀不变。读取进行中，其他观察者看到已清空的复用目标，直到成功或失败边界发布暂存元素。自定义元素保留逐项回调及原构造路径；缺失 helper API 时保留原读取器。
- **Frozen 构建存储。** Frozen 字典和集合读取可独占租用默认比较器的可变 Dictionary 或 HashSet，保留插入、哈希、回调、异常和成功后发布顺序。公共 BCL 冻结工厂负责选择结果实现。`finally` 在保留前清除输入引用。每个封闭可变类型全局最多保留 4 个对象，每个容量不超过 `max(128, 完成元素数 × 4)`。容量上限通常为 4096。`FrozenDictionary<TKey, TValue>` 构建器完成 4050 至 4096 个元素，或原始标量的二进制 `FrozenSet<T>` 请求同样数量的元素时，可以保留框架分配的最多 4861 个桶。较小请求可从同一缓存租用此表，归还时应用普通容量上限。冷启动、超容量或租用耗尽时正常分配。Frozen 标量集合写入可复用既有批量写入器。原始标量字典数组可按平台固定访问规则交错写入一次预留的输出窗口。其他元素契约和缺少 helper API 时保留原路径。BCL 工厂内部仍有暂存分配。
- **原始标量冻结集合的二进制复用。** 在受支持的 .NET 10 和 11 运行时上，`ReadRawSetReuse` 可按原始元素类型和线程弱引用地记录一个框架冻结结果。仅当调用传入非空复用目标，且完整校验后的输入与默认比较器结果的元素字节按顺序完全一致时，才记录该结果。后续读取的完整输入再次匹配时，可以保留该不可变实例。此规则保留框架的枚举顺序，包括碰撞导致的重排。新建读取、输入不同、未经验证的实例和缺少辅助方法的路径沿用普通冻结。
- **不可变 Builder 复用。** 现有不可变字典、有序字典、哈希/有序集合及旧版短列表的 Builder 路径可以租用独占的空框架 Builder，保持插入、回调和失败发布顺序。租用在回调前移出缓存槽；`finally` 在有界保留之前清除输入引用并恢复默认比较器。二进制单元素字典可以直接调用公开的空字典 `Add`。最终节点直构、候选缓存、Span 工厂和缺失 API 回退保持不变。这消除了预热后的 Builder 外壳分配，BCL 冲突节点及非规范有序输入的分配仍存在。原生 `ArrayPool.Shared` 保持正常裁剪机制。
- **规范区域性名称。** 在已验证的 .NET 10、11 CoreCLR 上，二进制与 JSON 连续读取同一规范区域性名称时，可以复用框架当前的实例。每个线程最多保留一个不超过 85 个字符的名称和一个只读区域性实例。仅接纳已在框架名称缓存中确认的 ASCII 名称。通过缓存的弱引用识别 `CultureInfo.ClearCachedData()`，未命中时调用 `CultureInfo.GetCultureInfo`。
- **二进制 `Version` 复用。** Next 读入并校验完整记录后，四个分量全部相等时可以保留传入的不可变 `Version` 实例。分量不同时使用原有框架构造函数，null 标记清空目标。二进制根和成员读取均保留相等记录的引用身份。
- **有序 JSON 集合。** 在 .NET 10 及更高版本，JSON 完整读取具体的 `ImmutableSortedSet<T>` 后，可以将至少两个严格升序的元素直接连接成平衡的冻结树。枚举及 CoreLib 中实现自身比较接口的非泛型值类型使用默认排序。字符串必须为非 null 引用，且当前区域性为标准类型。用户自定义比较、重复、乱序或缺少树节点绑定时使用框架 Builder。
- **框架元素不可变哈希集合。** `ImmutableHashSet<T>` 和 `IImmutableSet<T>` 的二进制及 JSON 读取，在生成器确认元素为实际核心库中不含用户回调的标量或字符串、Runtime 验证布局后，可以直接构造最终哈希节点及碰撞节点。保留相等元素的首次表示，以及 BCL 顺序插入形成的碰撞列表拓扑。具体类型的二进制候选缓存、复用及失败发布保持不变。用户自定义元素的具体类型二进制入口按下列规则构建，其他入口使用原有 builder。临时租赁必须归还，引用暂存必须清空。
- **按对象身份比较的不可变哈希集合。** 在 .NET 10 x64 上，具体类型 `ImmutableHashSet<T>` 的二进制读取也可在完成受校验的元素暂存后使用已验证布局的直接构建路径。生成器选择由消费程序集声明、直接继承 `System.Object`、没有自己的相等或哈希实现的密封非泛型类。Runtime 重新检查链接后的类型，并要求使用框架的默认比较器。该路径按输入顺序获取对象身份哈希，并保留首次出现的元素和碰撞列表行为。此专用路径不可用时，具体类型的二进制入口按下列规则构建。JSON 和 `IImmutableSet<T>` 沿用原有选择条件。
- **具体类型不可变集合的二进制读取。** 完成受校验的元素暂存后，`ImmutableSortedSet<T>` 可用旧版排序树构造器链接严格升序的元素。其他输入使用旧版范围构造，遵循其比较顺序和等价元素选择。`ImmutableHashSet<T>` 可用旧版哈希树构造器链接不同的哈希值。出现碰撞或布局不可用时，框架 builder 使用已校验的暂存元素。用户哈希方法可能在探测和回退阶段各执行一次。对象身份路径和已有的框架元素专用路径优先。读取在构造成功后发布，并清空租用的暂存数组。Core 缺少辅助方法时保留原有的生成 builder 路径。
- **Next 不可变树遍历。** 对于已确认的 sealed 框架 set 或 dictionary，可以写入已知长度并按原枚举顺序捕获元素，再用既有二进制及 JSON 元素操作写出。符合条件的二进制 set 可以直接写入完整预留的输出区。自定义接口实现保持计数枚举。JSON 读取有序集合时，无回调的框架元素可以在暂存严格递增后直接构造树。字符串路径要求框架的确切 culture 类型和已知固定配置，自定义 culture 或配置沿用流式 builder。
- **Next 包装集合 JSON 整数批写。** 已验证的框架存储可使用有边界的 UTF-8 或 UTF-16 输出窗口写入固定配置下的 `int` 和 `long`。UTF-16 格式化采用当前框架 culture。派生 culture 和自定义配置沿用逐项枚举。输出窗口边界保留枚举器的元素捕获顺序和修改检查。
- **带缓冲区的 UTF-16 整数有序集合写入。** 对类型精确的 `SortedSet<int>` 或 `SortedSet<long>`，`TryWriteIntegerSortedSetJson` 可在已知 UTF-16 配置、框架常规区域性且自有缓冲区能容纳每个剩余元素的现有分隔符和数字写入时，沿用既有的中序树遍历。对使用默认比较器且在不变区域性下写入的非负 `Int32` 键，可以用最大键的十进制位数估算已写前缀的上界，再用最小的两个键收紧该上界，并为最后一个元素预留完整的写入空间。派生区域性、外部输出和空间不足均保留框架枚举，包括原有增长回调和集合修改异常。UTF-8 路径沿用原有规则。
- **Next 字典混合条目写入。** 二进制字典中由一个 UTF-16 长度字符串和一个原生值构成的直接写入条目，可以检查二者的输出上界后一次推进。接口指向确切框架字典时，其具体枚举器也可使用同一上界。密集遍历保留修改检查。窗口不足、其他配置或任意接口实现沿用逐成员写入。
- **Next 确切列表和数组存储。** 具体不可变列表及通过 `IImmutableList<T>` 识别的确切框架类型可以使用现有按序树传输。JSON 读取可以暂存输入并通过框架的 span 工厂一次构造。二进制字符串序列接口可以对确切列表或数组共用连续字符串批写。其他接口实现沿用计数操作。
- **二进制复用以数组为后备的只读包装集合。** 在现代 CoreCLR 上，如果受支持的原始标量 `ReadOnlyCollection<T>` 类型精确匹配、直接包装精确的 `T[]` 且长度与输入相等并非零，Next 可填充原有数组。针对封闭类型的探测会验证框架后备字段。修改前校验完整集合载荷，并要求目标与保留的输入区间无重叠。集合读取后，原包装集合和后备数组的其他引用可看到新值，即使外围记录的后续成员读取失败。布局不受支持、存储重叠、其他目标形状或缺少 Core API 时沿用替换读取。
- **二进制读取复用只读切片中的字符串。** 在现代 .NET 上，使用内置 UTF-16 长度配置读取 `ReadOnlyMemory<string>` 或 `ReadOnlySequence<string>` 时，可以从长度相同的原数组切片复用内容匹配的字符串。首项经校验且与原字符串匹配时，其余位置才使用原字符串作为复用候选。读取器在所有记录解码完成后发布具有独立后备数组的新结果。自定义内存管理器、多段或非数组序列以及其他配置沿用新建字符串的路径。首项和剩余记录均遵守生成的外围输入限额。
- **按顺序匹配键的二进制只读字典复用。** 在经探测验证的 64 位 CoreCLR 布局上，Next 对采用默认比较器、后备字典类型精确且条目连续的 `ReadOnlyDictionary<string, int>` 和 `ReadOnlyDictionary<string, string>`，可在内置 UTF-16 长度配置下更新原有值。输入须包含 1 至 4096 个键，且与现有键按顺序匹配。后备条目存储区间须与保留的输入区间无重叠。无回调的私有缓存每种值类型最多保留四个暂存数组，并在保留前清除引用。读取器验证完整字典记录及原有条目存储状态后才发布值，旧引用可见成功更新。键不匹配、配置或布局不受支持、生成读取器应用外层输入限额时，沿用原有替换路径。
- **标量有序列表的二进制键复用。** 在经探测验证的布局上，Next 可从类型精确、使用默认比较器的 `SortedList<string, int>` 和 `SortedList<string, long>` 复用匹配字符串。此路径使用框架的常规区域性和内置字符串配置，要求输入和现有列表的条目数相同且在 1 至 4096 之间。读取器先暂存旧键，再按原顺序清空列表、执行带校验的键值读取并有序追加或调用 Add。每个完整键值对立即可见，集合版本和失败行为保持原样。缓存最多保留四个已清除引用的数组。应用外围输入限额或形状不受支持时沿用原读取器。
- **标量接口的分配型二进制写入。** 当 `IEnumerable<T>`、`ICollection<T>`、`IReadOnlyCollection<T>` 或 `IReadOnlyList<T>` 持有元素为受支持框架标量的精确 `List<T>` 时，Next 可获取一次元素跨度，并用其确定最终字节数组的大小及填充范围。写入保留原计数和原始数据块格式。其他输入沿用池化写入器及其枚举规则。读取状态和复用输出的操作沿用既有路径选择。
- **稠密原始标量 `HashSet` 的二进制写入。** 在支持 SSE 的 x64 上，若运行时探测确认框架条目步长为 12 字节且值位于偏移 8，共用写入器可以按枚举顺序一次写入四个 32 位值。写入前预留完整记录，每次向量读取都位于捕获的稠密条目区间内。存储稀疏或重叠、探测不可用、其他值宽度或平台时沿用现有标量写入。有界尾部使用普通标量写入器。
- **优先队列的二进制紧凑写入。** 在现代 64 位运行时上，若实际数组字段地址证明支持的整数字段顺序、相邻关系及步长与 wire 键值对一致，则可以一次复制类型精确的框架 `PriorityQueue<TElement, TPriority>` 的活动堆。`TryAllocatePriorityQueueRecord` 直接将计数和堆数据写入最终数组。复用输出的写入保留原有空间、重叠、记录头、版本和游标检查。包含填充、字段重排、布局无法验证或缺少 helper 时沿用原写入器。
- **Next 不可变线性集合。** 接口指向确切框架队列时，可以沿用双栈遍历，无需创建惰性反转缓存。JSON 队列读取可以租用元素缓冲区，再通过框架 span 工厂一次构造。栈接口可以直接枚举确切框架栈，并从暂存的 JSON 元素或经过完整校验的二进制原生数据构造最终节点。自定义接口实现保持自己的枚举顺序。
- **池化类型的全新读取。** 普通（`Object` 模式）二进制读取中，带 `[LuminPackPoolRent]` 的引用类型在目标为 null 时先租用实例（根对象和内联成员都一样），然后像读入已有实例一样读取。版本容忍和引用跟踪模式保留各自的暂存成员和延迟提交。
- **回调**在既定的时机和顺序执行。

### 选项与生成

- **编译期选项。** `[LuminPackOption]` 的作用域（程序集、类型、成员）和无状态的 `ILuminPackOptions` 配置都编译进代码。不存在运行时选项对象或可变的全局默认值。JSON 的编码、深度和语法策略作用于整份文档，由根类型决定。
- **`UntrustedData`** 在编译期选择带检查的二进制读取，默认开启；`UntrustedData = false` 生成的代码与可信代码完全相同。不可信记录使用普通线格式和写入端。对象、版本容忍记录、引用跟踪记录和 Union 的生成读取在实际读取位置检查对象标记、Boolean 值域、回引类型、原始槽位宽度、压缩计数以及已声明的集合和字符串限额，根的限额以常量固化；未声明的限额是不设上限的常量。只在声明了 `MaxDepth` 的递归类型中计数深度；Reader 边界检查和栈保护保持开启。显式的恶意输入声明还会选择严格 JSON 配置。由输入决定的类型直接拒绝。不存在信封、环境计费状态或模式预扫描。
- **`[LuminPackBounded]`** 是调用方的担保：有界记录一次性预留，并去掉内部容器检查。
- **自动生成**发现已声明的模型图和静态所需的闭合操作。旧的生成档位设置被忽略。应用程序和没有友元访问的 Unity 预定义程序集按绑定调用的负载独立保留四种操作，并扩展到成员图与 Union 依赖。编译器拦截与 IL 改写采用相同的操作选择。无法推导更窄范围时，未解析的序列化表达式、注册与直接调用生成的格式化器会保留全部四种操作。库看不到消费方的调用，为已发现的负载保留全部四种操作。注册策略和线格式独立于操作选择。程序集级生成选项可强制保留单个操作。
- **增量缓存**保留精确的语义依赖、设置、诊断和确定性的标识。跨编译的缓存中不能留下任何 `Compilation`、`SemanticModel` 或符号。保留驱动器的输出必须与全新生成的输出一致。

### 可选模块

- Core 不引用 `LuminPack.Unity` 和 `LuminPack.Burst`。
- `LuminPackBurst` Hook 表只存在于 `netstandard2.1`，遵循 [Hook ABI](burst-hooks.cn.md)。空槽位保留 Core 的实现。Burst 代码从 Core 源码投影生成，绝不另外维护第二套算法。

## 3. 安全规则

1. **Release 下保留 Reader 检查。** 前进式 Reader 的 public `EnsureReadable` 及其调用者（`Advance`、固定存储批次、Union 帧）在所有配置下都启用。不得恢复 `Conditional("DEBUG")`、用 `#if DEBUG` 包裹，或为了性能绕过它们。
2. **先检查后访问。** 替代 `Advance` 的生成游标运算，在移动游标之前保留范围检查。标量读取和固定字段回退在任何 unsafe 加载或写入目标之前校验完整范围。
3. **保留动态检查。** 集合、字符串和批量负载的头部与负载校验是必需的。任何按计数分配之前，先用剩余输入长度校验该计数。
4. **独立的不检查契约。** 写入已预留空间的固定 Writer 存储和仅基于地址的原始内核，保持各自现有的不检查契约。这不代表可以删除 Reader 检查，也不代表要给 Writer 一律加检查。
5. **递归。** 递归负载的操作调用 `EnsureSufficientStack`，递归的二进制写入在重入时检查容量。
6. **有符号比较。** 与缓存结束位置的范围比较使用有符号 64 位距离，这样在所有目标上都能拒绝越过末尾的游标和负数计数。
7. **异常**通过 `LuminPackExceptionHelper`（运行时）或生成器自己的辅助类抛出。保留异常类型、参数名、清理逻辑和原始调用栈。

## 4. SIMD

- 每次 SIMD 改动都要审查标量、128 位、256 位、512 位和 ARM64 路径。
- 每个特定指令集的操作都用其精确所需的特性来保护。向量宽度偏好不等于硬件支持。
- 保留有界尾部处理、标量或可移植回退、零长度行为以及完全相同的字节结果。绝不读写已校验完整范围之外的内存。
- 固定宽度的算法只有在有书面理由时才能保留其自然宽度。
- 本地没有的硬件需要在 CI 上执行。编译通过或合成的掩码不算硬件验证。

## 5. 性能证据

- 主要证据是 LuminPack 耗时除以参照库耗时，在同一台机器、同一份数据、同一运行时和选项下于同一次运行中测得。越低越好。
- 报告相对同一参照的改动前后比值、多次采样及离散度，以及分配量。绝对时间作为辅助证据保留。
- 不要从单个纳秒数字推断提升，也不要假设所有负载的波动方式相同。
- 机器负载导致计时不可靠时，改为比较保留的 IL 和原生代码，并说明这一点。
- 可复用缓冲区的基准要把每条独立记录前的重置计入测量。

## 6. 仓库规则

- 代码、注释、XML 文档、诊断、测试和维护文档使用英文。README 和 `*.cn.md` 中文版是例外。
- README、CONTRIBUTING 以及功能指南都有英文版（`name.md`）和中文版（`name.cn.md`）；两个版本一起修改。`AGENTS.md` 只有英文版。所有中文版统一放在 `docs` 下：根目录页面译文直接放在 `docs`，模块 README 译文放在 `docs/modules/<模块名>.cn.md`，功能指南译文与英文版放在一起。英文文档保留原有位置。
- README 只放介绍、安装和使用。发布说明、版本历史、迁移通知和实验报告既不放 README 也不放 `docs`，这些记录不纳入版本控制。
- 不要仅凭调用点搜索就删除外部可用或生成代码使用的成员。
- 维护的源码中每个方法都要有 XML 文档（由 `tools/LuminPack.RepositoryChecks` 检查）。生成的 XML 仅用于可直接调用的 `LuminPackSerializer` API 和门面类型。执行根方法、保留的内部状态转发方法、布局辅助方法、派发槽及私有辅助代码不生成 XML。生成文件对这些有意省略文档的实现细节屏蔽 CS1591。
