# 机制契约

[English](mechanism-contract.md)

本文列出 LuminPack 的硬性约束，适用于整个仓库：运行时代码、生成器、生成的代码、可选模块以及各条件编译目标。往返测试通过、文件变小或基准变快，本身都不能成为替换下列机制的理由。

每次批准的历史记录保存在 Git 中。如果本文、代码和历史三者不一致，请带着证据报告差异，不要擅自选一种设计。

## 1. 变更管控

1. **默认保留机制。** 第 2 节中的每个机制都保持原样，除非所有者明确批准一个具体的替换方案。
2. **先做实验。** 更快的替代方案在 `experiments/`（不纳入版本控制）中准备，需要包含：
   - 与相同参照库（如 Nino、MemoryPack、System.Text.Json）的耗时比值，改动前后都要有，且在同一台机器、同一份数据、同一运行时和选项下于同一次运行中测得；
   - 多次采样及其离散度，以及分配量；
   - 必要时提供生成的源码、IL 或原生代码；
   - 语义、API、数据格式、状态归属和平台方面的取舍。
3. **只有所有者明确批准该具体方案，才能替换。** 性能目标、重构、删除死代码或减小体积都不等于批准。
4. **正确性修复单独对待。** 已复现的 bug 可以在保持原有协议的前提下修复。请作为修复记录并附带回归测试，不要声称实现没变。
5. **记录批准的差异。** 把批准的规则写进本文（写规则，不写带日期的叙述），并在提交说明中描述改动。
6. 除非所有者要求，**不要提交、推送或打标签**。

## 2. 必须保留的机制

### 存储访问

- **Local + As 视图。** private、protected、readonly 以及自动属性 backing field 的存储，通过生成的布局镜像和 `Unsafe.As` 访问，绝不使用反射。镜像复刻继承链和 `LayoutKind`（包括显式偏移）。可访问的可写字段直接访问。
- **存储占位。** 镜像字段、padding 成员和隐藏存储不能因为普通的调用点搜索找不到引用就删除。
- **相邻字段批量复制。** 连续的非托管字段只在 64 位上、且证明实际字段地址与紧凑偏移一致、排除 volatile 字段并保留逐字段回退时，才可以整块复制。
- **按架构区分的固定值访问。** 在 32 位上，只有 `Unsafe.SizeOf<T>() <= 4` 的单个非托管值可以使用类型化的 `Unsafe.ReadUnaligned` / `WriteUnaligned`。更大的值和字段批次使用 `LuminPackMarshal.CopyBlockUnaligned` 和紧凑存储视图，因为对它们做类型化非对齐访问可能让 IL2CPP 崩溃。所有成员都不超过 4 字节，也不代表可以对整体做类型化访问。64 位上类型化访问和块复制都允许。
- **原始复制。** 不重叠的块复制（包括生成代码中的）都经过 `LuminPackMarshal.CopyBlockUnaligned`；只有这个辅助方法直接调用 `Unsafe.CopyBlockUnaligned`。允许重叠的 span 复制保持 memmove 语义。

### 数据表示

- **Object 模式**按位置写成员，成员数为 1 字节（0 到 249，`255` 表示 null）。
- **版本容忍**使用带 UTF-8 元数据的命名成员、长度表和按字节的元数据比较；`LuminPackOldName` 写入时保留最早的名称。
- **引用跟踪**（`CircleReference`）保留槽位长度表和引用 id。
- **非托管结构体**遵循 `StructLayout` 契约：`Tagged`（默认）、`Packed`、`Native`。
- **字符串**默认使用 UTF-16 长度记录，带紧凑 Latin-1 形式；UTF-8 和 Token 配置保持可用。长度记录区分 null 与空字符串；Token 记录二者共用空终止符。
- **JSON** 保持其包络格式（`$type`/`$value`、`$id`/`$ref`、`Lazy`、多维数组），并拒绝非有限数字。
- **字节序**为小端。任何模式都不做字节序转换。
- 改变任何线上字节都需要明确批准，并更新数据格式测试夹具。

### 派发

- **具体重载**直接绑定生成的根方法体，从不查询注册表。
- **泛型入口**先查显式注册和 `Custom` 注册，然后按类型和配置在首次使用时创建该类型的生成入口。不为每个分析到的类型生成类型 id 表、类型 switch 或注册块。
- **Union 派发**是在根类型上生成的 public 虚方法（`EditorBrowsable(Never)`）。泛型 Union 根在虚调用之后增加缓存槽位 switch。不使用泛型虚方法、运行时类型映射或替代用的 switch。
- **注册**传入以方法表地址为键的静态方法指针（`LuminPackFormatter`）。不保存 `Type` 或委托，因此可回收的 `AssemblyLoadContext` 可以卸载。注册在发布前校验标签、case 类型和必需操作。
- **`Custom`** 格式化器拥有完整的数据表示，通过注册的指针调用。

### 执行状态

- **前进式游标。** 二进制和 JSON 读写器在新版 .NET 上前进 `ref byte` 游标，在 `netstandard2.1` 上前进 `byte*` 游标。
- **缓存结束位置。** Writer、Reader、JSON Writer 和 JSON Reader 在游标旁缓存窗口的结束位置（或写入器的扩容阈值）。`Buffer`、`BufferCheckLimit` 和 `Owner` 的 getter 为 public、setter 为 internal，setter 会刷新缓存；每个构造函数和每次窗口变化都必须刷新。
- **游标发布。** 生成代码可以在两个会观察状态的边界之间把游标放在局部变量中。在调用格式化器、Union 或递归操作、回调或容量检查之前必须发布游标，之后从结果状态恢复。绝不能在扩容之后继续持有旧的缓冲区引用。
- **固定 Union case 写入。** 符合条件的本地、窄标签、非泛型类 Union 的普通虚 case 槽位可以在共享的返回游标方法体内一并写入标签和无回调的固定负载，并在返回前发布结果位置。该路径保留原有虚槽位和各配置槽位，排除外部输入策略 case；其他 case 保留原有写入路径。
- **大型固定 Union 记录。** 固定负载宽度加上最大 Union 头长度超过普通扩容检查保证的最小余量时，必须在该负载的无检查存储之前为整个负载预留容量。返回游标的方法体在该容量边界前发布绝对游标，并在扩容后重新取得输出存储。小型固定负载保留基于扩容阈值的预留契约。
- **每个操作一个状态方法体。** 每个保留类型对二进制写、二进制读、JSON 写、JSON 读和大小计算各有一个完整方法体；便捷重载转发到它。
- **调用方持有的追加会话。** 接收 `LuminBufferWriter` 的重载从其游标处追加，并保留引用状态直到调用方重置（`ResetForReuse`、`Reset`、`ResetCore`）。
- **独立的默认引用上下文。** 互相独立的默认读取器、写入器和计算器绝不共享引用身份。
- **构造、池化与复用。** 构造函数选择、`[LuminPackPoolRent]`、对象/集合/字符串的 `ref` 复用，以及文档中描述的失败时发布规则都要保留。复用不是事务性的。
- **池化类型的全新读取。** 普通（`Object` 模式）二进制读取中，带 `[LuminPackPoolRent]` 的引用类型在目标为 null 时先租用实例（根对象和内联成员都一样），然后像读入已有实例一样读取。版本容忍和引用跟踪模式保留各自的暂存成员和延迟提交。
- **回调**在既定的时机和顺序执行。

### 选项与生成

- **编译期选项。** `[LuminPackOption]` 的作用域（程序集、类型、成员）和无状态的 `ILuminPackOptions` 配置都编译进代码。不存在运行时选项对象或可变的全局默认值。JSON 的编码、深度和语法策略作用于整份文档，由根类型决定。
- **`UntrustedData`** 在编译期选择受限的外部数据协议；未开启的声明生成的代码与可信代码完全相同。
- **`[LuminPackBounded]`** 是调用方的担保：有界记录一次性预留，并去掉内部容器检查。
- **生成模式** `Full`、`Medium`、`Light`、`Minimal` 保持各自的可达性规则。裁剪只决定哪些代码存在，绝不改变数据格式或所选的格式化器。
- **增量缓存**保留精确的语义依赖、设置、诊断和确定性的标识。跨编译的缓存中不能留下任何 `Compilation`、`SemanticModel` 或符号。保留驱动器的输出必须与全新生成的输出一致。

### 可选模块

- Core 不引用 `LuminPack.Unity` 和 `LuminPack.Burst`。
- `LuminPackBurst` Hook 表只存在于 `netstandard2.1`，遵循 [Hook ABI](burst-hooks.cn.md)。空槽位保留 Core 的实现。Burst 代码从 Core 源码投影生成，绝不另外维护第二套算法。

## 3. 安全规则

1. **Release 下保留 Reader 检查。** 前进式 Reader 的 public `EnsureReadable` 及其调用者（`Advance`、固定存储批次、Union 帧）在所有配置下都启用。不得恢复 `Conditional("DEBUG")`、用 `#if DEBUG` 包裹，或为了性能绕过它们。
2. **先检查后访问。** 替代 `Advance` 的生成游标运算，在移动引用或指针之前保留范围检查。标量读取和固定字段回退在任何 unsafe 加载或写入目标之前校验完整范围。
3. **保留动态检查。** 集合、字符串和批量负载的头部与负载校验是必需的。任何按计数分配之前，先用剩余输入长度校验该计数。
4. **独立的不检查契约。** 写入已预留空间的固定 Writer 存储和仅基于地址的原始内核，保持各自现有的不检查契约。这不代表可以删除 Reader 检查，也不代表要给 Writer 一律加检查。
5. **递归。** 递归负载的操作调用 `EnsureSufficientStack`，递归的二进制写入在重入时检查容量。
6. **有符号比较。** 与缓存结束位置的范围比较使用有符号 64 位距离，这样在所有目标上都能拒绝越过末尾的游标和负数计数。
7. **异常**通过 `LuminPackExceptionHelper`（运行时）或生成器自己的辅助类抛出。保留异常类型、参数名、清理逻辑和原始调用栈。

## 4. SIMD

- 每次 SIMD 改动都要审查标量、128 位、256 位、512 位和 ARM64 路径。
- 每个特定指令集的操作都用其精确所需的特性来保护。向量宽度偏好不等于硬件支持。
- 保留有界尾部处理、标量或可移植回退、零长度行为以及完全相同的字节结果。绝不读写已校验完整范围之外的内存。
- 固定宽度的算法只有在有书面理由时才能保留其自然宽度（例如 16 字节的 F14 标签组）。
- 本地没有的硬件需要在 CI 上执行。编译通过或合成的掩码不算硬件验证。

## 5. 性能证据

- 主要证据是 LuminPack 耗时除以参照库耗时，在同一台机器、同一份数据、同一运行时和选项下于同一次运行中测得。越低越好。
- 报告相对同一参照的改动前后比值、多次采样及离散度，以及分配量。绝对时间作为辅助证据保留。
- 不要从单个纳秒数字推断提升，也不要假设所有负载的波动方式相同。
- 机器负载导致计时不可靠时，改为比较保留的 IL 和原生代码，并说明这一点。
- 可复用缓冲区的基准要把每条独立记录前的重置计入测量。

## 6. 仓库规则

- 代码、注释、XML 文档、诊断、测试和维护文档使用英文。README 和 `*.cn.md` 中文版是例外。
- README、AGENTS、CONTRIBUTING 以及 `docs` 下的每篇文档都有英文版（`name.md`）和中文版（`name.cn.md`）；两个版本一起修改。
- README 只放介绍、安装和使用。发布说明、版本历史、迁移通知和实验报告既不放 README 也不放 `docs`，这些记录不纳入版本控制。
- 不要仅凭调用点搜索就删除外部可用或生成代码使用的成员。
- 每个方法都要有 XML 文档（由 `tools/LuminPack.RepositoryChecks` 检查）。

## 7. 验证

运行 [CONTRIBUTING](../CONTRIBUTING.cn.md) 中覆盖本次改动的检查：仓库检查、生成器与生成代码契约、针对性的运行时测试、增量生成、数据格式夹具，以及平台相关代码的运行时兼容性工作流。结构断言和往返测试只能证明已测试形态的覆盖，不能证明对所有模型都成立；请报告未验证的部分。
