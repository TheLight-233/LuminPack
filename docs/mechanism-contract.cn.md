# 机制契约

[English](mechanism-contract.md)

本文列出 LuminPack 的硬性约束，适用于整个仓库：运行时代码、生成器、生成的代码、可选模块以及各条件编译目标。往返测试通过、文件变小或基准变快，本身都不能成为替换下列机制的理由。

每次批准的历史记录保存在 Git 中。如果本文、代码和历史三者不一致，请带着证据报告差异，不要擅自选一种设计。

## 1. 变更管控

1. **默认保留机制。** 第 2 节中的每个机制都保持原样，除非所有者明确批准一个具体的替换方案。
2. **先做实验。** 更快的替代方案在 `experiments/`（不纳入版本控制）中准备，需要包含：
   - 与相同参照库（如 Nino、MemoryPack、System.Text.Json）的耗时比值，改动前后都要有，且在同一台机器、同一份数据、同一运行时和选项下于同一次运行中测得；
   - 多次采样及其离散度，以及分配量；
   - 必要时提供生成的源码、IL 或原生代码；
   - 语义、API、数据格式、状态归属和平台方面的取舍。
3. **只有所有者明确批准该具体方案，才能替换。** 性能目标、重构、删除死代码或减小体积都不等于批准。
4. **正确性修复单独对待。** 已复现的 bug 可以在保持原有协议的前提下修复。请作为修复记录并附带回归测试，不要声称实现没变。
5. **记录批准的差异。** 把批准的规则写进本文（写规则，不写带日期的叙述），并在提交说明中描述改动。
6. **默认提交已完成的工作。** 完成一个功能或修复并进行相应验证后，按[提交规范](CONTRIBUTING.cn.md#提交规范)直接提交本任务的改动，无需询问提交权限。排除无关或未完成的改动。提交后询问是否推送；所有者已授权该次推送时直接执行。打标签和重写已发布历史仍需明确授权。

## 2. 必须保留的机制

### 存储访问

- **Local + As 视图。** private、protected、readonly 以及自动属性 backing field 的存储，通过生成的布局镜像和 `Unsafe.As` 访问，绝不使用反射。镜像复刻继承链和 `LayoutKind`（包括显式偏移）。可访问的可写字段直接访问。
- **存储占位。** 镜像字段、padding 成员和隐藏存储不能因为普通的调用点搜索找不到引用就删除。
- **相邻字段批量复制。** 连续的非托管字段只在 64 位上、且证明实际字段地址与紧凑偏移一致、排除 volatile 字段并保留逐字段回退时，才可以整块复制。
- **按架构区分的固定值访问。** 在 32 位上，只有 `Unsafe.SizeOf<T>() <= 4` 的单个非托管值可以使用类型化的 `Unsafe.ReadUnaligned` / `WriteUnaligned`。更大的值和字段批次使用 `LuminPackMarshal.CopyBlockUnaligned` 和紧凑存储视图，因为对它们做类型化非对齐访问可能让 IL2CPP 崩溃。所有成员都不超过 4 字节，也不代表可以对整体做类型化访问。64 位上类型化访问和块复制都允许。
- **原始复制。** 不重叠的块复制（包括生成代码中的）都经过 `LuminPackMarshal.CopyBlockUnaligned`；只有这个辅助方法直接调用 `Unsafe.CopyBlockUnaligned`。允许重叠的 span 复制保持 memmove 语义。它按处理器类别划分的尺寸范围只能依据新的跨主机测量调整，测量记录写在 `LuminKernelPolicy` 旁。处理器类别分为 Intel、AMD Zen 5、其他 AMD 和其他 x64，只用 CPUID 读取一次；其他目标使用运行时复制。`AllocateUninitializedArray` 的清零阈值（Intel 为 16 KiB，其他为 5 KiB）遵循同样的规则。

### 数据表示

- **Object 模式**按位置写成员，成员数为 1 字节（0 到 249，`255` 表示 null）。
- **版本容忍**使用带 UTF-8 元数据的命名成员、成员宽度表和按字节的元数据比较；`LuminPackOldName` 写入时保留最早的名称。修订版 2 的记录单遍写出：原始成员按表中宽度写出，变长成员前带 `int` 长度。读取方继续接受修订版 1 的记录。
- **引用跟踪**（`CircleReference`）保留槽位表和显式引用 id。表中每个槽位一个宽度字节（原始宽度；空槽位为 `0`；`255` 表示值前带 `int` 长度），因此记录可以单遍写出；表与自身一致的读取方按常量字比较后直接读入对象。未知的尾随槽位会被跳过，显式 id 保证跳过之后的回引用仍然准确。写入方先用引用扫描查找一次操作中的前几个对象，之后才使用哈希；读取方用数组存储顺序分配的引用 id，并用一次探测同时检查和登记可复用的候选对象。
- **非托管结构体**遵循 `StructLayout` 契约：`Tagged`（默认）、`Packed`、`Native`。
- **字符串**默认使用固定宽度的 UTF-16 长度记录，带紧凑 Latin-1 形式；UTF-8 和 Token 配置保持可用。可选的 `VarInt` 记录将每个原有长度头加一，再以规范的无符号 base-128 编码，保留负载编码及 null 与空字符串的区分；UTF-8 保留两个长度字段。默认固定宽度格式及其字节保持不变，读写双方选择相同配置。Token 记录二者共用空终止符。
- **JSON** 保持其包络格式（`$type`/`$value`、`$id`/`$ref`、`Lazy`、多维数组），并拒绝非有限数字。
- **规范 JSON 时钟读取。** 在现代 .NET 上，内置 UTF-16 长度配置可以在当前区域性为不变区域性时，将精确的 `HH:mm:ss.fffffff` 标记解析为 `TimeOnly` 或一天内的非负 `TimeSpan`。读取器先校验并暂存标记，再提交值的读取状态，随后检查数字范围并构造结果。其他形式、区域性和配置沿用既有解析器。
- **规范 JSON 日期读取。** 现代 Core 可对已解码的 `DateOnly` 标记进行有界 ASCII 数字与公历校验，解析精确的不变区域性 `yyyy-MM-dd` 格式。Next 在引用的运行时提供该辅助方法时选用它。沿用既有的标记完成步骤，其他格式和无效日期交由框架的往返格式解析器处理。
- **规范 JSON 时间戳读取。** 在现代 .NET 上，内置 UTF-16 长度配置可在当前区域性为不变区域性时，解析带 UTC 标记的精确往返格式 `DateTime` 和带显式有符号偏移的精确往返格式 `DateTimeOffset`。沿用标记校验、私有暂存和读取状态提交，随后将有界 ASCII 标记收窄为字节，并要求框架的往返格式字节解析器消费整个标记。其他形式、区域性和配置沿用原解析器。
- **引用追踪 JSON 属性头。** 在 64 位现代 .NET 上，生成的写入方法在连续输出和分段输出时都可以把完整的静态属性头复制到当前窗口，并一次推进游标。属性头沿用文档编码和当前分隔符状态。窗口不足或配置不受支持时沿用原有属性写入方法，保留输出回调、已提交前缀和引用注册顺序。
- **普通 JSON 整数字段组。** 对于连续、可直接写入的非 volatile `Int32` 字段，生成的 Reader 可以在有界的局部托管窗口中匹配完整静态字段头并解析纯整数。分块结束或回退前，只发布已成功消费的前缀。保留逐字段赋值、分隔符语法、复用行为及首个失配字段上的普通解析路径。
- **字节序**为小端。任何模式都不做字节序转换。
- **压缩**采用 `LUM2` 帧：小于 255 的长度扩展占一个字节，较长扩展使用转义字节及规范的无符号 base-128 余数；保留 64 KiB 匹配窗口及每线程位置表。高压缩率的分配式读取在分配前验证完整序列结构。拒绝旧的 `LUMZ` 帧。匹配钩子、有界 SIMD 尾部、解码检查及 32 位访问规则仍然有效；参见[压缩](compression.cn.md)。
- 改变任何线上字节都需要明确批准，并更新数据格式测试夹具。
- **二进制系统时区。** 经实例身份确认的系统区在标记 `1` 后携带时区标识。空值标记及完整快照标记 `0` 保留原含义。接收端以其系统目录的规则为准，缺少标识时在发布目标前报错。标识应用所选字符串配置和输入限额。内置 UTF-16 长度配置只有在扩容阈值前能容纳完整 UTC 记录时才使用一次定宽写入。区间较短时使用原有分帧字符串操作。

### 派发

- **具名成员内核。** 源码内定义、不含继承、回调或有界记录声明的非泛型位置类，在成员都是公开原始存储或字符串、且至少含一个字符串成员时，可以共享一个具体的静态成员写方法。纯定长记录保留现有紧凑存储。保留原有成员头、字段地址证明、定长存储、字符串操作和编译期成员配置，不用独立根方法的容量融合替换成员语义。成员内核保留内联提示，其调用方的根方法交由运行时决定是否内联。仅包含运行时记录内核和无独立配置边界的具名成员调用的完整公开字段写入，可以直接使用已有类型事实生成。其余契约沿用现有操作投影。此机制不增加运行时计划、格式化器见证或载荷派发，也不删除现有入口。
- **Next 嵌套记录入口。** JSON 嵌套字段使用具体 Formatter 的文档配置入口。二进制位置记录仅在原有头部、输入校验策略、字段地址证明和部分读取行为保持一致时调用子类型已有的对象或载荷读取入口。先在局部变量中读取子对象，成功后才将新对象写回成员。可直接调用已有的二进制成员写入入口，也可调用存储操作等价的独立写入入口。独立入口的输出预留方式不同时，保留原有的成员写入方式。
- **静态入口**在编译器支持带版本的拦截位置且使用 C# 11 或更高版本时使用 Interceptor。闭合负载调用（包括显式泛型写法）直接绑定既有具体 Root，不经过负载类型分发、反射或委托缓存。显式配置同时指定负载和配置类型；任何后端都不在公共门面生成负载专属的配置便捷重载。静态接入路径的具体状态转发方法使用负载专属名称，便捷入口位于负载专属容器中。不增加 Runtime Plan 或格式化器见证类型。旧编译器通过已安装的 IL 后处理器使用相同具体入口和精确签名映射，替换本程序集静态调用操作数，校验栈类型并保留 Portable PDB；签名产物需要原始签名密钥。两种接入均关闭时，默认调用保留具体重载，显式配置调用使用已注册的泛型兜底。
- **应用程序内的状态转发。** 启用编译器拦截且没有友元访问的可执行项目中，只有一次调用的状态拦截器可直调现有嵌套 Root，保留原签名、配置和参数传递方式。仅当所有已生成贡献和用户源码都未引用某个负载专属的内部转发方法，且其声明无歧义时，才可省略该方法。库、有友元访问的程序集和 IL 改写后端保留原状态转发和绑定契约。
- **源码泛型包装方法**在静态源码方法体可以安全迁移时，于闭合调用处生成特化实现。保留参数求值、重载选择、调用者信息、副作用以及方法与所属类型的关联类型实参。不透明或不支持的方法体保留原调用并使用注册兜底。拦截不会改写引用程序集或替换虚方法派发。
- **Next 静态入口。** Next 只拦截负载类型已闭合的门面调用。拦截器调用既有静态 Root 并处理相应的文档边界。显式配置共用拦截器的配置类型参数。源码泛型包装方法中的开放负载调用使用注册兜底，不执行过程间展开。生成的 XML 文档位于公开门面上。
- **泛型兜底入口** 使用显式注册和 `Custom` 注册。Next 还会在消费程序集的注册表中登记已发现闭合负载的生成操作，并使用 Core 中内置的标量和字符串注册。门面在首次使用时初始化注册，显式注册的操作优先。缺少注册或操作时抛出 `LuminPackException`。关闭注册同时禁用兜底。注册不依赖运行时类型发现或反射工厂。泛型兜底文档边界使用消费程序集默认值或显式配置，拦截后的具体 Root 保留声明所属的选项。
- **Union 派发。** Next 对生成 case 数不超过 32 的类和接口 Union 使用精确运行时类型比较链，直接调用具体负载 writer，涵盖闭合和开放泛型 case。二进制精确分发在每个分支中直接比较 `GetType()` 和 `typeof(Case)`。更大的 Union 保留生成的公开虚槽位。虚方法中的泛型写入器在需要从声明的 case 中选择时，为每个闭合类型以 `static readonly int` 缓存匹配 case 的名称哈希。二进制和 JSON 的第二层派发使用相同的哈希常量，JSON 仍写入声明的数字标签。只有生成虚槽位的档位要求声明为 partial。未命中的运行时类型继续查找类型化注册或抛出未知 case 错误。启用注册的二进制精确写入器使用不内联的辅助方法执行这条回退路径。
- **二进制 Union 类型名。** Next 将生成 case 的规范 UTF-8 类型名的 FNV-1a 哈希写为四字节小端值，后接原有负载。名称包含命名空间、嵌套类型、闭合泛型参数及按位置编号的开放参数。生成器拒绝哈希冲突和保留值。零表示 null，全一值后接注册委托原有的数字标签和负载。JSON 和 C# 编译器 Union 结构体沿用原标签。此前的类与接口 Union 二进制帧属于另一套线格式。
- **Union 集合。** 列表、一维数组、`ImmutableArray<T>` 和字典均按输入顺序逐元素使用根选定的写入档位。密集字典在既有的固定 Union 游标协议中应用同一档位。负载是否定长不改变档位或字符串表示。二进制 Union 成员的状态转发方法保留内联提示，并调用原根方法。
- **Fresh Union 元素。** 新分配的 Union 集合存储可以先通过初始化为 null 的局部变量读取，再赋给元素，保持 Union 操作在负载成功读取后发布结果的既有行为。已有元素保留复用路径；普通对象和 Custom 格式化器保留各自的发布契约。
- **新建固定 Union case 的读取。** 在 64 位新版目标上，Next 可对不经池租赁、无回调的新建固定 case 使用现有带校验的块读取。连续字段须可直接写入、非 volatile、无托管引用，且不涉及布尔值校验。使用块读取前证明实际字段地址连续，并保留逐字段兜底。复用的同类型 case 也可使用同一带校验的块读取，因为复制任何字节前已校验完整范围；复用分支只在 case 对象变化时写回槽位。推进游标或写入批次前校验完整输入，负载读取成功后才发布新建 case。
- **新建负载记录的批量读取。** 记录根的 payload framing 读取在刚创建实例时，可以对可直接写入、非 volatile 字段组成的定长连续段，使用 object 读取已有的带校验批量读取（`ReadBatch` 或带校验块读取，附字段地址证明和逐字段兜底）。带回调或池租赁的记录以及复用实例保留逐字段读取。调用方会先把新实例暂存在局部变量中；公开的多态读取槽位例外：遇到非法布尔字节时，已发布实例中会保留已拷贝的整段，与 object 读取的既有行为一致。
- **共享定宽 Union 块读取。** Union 读取 switch 中负载宽度相同的两个及以上定宽 case 可以共用一次带校验的块读取。每个 case 保留各自的分配或精确类型复用、字段地址证明和逐字段兜底；通过证明的 case 选出目标块后跳转到共享读取。新建元素在该读取完成后才发布；复用目标仅在 case 对象改变时于读取之后写回。switch 处理四字节 null 标记，并在读取负载前检查标识。
- **注册**传入强类型委托（`LuminPackFormatter`），不要求 unsafe 上下文。条件弱表使完整注册项随载荷类型存活，方法表索引只保存弱引用，因此可回收的载荷程序集可以卸载。委托及其捕获对象在载荷注册项存活期间保持存活；为不可回收载荷注册可回收程序集中的代码，会将该代码保留至载荷生命周期结束。注册在发布前校验标签、case 类型和必需操作。
- **`Custom`** 格式化器拥有完整的数据表示，通过注册的委托调用。

### 执行状态

- **前进式游标。** 二进制和 JSON 读写器在新版 .NET 上使用 `ref byte` 游标，在 `netstandard2.1` 上用长度为 1 的 `Span<byte>` 保存托管游标地址。该 Span 的长度仅用于表示游标，实际可访问范围由保留的窗口和结束缓存决定。底层调用方可用 `MemoryMarshal.GetReference` 取得游标引用。
- **缓存结束位置。** Writer、Reader、JSON Writer 和 JSON Reader 在游标旁缓存窗口的结束位置（或写入器的扩容阈值）。`Buffer`、`BufferCheckLimit` 和 `Owner` 的 getter 为 public、setter 为 internal，setter 会刷新缓存；每个构造函数和每次窗口变化都必须刷新。
- **游标发布。** 生成代码可以在两个会观察状态的边界之间把游标放在局部变量中。在调用格式化器、Union 或递归操作、回调或容量检查之前必须发布游标，之后从结果状态恢复。绝不能在扩容之后继续持有旧的缓冲区引用。
- **对象标记和首个标量。** 在现代 .NET 上，普通位置类若以一个标量开头、紧接着是变长字段，可写入成员数和标量后一次更新游标。此路径要求 Core 提供对应重载，首字段可直接访问且非 volatile，类没有基类负载、已实现的接口、回调、镜像或显式大小上界。连续定长字段沿用原有布局证明。标量遵循原有 32 位存储规则，Debug 按原顺序校验两次推进。
- **标量读取。** 生成的标量读取调用 `LuminPackReader.Read`。定长批次或序列窗口可以在校验完整区间后使用按地址读取的重载。32 位标量访问由 Reader 选择，批量读取和不可信读取仍遵循各自的存储证明和校验要求。
- **固定 Union case 写入。** 符合条件的本地非泛型类 Union 可在共用的返回游标方法体内一并写入四字节哈希和无回调固定负载。使用托管引用的路径将判别值和负载的推进量合并为相对当前输出引用的偏移。返回前及预留容量前均将偏移换算为游标，预留后以刷新的游标为起点重新计算偏移。虚分发档位保留各配置槽位，外部输入策略 case 沿用普通路径。
- **大型固定 Union 记录。** 固定负载宽度加上最大 Union 头长度超过普通扩容检查保证的最小余量时，必须在该负载的无检查存储之前为整个负载预留容量。返回游标的方法体在该容量边界前发布绝对游标，并在扩容后重新取得输出存储。小型固定负载保留基于扩容阈值的预留契约。
- **每个操作一个状态方法体。** 每个保留类型对每个生成的操作（二进制写、二进制读、JSON 写、JSON 读，见自动生成）各有一个完整方法体；便捷重载转发到它。直接记录另为其分配写入保留一个精确长度方法体。 对于反复遍历同类复合元素集合的大型二进制写方法，循环和预留容量区域以外的同级调用可以复用该框架集合的闭合写方法，并传入原状态和已编译的成员配置。 特大型二进制读方法可以将完整的成员分支拆成静态局部函数，按引用共享原 Reader 并操作同一类实例，保留校验、游标推进及失败时的赋值顺序。
- **托管输出存储。** `LuminBufferWriter` 拥有一个 `ArrayPool<byte>.Shared` 数组。所有目标都先用 `GCHandle` 固定新租用的数组，再测量 64 字节对齐的起点。固定持续到归还数组，使 GC 在租期内保持其对齐。扩容保留 32 KiB 初始容量、1.5 倍增长和 87.5% 阈值。已租数组放得下时原地扩展，否则复制到新固定的数组，再解固定并归还旧数组，刷新游标与结束缓存。每个暴露的字节要么在获取时清零，要么由所有者写入。终结器为未释放的 writer 释放固定句柄。数组由显式释放或归还回收至池中。
- **调用方持有的追加会话。** 接收 `LuminBufferWriter` 的重载从其游标处追加，并保留当前操作状态。`Reset()` 重置已发布的字节数和当前游标，清除读写操作状态，并保留容量。`ResetWrittenCount()` 重置写入计数和游标，保留读写操作状态及容量。`ResetAndRelease()` 重置写入计数和游标，清除读写操作状态，再归还当前租用的数组。writer 仍可继续使用。
- **定宽对象记录。** 没有回调的定宽原生类记录可以一次预留既有位置头和全部字段，再一次发布游标。只有经证明相邻的字段可整块拷贝。可计数数组在当前窗口覆盖连续非空定宽记录的完整上界时可以共用容量校验，空值和空间不足沿用普通记录路径。
- **位置记录和版本记录的原始成员。** 符合条件的原始数组和框架列表可以与相邻记录字段一起预留集合负载。二进制捕获与其他操作所需 formatter 的发布独立。读入沿用带校验的 formatter，集合标记及元素字节编码保持一致。
- **精确版本成员宽度。** Next 可以把经证明的字节长度写入既有版本长度槽，并在预留的连续范围内写完成员。未知长度沿用原回填路径。匹配的结构只能在验证记录长度及其完整负载后直接读取定宽成员。
- **常量版本前缀。** 闭合版本记录可以按常量宽度预留和计算完整前缀的大小。常量前缀达到 64 字节时，将完整前缀的匹配和预留区写入放在独立方法中，重复记录使用精简入口读写 12 字节指纹头。保留操作内的表历史、配置标记、短记录校验、完整前缀边界以及动态架构路径。
- **配置观察顺序。** 生成的位置记录或版本记录写入可在已验证的内置配置下，将新增的原始集合捕获移入更早的预留。若其他配置的属性可在观察集合前执行，则保留原来的预留边界。
- **独立的默认引用上下文。** 互相独立的默认读取器和写入器绝不共享引用身份。
- **新建 JSON 顺序集合容量。** 新建 List/Queue、普通序列接口、Collection/ObservableCollection 及只读包装可以在原逐项读取循环前使用只读结构容量提示；Grouping/Lookup 的元素 List 共用此规则。已有目标保留原复用、发布和回调；提示不可用或后续数量变化时继续扩容。短输入跳过扫描。新结果 Capacity 可以变化，额外扫描可能增加 CPU 成本，以避免增长分配为优先。数组和字典保持原构造；生成前检查可选 helper 元数据。
- **新建 JSON 哈希集合容量。** 在 Unity 以外的现代 .NET 上，新建具体 `HashSet<int>`、`HashSet<long>` 或 `HashSet<string>` 可为内置默认配置及 UTF-8、UTF-16 长度配置使用现有的结构容量提示。探测从 128 个元素开始，提示不超过 4096 才预分配容量。原有插入循环仍读取每个元素并处理重复项和无效输入。已有集合保留比较器和清空行为。
- **Next ObjectModel 包装集合格式化器。** 精确匹配且由已知列表或数组提供存储的框架包装集合，以及密封的集合构建器，可复用已有跨度内核批写 UTF-16 长度字符串和 UTF-8 JSON 整数。带版本的存储在输出窗口边界检查枚举版本，并在容量变化后重新读取后备数组。其他存储和配置沿用原格式化器循环。JSON 可观察集合在每个元素格式化后检查实际类型和订阅状态。新建包装集合或构建器可在原元素循环前用容量提示分配存储。
- **Next 集合接口写入。** 精确匹配的框架列表、数组、集合和字典可以选用具体类型的遍历。派生类型和自定义实现沿用接口枚举。可变字典接口可以在一次完整的边界检查后写入每对无回调的原始元素，枚举结束后回填元素数，输出区间不足时沿用逐成员写入。JSON 可以在原有逻辑记录中合并分隔符与整数元素或整数键值对。 现代 .NET 的自有缓冲区二进制写入，对精确匹配的 List、内置 UTF-16 长度配置，以及变长成员只有字符串或原始标量列表且无回调的位置记录，可以使用旧版的已知长度跨度和逐对象完整预留。数组、自定义接口实现、自定义配置及跨度目标沿用现有路径。
- **Next 具体字典记录。** 二进制写入可对已验证的 SortedList 数组或 SortedDictionary 独占租约中的非空原始键值对一次校验整个输出区间。区间较短时沿用原逐值写入。由定宽整数键值对构成的新建字典，可以在验证完整负载后直接读入已确认的存储。JSON 可以合并整数键值对的定界与数字写入。精确匹配的 SortedList 在写任一成员前先读取完整键值对，并在包括最后一次在内的所有原枚举边界检查修改版本。 有界 UTF-16 成对写入器也识别由声明固定封装的内置 UTF-16 长度配置及默认配置。 在扩容阈值前能完整写入原始键时，稠密字典的二进制写入可省去值 Formatter 前的扩容检查。阈值边界的回退仍校验容量，并在值原有的阈值检查前取值。 当键和值都是 Int32 时，内置 UTF-16 配置可在一个完整输出窗口内写入两个整数及键值对分隔符。窗口不足或区域性格式化可能触发回调时，使用原有的逐标量操作。
- **字典的并行存储。** SortedList 和冻结字典的二进制写入器可在已校验的并行存储上，对固定 UTF-16 字符串与非托管值组成的整对数据一次验证输出容量。原逐值回退在输出扩容时仍先取键再取值。SortedList 的 JSON 遍历保留版本检查和取值顺序。
- **Next 连续集合批写。** 精确匹配的 `int` 和 `long` 跨度可在当前输出区间内使用局部游标写入 JSON 元素。区间不足或重叠、或者 UTF-16 区域性可能触发用户回调时，沿用原标量操作和取值顺序。分段字符串的二进制 UTF-16 长度记录可在存储边界和原有扩容阈值内使用已有的批写内核，保留累计数量回填和下一条记录的标量检查。多维 JSON 数组保留形状帧，并按行优先顺序将已验证的暂存跨度复制到结果。存储地址取自框架的数组数据 API，旧目标使用声明下界处的带类型元素地址。
- **短原始集合写入。** 在受支持的 64 位目标上，读写范围已校验或预留且集合负载不超过 32 字节时，写入可以内联既有小块拷贝内核。更大的传输及不支持的平台沿用标准拷贝策略和共享非对齐访问方法。
- **Next 可变栈、队列和堆记录。** 精确匹配并经验证的栈可在确认容量的区间内按栈底优先顺序搬运无引用的二进制存储。直接填充的栈在校验完整负载后才发布。字符串栈和环形字符串队列可使用经边界校验的 UTF-16 长度记录批写。暂存字符串读取失败时，栈保持为空并清除引用槽。整数栈和队列可以跨输出窗口批量格式化 UTF-8。分隔符或数值可能回调输出方时，先捕获当前元素，再在继续时检查枚举版本，包括最后一个元素之后。优先队列保持堆的枚举顺序。整个二进制记录有足够空间时，可不含元组填充地写入两个字段；使用默认比较器的定宽标量读取可直接填充已校验的堆序前缀，再沿用常规插入。在支持 SSE 和 SSE2 的 x64 上，四字节元素与 `Int32` 优先级的紧凑键值对可用一次向量比较检查共享同一父节点的四个子节点并整组拷贝；遇到第一个被拒绝的组时回到标量检查。JSON 可复用有边界的整数键值对写入，并为含字符串成员的大型新堆使用容量提示，保留原比较器、键值对语法、部分读取的发布方式和回退路径。
- **深层 JSON 预读存储。** CountArrayElements 持有独立的深层语法副本，可以从 ArrayPool<byte>.Shared 租借和增长私有副本，并在成功或失败的 finally 中归还。原 reader 存储与状态保持不变。普通 reader 的深层语法仍保留原分配与生命周期。原生池缺失和裁剪机制照常运行。
- **Next JSON 数组池化读取。** 在内置的可信默认配置及 UTF-8/UTF-16 长度和标记配置下，共用的连续集合格式化器可以单遍解码到独占的池化存储，以构造替换 `T[]`、元素非 `string` 的 `ImmutableArray<T>`，或原值为默认值的 `ImmutableArray<string>`。确认数组结束标记处于外层深度后，才发布长度精确的结果。归还缓冲区时清除其中的引用槽。后续输入畸形时，合法前缀的元素回调可能先于错误报告执行。已有 `T[]` 只有在运行时类型精确匹配，且先行计数和校验确认长度相同时，才复用元素槽。严格配置与自定义配置在此格式化器中继续使用原有的完整前瞻校验。 非默认的不可变字符串数组仍以原字符串引用作为逐项读取的初值。
- **原始不可变数组读取。** 在 .NET 8 及以后，Next 可通过运行时的带校验读取器读取原始标量 `ImmutableArray<T>`。读取器分配前验证计数和完整载荷，将数据复制到新数组后推进游标。默认值和空数组保持不同。布尔元素、旧运行时和 API 不可用时沿用原路径。
- **二进制队列与堆区间。** 队列读取器可在验证完整区间后一次推进三个存储字，遇到截断头部则逐字读取。采用已验证堆存储的精确优先队列可一次验证固定 UTF-16 字符串与非托管值组成的整对数据的输出容量。写入前先捕获整对数据，并在每个枚举边界检查修改版本，包括最后一次。不支持的配置和布局使用公开枚举，输出区间不足时使用原有逐值写入。对元素数相同、比较器为默认值的字符串/Int32 优先队列，固定 UTF-16 长度配置的读取器可在清空目标前将原有字符串暂存到池化数组。每个键值对完整读取后立即入队，输入截断时，别名可观察到已经完成的前缀。
- **多维 JSON 数组形状。** 生成的读取器可在栈上保存固定秩的维度长度和下界缓冲区。校验完整形状和暂存元素数后，零下界数组可直接使用静态类型构造。非零下界仍将原长度和下界交给框架构造方法。
- **Next 具体集合格式化器。** 定宽且无回调的哈希集合可先校验完整二进制负载，再按线格式顺序同时读取条目和链接哈希桶。冻结集合可从同样经过完整校验的输入直接填充私有构建器，通过常规插入处理重复项。冻结集合写入可从不可变元素跨度批量处理兼容的元素。精确匹配的整数有序集合可遍历经验证的树写入 UTF-8 JSON，并在每个元素写入后检查版本。使用默认比较器的精确整数有序集合可从严格升序的暂存前缀构建树。输入错误时通过常规插入发布已完成的前缀，遇到乱序或重复项则按输入顺序恢复常规插入。派生集合、不支持的配置和无法绑定的存储布局沿用已有路径。
- **复用的哈希集合。** Next 二进制读取 `HashSet<T>`，以及持有精确 `HashSet<T>` 的 `ISet<T>` 或 `IReadOnlySet<T>` 时，会清空已有的、类型精确且使用默认比较器的集合，确保容量后通过现有的直接条目读取器填充其保留的条目和桶。自定义比较器和派生集合仍然替换，因为直接读取器不会移除在其他相等比较下会合并的元素。
- **一次遍历的链表。** Next 二进制读取 `LinkedList<T>`，且目标是类型精确的新建或已清空链表时，可在解码每个元素后立即用公开构造器创建节点，并通过经探测的节点字段链接。原始存储在读取任何元素前校验完整载荷。链表读完最后一个元素才发布表头、计数和版本，读取失败时与暂存填充一样保持为空。其他链表以及探测不可用时沿用暂存的 `FillLinkedList` 路径。
- **链表节点视图。** 直接追加及暂存后链接都要求实际闭合框架链表和节点的所有相关字段偏移与已验证的环形布局一致。直接追加还须核对编译后的节点视图，才可进行类型化写入。只有视图不匹配时，暂存填充仍可通过已验证的偏移链接。闭合布局无法验证时，先解码所有元素，再通过 `AddLast` 填充。
- **链表原位复用。** Next 二进制读取非空的复用 `LinkedList<T>` 时，按顺序把每个元素读入已有节点的值（已有对象和未变化的字符串保留身份），多出的元素追加节点，多余节点移除，与复用 `List<T>` 填充槽位的方式相同。读取失败时可见已完成的前缀。
- **包装集合原位复用。** Next 二进制读取包装精确 `List<T>` 的精确 `Collection<T>` 时跳过 `Clear`，让列表 span 像复用 `List<T>` 一样保留已有元素作为复用种子；派生集合仍通过自己的 `ClearItems` 清空。元素为字符串或对象的 `ReadOnlyCollectionBuilder<T>` 保留已有元素、清理多余槽位，并用索引器自赋值推进版本。元素为字符串或对象、直接包装与输入等长的精确数组的精确 `ReadOnlyCollection<T>`（`GetArrayBackedWrapperItems`，经探测的 `list` 字段）原位读取。包装精确 `Dictionary<K,V>` 的精确 `ReadOnlyDictionary<K,V>`（`GetReadOnlyDictionaryStorage`）把该字典作为复用目标交给字典读取，字典被保留时包装器也保持不变。探测不可用和其他形态仍按原方式分配。读取失败时，留下的部分状态与复用列表或字典读取相同。
- **原位填充队列。** Next 二进制读取元素为字符串或生成负载的 `Queue<T>` 时，可把精确框架队列中的旧元素线性化到后备数组前部，按传入元素数扩容或清理多余槽位，先把队列发布为空，再在旧元素上逐个原位读取（未变化的字符串和可复用对象保留身份），最后一次性发布头、尾、大小和新版本号。读取失败时队列为空。布局不受支持时使用 `Clear` 和 `Enqueue`。
- **原位填充栈。** Next 二进制读取复用的、元素为字符串或生成负载的 `Stack<T>` 时，可把精确框架栈的旧元素按栈底优先保留在后备数组中作为种子，按传入元素数扩容或清理多余槽位，先发布为空，再原位读取字符串或元素，最后一次性发布大小和版本号。读取失败时栈为空。新建栈保留直接读取；布局不受支持时使用 `Clear`。
- **类型化二进制有序集合建树。** 在支持编译动态代码的 x64 .NET 10 和 11 上，经验证的有序树构造器可为引用元素生成对实际框架节点构造器的类型化调用；字符串元素最多支持实测过的 4096 项。生成代码按引用读取元素前检查输入范围。每个类型的探测须匹配框架节点类型、树形和颜色。沿用既有比较器检查、暂存、节点拓扑及根、计数和版本发布。其他平台、无法绑定运行时接口或探测失败时沿用现有构造路径。
- **构造、池化与复用。** 构造函数选择、`[LuminPackPoolRent]`、对象/集合/字符串的 `ref` 复用，以及文档中描述的失败时发布规则都要保留。复用不是事务性的。
- **复用缓存所有权。** 共享池存储有界、无序，采用原子首槽和带起点提示的有界溢出扫描。只有槽位原子操作转移所有权，提示和诊断快照不转移所有权。保留既有 TLS 快缓存与池身份校验，在发布前重置对象，释放被拒绝的对象，并区分共享容量为零和禁用 TLS。对象池调整容量要求静默期，先发布替代存储，再释放多余对象，完成清理后汇总释放异常。本地清理在调用释放回调前解除所有权。
- **二进制字符串矩阵。** 完成所有维度及元素数量检查后，框架的默认 UTF-16 长度配置可以复用形状完全匹配、两个下界均为零的 `string[,]`。按行读取各位置，逐条检查边界与配置的字符串限额。内容相等的字符串保留原引用。旧矩阵的其他引用可以看到每个完成的位置，包括读取失败前已解码的前缀。其他配置、形状、数组秩或缺少相应辅助方法的运行时沿用原读取路径。
- **二进制对象矩阵位置复用。** 在 .NET 8 及更高版本上，除非元素声明设置 `ReuseRectangularArraySlots = false`，Next 会把已有二维数组的各位置传给元素的普通对象复用读取器。目标的运行时数组类型和两个维度长度必须完全匹配，两个下界必须为零。与一维数组和列表相同，共享同一元素对象的多个位置会看到最后读入该对象的记录。修改前先检查形状与元素数量。按行读取，失败时可能看到已解码的前缀。其他目标使用替换读取。
- **原始标量二维数组的二进制复用。** 在 64 位现代 .NET 上，元素符合原始标量契约且下界均为零的现有数组可以用于形状证明。移动游标前验证完整输入窗口、非空标记、两个维度和显式计数，并确保形状与同一个目标数组一致。沿用原有块拷贝。证明失败时从原游标进入既有校验读法，保留目标发布顺序和失败位置。
- **同布局的 Packed 存储。** 采用 `Packed` 存储的多维数组和其他连续负载，若既有布局帮助器证明无引用元素的步长等于线格式宽度，且实际字段的每个字节均处于线格式偏移，就可整块拷贝。证明结果按闭合布局描述符缓存。直拷只用于互不重叠的源和目标窗口。字段重排、填充、volatile、窗口重叠和未证明的布局沿用各自的传输规则。拷贝前先校验形状、元素数和输入长度。
- **便携 BitArray 存储。** 经验证的整数或字节后备存储可以直接写出，同时保留实际运行时公开 `CopyTo` 的填充位行为，不修改输入。便携二进制读取可以直接填充尚未发布、按整数边界取整的最终 `BitArray`，再进行原有的公开长度调整，成功后发布。空值和极端长度、保留多余容量时的写入回退、载荷检查、缺失 API 或未知布局回退均保持既有行为。现代目标的复用及两种 JSON 表示不变。 在现代目标上，分配数组或使用空的保留缓冲区时，从原有整数或字节后备视图复制按字取整的载荷。逻辑位数决定头部和复制长度，末字保留原始填充位。
- **不可变树集合的 JSON 写入。** 具体类型 `ImmutableList<T>`、`ImmutableSortedSet<T>`、`ImmutableSortedDictionary<TKey, TValue>`，以及通过 `IImmutableList<T>` 访问的框架列表，可以按枚举顺序将非空集合复制到独占的池化数组。写入器依次调用原有的编译期格式器，并在归还数组时清理其中的引用，发生异常时也会归还。引用的运行时缺少对应的复制重载时直接枚举。无法识别节点布局时，通过公开枚举填充数组。
- **不可变集合的原始记录。** 具体类型 `ImmutableList<T>` 可以将已验证的树直接复制到已确认容量的可写跨度。输出区间不足、无法识别节点布局或目标平台不支持所需的非对齐存储时，使用暂存写入。原始元素的 `ImmutableStack<T>` 可以在验证完整负载后从输入末尾向前构造节点，完成后再发布栈。
- **框架不可变队列写入。** 二进制和 JSON 可以遍历精确 `ImmutableQueue<T>` 经验证的前后栈，包括通过 `IImmutableQueue<T>` 引用访问的实例。已有反转缓存继续使用；未缓存的后栈通过池化缓冲遍历，归还时清理引用，不建立 BCL 的惰性缓存。空后栈和单节点后栈不需要租借缓冲。元素顺序、formatter 调用、格式和失败行为保持不变。不支持的布局、缺失辅助 API 及任意接口实现保留原遍历。
- **标量不可变队列的二进制遍历。** 前栈和已按输出顺序排列的后栈通过框架的 `Peek` 和 `Pop` 遍历。每个元素仍执行原有缓冲区检查。需要反转的后栈沿用已有的缓冲区租约。
- **框架不可变队列构建。** 在可编译动态代码的 .NET 10 及以后，Next 二进制读取器可将解码元素逆序链接到前栈，再以空后栈构造精确的 `ImmutableQueue<T>`。每个封闭元素类型验证一次绑定。旧版运行时引用和失败的绑定沿用已有的框架工厂。暂存元素保持经校验的顺序，在完整读取后发布。
- **集合分发。** 集合的遍历和构造应按存储布局、格式器能力与回调行为选择。禁止根据基准使用的键值类型组合选择专用算法。Next 对枚举保证键非空的字符串键字典写入 JSON 对象属性。其他键类型及未识别的字典实现保留键值对数组形式。字符串键读取器接受两种格式，调用既有的值格式器，保留各字典的重复键处理及复用行为。保留旧生成程序集所依赖的运行时签名。在受支持的现代目标上，二进制读取精确的字典类型时，若使用默认比较器、定长键的框架相等比较没有用户回调，且值格式器支持安全原位读取，则可直接复用已有槽位。匹配键保留目标顺序；失败时可能看到已读前缀。自定义键行为、自定义比较器或无法安全原位读取的值沿用暂存重建。目标字典为空、键无用户回调且键值均为原始数据时，可使用经过范围检查的批量重建。
- **共享 unmanaged Root。** 同一泛型定义（或同一秩的数组）的闭合格式器 Root，若方法体只在 unmanaged 类型实参上不同，可以只生成一个约束为 `unmanaged` 的泛型 Root。每个闭合 Root 保留名称、签名和 `Preserve` 特性，改为激进内联的转发方法；泛型 Root 保留原有内联特性。只有当代入各成员的实参能还原该成员的方法体，且泛型方法体中每个表达式绑定到的定义、类型和常量都与成员自身方法体一致、并且没有错误时，才会共享。`Nullable<T>` 以及任一证明失败的成员保留闭合 Root。值类型实例化在 CoreCLR、NativeAOT 和 IL2CPP 默认设置下仍分别编译；IL2CPP 的完全泛型共享（"Faster (smaller) builds" 选项）可能通过共享代码执行。
- **新建二进制并发字典。** 在布局已验证的 .NET 10、11 x64 上，新建的 `ConcurrentDictionary<TKey,TValue>` 可以将解码后的键值对逐项链接到预分配且尚未发布的表，并更新锁分区计数。流式构建器采用当前表的比较器，将分区扩容延迟到公开插入时。桶内已有节点超过 100 个时，使用已计算的哈希调用框架插入，保留哈希碰撞防护。重复键保留首个值。布局不受支持时，对未发布的字典使用 `TryAdd`。暂存构建与已有目标复用沿用原插入路径。
- **二进制 Lookup 构建。** Next 校验分组数量后创建尚未发布的 `ILookup<TKey,TElement>` 字典，初始容量请求最多为 64 组。空分组记录仍然跳过。字典保持原有插入顺序和重复键校验，读取完全部分组后才发布 Lookup。
- **复用的并发队列。** 当 Core 提供 `DrainConcurrentQueue` 时，Next 的二进制和 JSON 读取用框架出队操作清空任意元素的复用 `ConcurrentQueue<T>`，补填沿用保留的尾段，不再重新分配整条增长链。已有快照保留其捕获的段，每次移除都保持框架的并发保证。没有该辅助方法时，原始标量沿用下面的定长 `TryClearConcurrentQueue` 重置，其他元素使用 `Clear`。
- **并发字典原位复用。** 当 Core 提供 `ConcurrentDictionaryRefill` 时，Next 二进制把非空记录读入已有的 `ConcurrentDictionary<K,V>`。数量相同时（字符串键最多 64 对，更大的字符串键字典很少与外来记录的顺序一致），每个键值对先与字典自身的枚举顺序比对：候选字符串键作为键读取的复用对象，候选值作为值读取的复用对象，只有变化的值才通过索引器写回。首次不匹配或数量不同时，对象值把已匹配的键值对和之后的所有键值对暂存到池化数组，并用 `TryGetValue` 查找已有值使其仍能原位读取，然后清空字典并按记录顺序用 `TryAdd` 重新填充；字符串和值类型的值则立即清空字典，加回已匹配的键值对，其余键值对读到即 `TryAdd`。重复的键与新建读取一样保留第一个值。有序匹配使用公开的线程安全操作。其他引用类型的键按新建方式读取。读取失败时保留已更新的键值对。JSON 和新建读取保持原路径。
- **并发字典暂存发布。** 精确字符串键字典的暂存记录读完且至少有 64 对时，经验证的 x64 CoreCLR 绑定可使用当前默认或序数比较器预置并填充未发布的表。持有原有全部分条锁后确认原表仍有效、调整预算，再沿用同一锁数组发布新表。读取方可以保留已捕获的快照，对旧表的公开修改沿用框架重试。替换与并发清空一样清除顺序早于发布的修改。布局不受支持、自定义比较器、表或比较器发生变化以及空键继续使用公开清空和回填。
- **并发字典按键复用。** 在 .NET 9 及以后，Next 可在内置固定 UTF-16 长度配置下复用键为字符串、值为生成对象的字典，要求采用默认或序数比较器、超过 64 对且数量相等。读取器校验完整的键，再将字符交给框架备用查找。紧凑 Latin-1 键使用有界栈缓冲或归还的池化字符缓冲。值可原位读取时，原键和对象保留身份。键值对暂存和单次读取的引用身份集合记录输入顺序并发现已存在的重复键。所有键唯一匹配时保留原表，只通过索引器写回变更的值引用。缺键或重复键在完整解码后走暂存替换，每个键保留首个解码值。失败时保留已经完成的值更新并归还暂存。
- **预填的并发栈复用。** Next 二进制把对象元素读入复用的 `ConcurrentStack<T>`（记录非空）时，用 Core 的 `SeedConcurrentStack` 把已有元素按自底向上的顺序复制到租用的读取缓冲（租用快照，与记录自底部对齐），清空栈，在预填元素上逐个读取，再用原有的批量压入放回。读取失败时栈与原来一样为空。字符串元素保持原读取方式，因为预填耗费的时间超过节省的部分。
- **二进制原始并发队列复用。** 校验完整的原始载荷后，Next 可对精确类型且元素为受支持标量的 `ConcurrentQueue<T>` 调用 `TryClearConcurrentQueue`，适用元素数量为 33 至 4,096。在经探测的 .NET 10、11 x64 CoreCLR 上，先持有框架锁并冻结旧尾段，再发布新框架段的头和尾。段容量取大于或等于元素数量的最小二次幂。已有快照保留原先捕获的段。元素仍逐项校验、按序入队。其他数量、布局不受支持、缺少运行时支持及其他元素 owner 时，使用框架的 `Clear`。
- **并发队列批量清空与回填。** 在 .NET 10 和 11 CoreCLR 上，Core 的 `DrainConcurrentQueue` 对每个段的已发布元素只做一次段头比较交换来出队，并按框架每次出队的方式释放槽位；为观察而保留的段保留其槽位，仍在入队中的元素与段切换走 `TryDequeue`。Next 对原始标量 `ConcurrentQueue<T>` 的二进制复用读取先把完整载荷解码到池化存储，再调用 `RefillConcurrentQueue`：清空队列后，以一次尾部比较交换认领尾段的空闲槽位，再逐项发布序列号；段已满或已冻结时改用 `Enqueue`，照旧扩容。含引用的元素、其他运行时以及按类型探测失败时使用框架操作。回填装得下尾段时不分配。由于先解码后清空，读取失败时队列保持不变。
- **小型并发队列构建。** 在布局探测通过的 .NET 10 和 11 CoreCLR 上，新建且含 1–32 个无引用元素的并发队列可从默认段批量领取首批槽位。其他数量、含引用的元素以及探测失败时沿用框架集合构造器。
- **并发集合遍历。** Stack 写入可遍历在创建枚举时捕获、经布局验证的不可变节点链。Dictionary 写入可使用值类型遍历，保留延迟桶捕获、acquire 读取、整对值复制以及当前运行时在 yield 前后的链接读取时机；缺失元数据或 helper API 时保留公共枚举。Bag 写入保留全局/局部冻结协议及公共快照顺序：原始非托管二进制载荷可直接复制到预留输出，其他二进制和 JSON 路径租借完整快照并在格式化器调用前释放锁。未知布局回退 `ToArray`，保留原生 `ArrayPool.Shared` 的所有权及回收策略。
- **并发集合标量记录内核。** 对字符串键和直接写入的非托管值，Next 二进制写入器可一次证明固定 UTF-16 键的容量上界与值均能写入，再使用原有标量存储操作并一次推进游标。对同一固定 UTF-16 长度档位的字符串键和值，可在已证明的输出窗口内逐对推进局部字节游标。走原有逐对增长路径前先提交游标，再从新窗口继续写入。其他档位沿用原来的计数写入。Next 的 JSON 并发序列和字典可为匹配的框架标量调用 Runtime 的完整整数元素或键值对写入操作。这些内核保留遍历、线格式、回调和验证，缺失 Runtime 操作时沿用原路径。
- **新建二进制并发包。** 在布局已验证的 .NET 10、11 x64 上，新建的精确 `ConcurrentBag<T>` 暂存 64 至 4096 项时，可在第一次常规 `Add` 后预设本地工作窃取队列的数组容量。操作持有既有的全局和局部冻结锁，并确认仅有一个初始队列、当前所有者线程、原始容量和首项索引。保留目标发布、输入顺序、计数及后续 `Add`。回调更换对象或队列不符合探测条件时使用普通插入。
- **框架类型并发栈 JSON 读取。** 无用户回调的框架标量、字符串及其 Nullable 可暂存元素并通过 `PushRange` 一次构建最终节点链。完成顺序、目标身份和原来的失败前缀不变。读取进行中，其他观察者看到已清空的复用目标，直到成功或失败边界发布暂存元素。自定义元素保留逐项回调及原构造路径；缺失 helper API 时保留原读取器。
- **类型化并发栈区间压入。** 在支持编译动态代码的 x64 .NET 10 和 11 上，二进制与 JSON 并发栈的暂存发布可通过生成的框架区间压入副本完成。它按相同顺序调用实际节点构造器，链接相同的分离节点链，并以相同的比较交换和私有竞争例程发布。每个类型的探测须与 `PushRange` 比对节点类型和链长。暂存、`Clear`、受检解码、单次原子可见、新节点和失败前缀均不变。其他平台、无法绑定或探测失败时调用 `PushRange`。
- **原始并发栈根写入。** Next 对原始标量 `ConcurrentStack<T>` 的二进制根写入在 Core 提供 `WriteConcurrentStack` 时调用它：只读取一次栈顶，把捕获的链按栈顶优先写入写入器已为非检查记录证明的空间，原位反转后写入计数，不再租用快照。链长超出该空间、32 位进程中宽于四字节的元素以及不受支持的布局，仍以原有预留写入反转后的快照。记录字节与单次捕获的快照语义不变；内联成员写入保留快照。
- **Frozen 构建存储。** Frozen 字典和集合读取可独占租用默认比较器的可变 Dictionary 或 HashSet，保留插入、哈希、回调、异常和成功后发布顺序。公共 BCL 冻结工厂负责选择结果实现。`finally` 在保留前清除输入引用。每个封闭可变类型全局最多保留 4 个对象，每个容量不超过 `max(128, 完成元素数 × 4)`。容量上限通常为 4096。`FrozenDictionary<TKey, TValue>` 构建器完成 4050 至 4096 个元素，或原始标量的二进制 `FrozenSet<T>` 请求同样数量的元素时，可以保留框架分配的最多 4861 个桶。较小请求可从同一缓存租用此表，归还时应用普通容量上限。冷启动、超容量或租用耗尽时正常分配。Frozen 标量集合写入可复用既有批量写入器。原始标量字典数组可按平台固定访问规则交错写入一次预留的输出窗口。其他元素契约和缺少 helper API 时保留原路径。BCL 工厂内部仍有暂存分配。
- **原始标量冻结集合的二进制复用。** 在受支持的 .NET 10 和 11 运行时上，`ReadRawSetReuse` 可按原始元素类型和线程弱引用地记录一个框架冻结结果。仅当调用传入非空复用目标，且完整校验后的输入与默认比较器结果的元素字节按顺序完全一致时，才记录该结果。后续读取的完整输入再次匹配时，可以保留该不可变实例。此规则保留框架的枚举顺序，包括碰撞导致的重排。新建读取、输入不同、未经验证的实例和缺少辅助方法的路径沿用普通冻结。
- **不可变 Builder 复用。** 现有不可变字典、有序字典、哈希/有序集合及旧版短列表的 Builder 路径可以租用独占的空框架 Builder，保持插入、回调和失败发布顺序。租用在回调前移出缓存槽；`finally` 在有界保留之前清除输入引用并恢复默认比较器。二进制单元素字典可以直接调用公开的空字典 `Add`。最终节点直构、候选缓存、Span 工厂和缺失 API 回退保持不变。这消除了预热后的 Builder 外壳分配，BCL 冲突节点及非规范有序输入的分配仍存在。原生 `ArrayPool.Shared` 保持正常裁剪机制。
- **二进制读取中的不可变字典字符串键。** 对于使用默认键比较器且元素数与输入相同的 `ImmutableDictionary<string, int>`，内置字符串配置可以按枚举顺序将旧字典的键传给受检查的字符串读取器。内容相等的键可以保留原来的字符串引用。读取器暂存所有键值对，整条记录读取成功后才发布构造完成的字典。
- **不可变字典构造函数。** 在 .NET 10 及以上且编译动态代码时，哈希互不相同的不可变字典构建通过节点类型的私有无参构造函数分配哈希树节点，并用字典的私有树构造函数与空字典的比较器包装链接好的树，取代未初始化对象请求和一次公共单元素插入。绑定按封闭类型检查一次，并经现有 `<int, int>` 公共 API 探测；哈希冲突、NativeAOT、Mono、IL2CPP 和绑定失败时保留原有构建。
- **规范区域性名称。** 在已验证的 .NET 10、11 CoreCLR 上，二进制与 JSON 连续读取同一规范区域性名称时，可以复用框架当前的实例。每个线程最多保留一个不超过 85 个字符的名称和一个只读区域性实例。仅接纳已在框架名称缓存中确认的 ASCII 名称。通过缓存的弱引用识别 `CultureInfo.ClearCachedData()`，未命中时调用 `CultureInfo.GetCultureInfo`。
- **二进制 `Version` 复用。** Next 读入并校验完整记录后，四个分量全部相等时可以保留传入的不可变 `Version` 实例。分量不同时使用原有框架构造函数，null 标记清空目标。二进制根和成员读取均保留相等记录的引用身份。
- **有序 JSON 集合。** 在 .NET 10 及更高版本，JSON 完整读取具体的 `ImmutableSortedSet<T>` 后，可以将至少两个严格升序的元素直接连接成平衡的冻结树。枚举及 CoreLib 中实现自身比较接口的非泛型值类型使用默认排序。字符串必须为非 null 引用，且当前区域性为标准类型。用户自定义比较、重复、乱序或缺少树节点绑定时使用框架 Builder。
- **框架元素不可变哈希集合。** `ImmutableHashSet<T>` 和 `IImmutableSet<T>` 的二进制及 JSON 读取，在生成器确认元素为实际核心库中不含用户回调的标量或字符串、Runtime 验证布局后，可以直接构造最终哈希节点及碰撞节点。保留相等元素的首次表示，以及 BCL 顺序插入形成的碰撞列表拓扑。具体类型的二进制候选缓存、复用及失败发布保持不变。用户自定义元素的具体类型二进制入口按下列规则构建，其他入口使用原有 builder。临时租赁必须归还，引用暂存必须清空。
- **不可变哈希集合构造器。** 在可编译动态代码的 .NET 10 及以后，通过验证的私有构造器使用空集合的默认比较器封装已链接的哈希树。引用类型哈希码互异的构建及框架引用类型的双元素构建可跳过公开的单元素插入。用户哈希回调与碰撞桶构建保留既有行为。值类型和绑定不可用时沿用单元素集合路径。
- **按对象身份比较的不可变哈希集合。** 在 .NET 10 x64 上，具体类型 `ImmutableHashSet<T>` 的二进制读取也可在完成受校验的元素暂存后使用已验证布局的直接构建路径。生成器选择由消费程序集声明、直接继承 `System.Object`、没有自己的相等或哈希实现的密封非泛型类。Runtime 重新检查链接后的类型，并要求使用框架的默认比较器。该路径按输入顺序获取对象身份哈希，并保留首次出现的元素和碰撞列表行为。此专用路径不可用时，具体类型的二进制入口按下列规则构建。JSON 和 `IImmutableSet<T>` 沿用原有选择条件。
- **具体类型不可变集合的二进制读取。** 完成受校验的元素暂存后，`ImmutableSortedSet<T>` 可用旧版排序树构造器链接严格升序的元素。其他输入使用旧版范围构造，遵循其比较顺序和等价元素选择。`ImmutableHashSet<T>` 可用旧版哈希树构造器链接不同的哈希值。出现碰撞或布局不可用时，框架 builder 使用已校验的暂存元素。用户哈希方法可能在探测和回退阶段各执行一次。对象身份路径和已有的框架元素专用路径优先。读取在构造成功后发布，并清空租用的暂存数组。Core 缺少辅助方法时保留原有的生成 builder 路径。
- **Next 不可变树遍历。** 对于已确认的 sealed 框架 set 或 dictionary，可以写入已知长度并按原枚举顺序捕获元素，再用既有二进制及 JSON 元素操作写出。符合条件的二进制 set 可以直接写入完整预留的输出区。自定义接口实现保持计数枚举。JSON 读取有序集合时，无回调的框架元素可以在暂存严格递增后直接构造树。字符串路径要求框架的确切 culture 类型和已知固定配置，自定义 culture 或配置沿用流式 builder。
- **不可变有序字典暂存字符串键值对的二进制写入。** 内置 UTF-16 长度配置下，Next 可将既有独占租赁中完整的字符串键值对交给有界前缀写入器。每次前进前验证原始记录上界、实际窗口以及扩容阈值。第一个不满足边界的键值对沿用原键和值写入器，随后再尝试写入下一段前缀。保留树遍历捕获、计数、键值对顺序、扩容回调和租赁清理。其他配置以及没有前缀写入 API 的 Core 仍使用原循环。
- **普通对象值有序字典的二进制键写入。** 对 `SortedDictionary` 和 `ImmutableSortedDictionary` 已暂存的键值对，当完整原始记录上界和扩容阈值均满足时，Next 可用既有有界 UTF-16 长度键写入器处理字符串键。窗口不足或配置不同时沿用原键写入器。键写完后读取对象引用，随后执行原值检查和格式化器调用。保留树遍历捕获、集合记录边界、回调、字段读取时机和租赁清理。
- **Next 包装集合 JSON 整数批写。** 已验证的框架存储可使用有边界的 UTF-8 或 UTF-16 输出窗口写入固定配置下的 `int` 和 `long`。UTF-16 格式化采用当前框架 culture。派生 culture 和自定义配置沿用逐项枚举。输出窗口边界保留枚举器的元素捕获顺序和修改检查。
- **带缓冲区的 UTF-16 整数有序集合写入。** 对类型精确的 `SortedSet<int>` 或 `SortedSet<long>`，`TryWriteIntegerSortedSetJson` 可在已知 UTF-16 配置、框架常规区域性且自有缓冲区能容纳每个剩余元素的现有分隔符和数字写入时，沿用既有的中序树遍历。对使用默认比较器且在不变区域性下写入的非负 `Int32` 键，可以用最大键的十进制位数估算已写前缀的上界，再用最小的两个键收紧该上界，并为最后一个元素预留完整的写入空间。派生区域性、外部输出和空间不足均保留框架枚举，包括原有增长回调和集合修改异常。UTF-8 路径沿用原有规则。
- **Next 字典混合条目写入。** 二进制字典中由一个 UTF-16 长度字符串和一个原生值构成的直接写入条目，可以检查二者的输出上界后一次推进。接口指向确切框架字典时，其具体枚举器也可使用同一上界。密集遍历保留修改检查。窗口不足、其他配置或任意接口实现沿用逐成员写入。
- **Next 确切列表和数组存储。** 具体不可变列表及通过 `IImmutableList<T>` 识别的确切框架类型可以使用现有按序树传输。JSON 读取可以暂存输入并通过框架的 span 工厂一次构造。二进制字符串序列接口可以对确切列表或数组共用连续字符串批写。其他接口实现沿用计数操作。
- **二进制复用以数组为后备的只读包装集合。** 在现代 CoreCLR 上，如果受支持的原始标量 `ReadOnlyCollection<T>` 类型精确匹配、直接包装精确的 `T[]` 且长度与输入相等并非零，Next 可填充原有数组。针对封闭类型的探测会验证框架后备字段。修改前校验完整集合载荷，并要求目标与保留的输入区间无重叠。集合读取后，原包装集合和后备数组的其他引用可看到新值，即使外围记录的后续成员读取失败。布局不受支持、存储重叠、其他目标形状或缺少 Core API 时沿用替换读取。
- **二进制读取复用只读切片中的字符串。** 在现代 .NET 上，使用内置 UTF-16 长度配置读取 `ReadOnlyMemory<string>` 或 `ReadOnlySequence<string>` 时，可以从长度相同的原数组切片复用内容匹配的字符串。首项经校验且与原字符串匹配时，其余位置才使用原字符串作为复用候选。读取器在所有记录解码完成后发布具有独立后备数组的新结果。自定义内存管理器、多段或非数组序列以及其他配置沿用新建字符串的路径。首项和剩余记录均遵守生成的外围输入限额。
- **只读字符串字典的二进制写入。** 既有运行时探测确认精确类型的 `ReadOnlyDictionary<string, string>` 由非空且类型精确的 `Dictionary<string, string>` 支持时，Next 可使用框架结构体枚举器。内置 UTF-16 长度配置可为捕获的键和值一次预留有界空间，并调用原字符串记录写入内核。保留集合长度回填和框架版本检查，其他配置或空间不足时逐成员写入。不支持的后备存储和空输入沿用框架包装器枚举。
- **对象值只读字典的二进制写入。** 精确类型的字符串键包装器使用普通生成对象契约时，Next 可沿用已验证的后备存储和框架结构体枚举。内置 UTF-16 长度配置在键记录原始容量上界和既有扩容阈值均满足时，可一次预留键的空间。其他配置或窗口不足时沿用逐键写入和缓冲区检查。键写完后将捕获的对象传给原格式化器，保留字段读取时机、回调、版本校验和集合长度回填。
- **直接非托管值只读字典的二进制写入。** 内置 UTF-16 长度配置下，既有运行时探测确认精确类型的字符串键 `ReadOnlyDictionary` 由非空且类型精确的 `Dictionary` 支持时，Next 可使用框架结构体枚举器。值须适用既有的有界混合记录写入内核。当前窗口满足完整原始记录上界和扩容阈值时，该内核写入捕获的键值对。窗口不足时沿用逐成员写入和缓冲区检查。保留集合长度回填和框架版本检查。其他配置、空输入和不支持的后备布局沿用原包装器路径。
- **字符串键和普通对象值有序列表的二进制写入。** 在现代 .NET 上，Next 可在运行时探测通过的并行数组路径中写入有界 UTF-16 长度键记录。内置配置和当前窗口必须允许原始键的完整上界处于扩容阈值内。其他情况沿用逐成员键写入。键写入后读取值槽，保留原有值检查、格式化器调用和集合计数回填。布局不受支持时沿用公开遍历路径。
- **按顺序匹配键的二进制只读字典复用。** 在经探测验证的 64 位 CoreCLR 布局上，Next 对采用默认比较器、后备字典类型精确且条目连续的 `ReadOnlyDictionary<string, int>` 和 `ReadOnlyDictionary<string, string>`，可在内置 UTF-16 长度配置下更新原有值。输入须包含 1 至 4096 个键，且与现有键按顺序匹配。后备条目存储区间须与保留的输入区间无重叠。无回调的私有缓存每种值类型最多保留四个暂存数组，并在保留前清除引用。读取器验证完整字典记录及原有条目存储状态后才发布值，旧引用可见成功更新。键不匹配、配置或布局不受支持时，若 Core 提供 `GetReadOnlyDictionaryStorage`，则原位读取精确后备字典（见包装集合原位复用），否则沿用替换路径；生成读取器应用外层输入限额时仍沿用替换路径。
- **标量有序列表的二进制键复用。** 在经探测验证的布局上，Next 可从类型精确、使用默认比较器的 `SortedList<string, int>` 和 `SortedList<string, long>` 复用匹配字符串。此路径使用框架的常规区域性和内置字符串配置，要求输入和现有列表的条目数相同且在 1 至 4096 之间。读取器先暂存旧键，再按原顺序清空列表、执行带校验的键值读取并有序追加或调用 Add。每个完整键值对立即可见，集合版本和失败行为保持原样。缓存最多保留四个已清除引用的数组。应用外围输入限额或形状不受支持时沿用原读取器。
- **JSON 新建标量有序列表。** `SortedList` 的键为字符串或 Int32，值为字符串、Int32 或 Int64 时，Next 可将完整的有序键值对直接追加到新列表。内置默认配置和 UTF-8、UTF-16 长度配置使用已验证的运行时布局及常规区域性下的框架默认比较器。布局不可用或比较顺序不允许追加时，以 `Add` 插入该键值对。后续读取失败时已完成的条目可见。已有目标按原方式清空和插入。
- **标量列表的分配型二进制写入。** 对于符合条件的框架 `List<T>` 根值，读取一次元素跨度即可计算原生记录大小，并直接向最终字节数组写入计数和负载。null 列表仍写入原有的 null 集合计数。复用输出沿用普通列表格式化器。
- **标量接口的分配型二进制写入。** 当 `IEnumerable<T>`、`ICollection<T>`、`IReadOnlyCollection<T>` 或 `IReadOnlyList<T>` 持有元素为受支持框架标量的精确 `List<T>` 时，Next 可获取一次元素跨度，并用其确定最终字节数组的大小及填充范围。写入保留原计数和原始数据块格式。其他输入沿用池化写入器及其枚举规则。读取状态和复用输出的操作沿用既有路径选择。
- **稠密原始标量 `HashSet` 的二进制写入。** 在支持 SSE 的 x64 上，若运行时探测确认框架条目步长为 12 字节且值位于偏移 8，共用写入器可以按枚举顺序一次写入四个 32 位值。写入前预留完整记录，每次向量读取都位于捕获的稠密条目区间内。存储稀疏或重叠、探测不可用、其他值宽度或平台时沿用现有标量写入。有界尾部使用普通标量写入器。
- **受检的 JSON 哈希集合遍历。** 布局探测通过后，Next 可以遍历类型精确的框架 `HashSet<T>` 的活动条目。每一步都检查枚举版本，包括遍历结束时。读取当前条目数，跳过空槽，并在调用原 JSON formatter 之前捕获各值。派生类型和探测不可用时沿用框架枚举。
- **优先队列的二进制紧凑写入。** 在现代 64 位运行时上，若实际数组字段地址证明支持的整数字段顺序、相邻关系及步长与 wire 键值对一致，则可以一次复制类型精确的框架 `PriorityQueue<TElement, TPriority>` 的活动堆。`TryAllocatePriorityQueueRecord` 直接将计数和堆数据写入最终数组。复用输出的写入保留原有空间、重叠、记录头、版本和游标检查。包含填充、字段重排、布局无法验证或缺少 helper 时沿用原写入器。
- **UTF-16 整数队列写入。** 固定 UTF-16 配置可以沿用 UTF-8 路径的两段出队顺序跨度。写入器校验每个窗口，输出回调后继续前检查队列版本。
- **整数链表的 JSON 写入。** 对已验证布局的框架 `LinkedList<int>` 或 `LinkedList<long>`，固定配置可将节点元素读入临时跨度，再连续写入整数。只暂存按各自标量上界计算仍完整容纳在当前窗口中的元素。窗口不足时按原标量路径写入已获取的元素，并在读取下一节点前检查链表版本。
- **Next 不可变线性集合。** 接口指向确切框架队列时，可以沿用双栈遍历，无需创建惰性反转缓存。JSON 队列读取可以租用元素缓冲区，再通过框架 span 工厂一次构造。栈接口可以直接枚举确切框架栈，并从暂存的 JSON 元素或经过完整校验的二进制原生数据构造最终节点。自定义接口实现保持自己的枚举顺序。
- **池化类型的全新读取。** 普通（`Object` 模式）二进制读取中，带 `[LuminPackPoolRent]` 的引用类型在目标为 null 时先租用实例（根对象和内联成员都一样），然后像读入已有实例一样读取。版本容忍和引用跟踪模式保留各自的暂存成员和延迟提交。
- **回调**在既定的时机和顺序执行。
- **JIT 分层提示。** 现代 .NET 上，Core 的选定集合、字符串及向量内核从优化代码开始执行。Next 保留内联提示，并为 Unity 之外的部分元素遍历根请求首次优化。目标支持首次优化提示时，符合条件的 Union 元素集合写根从优化代码开始执行。二进制字符串及符合条件的位置记录循环可升层并使用动态 PGO，包括遍历带标记的可空值及嵌套集合的循环。字典条目的另一部分须为原生值或同样符合分层条件。原生存储、直接键值对拷贝、定宽对象预留、读取及 JSON 沿用此前的提示选择。netstandard2.1 省略首次优化提示，Mono、IL2CPP 和 NativeAOT 会忽略它。
- **集合元素的可空原生存储。** 逐元素集合可通过经校验的槽位或步长读写，传输经证明的可空原生步幅。适用于 `Native` 和只有一个已验证原生模型的 `Tagged` 标量。保留集合原有的帧、遍历、复用和枚举回退。在发布已复制的元素前，检查完整访问范围及布尔存储。
- **二进制根入口。** 经分析确认 formatter 图无需操作状态的闭合根，可以直接读取而无需租借上下文。未知或自定义 formatter、版本表和引用追踪仍租借状态。在现代 .NET 上，普通对象 span 根符合拆分资格，且根或内联记录包含至少八个建模成员，或读取涉及集合或 Union 操作时，可以外移带校验的读取方法。入口包装先检查输入上限，再消费完整的空对象标记，并保留现有目标。非空对象和空 span 进入外移的校验读取方法。拆分只适用于无回调、递归、版本表、引用跟踪、继承集合体、有界记录、拒绝或显式输入限制的普通对象。紧凑根直接执行带校验的读取。
- **定宽二进制根写入。** 符合条件的原生值、带标记的原生可空值、定宽密封对象、Version 及原始数组可调用既有的按地址存储，直接填充最终数组。定宽对象数组可以按已校验的上界分配，存在空元素时裁剪到实际长度。已有容量的空 writer 可在固定窗口和既定扩容阈值内使用同一存储方法，再发布长度。追加和空间不足仍走原写入器。 对于 BigInteger，先校验四字节头和完整有符号小端补码载荷的总宽度，再写入最终数组或空的保留缓冲区。
- **原生可空根载荷。** 直接写入的根按值是否存在确定精确宽度，并通过 `Nullable.GetValueRefOrDefaultRef` 读取存在的载荷。先存储载荷再存储存在标记，允许输入位于同一保留窗口内。空值只写标记。
- **有界保留缓冲区根。** 紧凑的可移植布局可把现有的独立紧凑字段写入已证明足够的保留窗口。集合记录布局保持原有规则。仅含字段的普通密封记录包含原生可空字段时，可以预留编码宽度上界，再发布游标实际移动的距离。追加或空间不足时使用普通写入器。
- **二进制根扩容与文本。** `ReserveRecord` 的窗口检查失败时，只调用一次不内联的 `GrowRecord`，按引用传入写入器和游标。辅助方法提交游标，拒绝负的位置和宽度，并检查绝对结束位置是否溢出。记录起点越过扩容阈值时，所有者先合并阈值扩容和容量预留，再更换存储。计算、租用或固定数组失败时，已提交游标仍指向原窗口。扩容成功后刷新窗口、游标、记录边界和扩容阈值。UTF-16 长度字符串的短窗辅助方法按值接收所有者、已提交位置和窗口信息。它先尝试写入当前窗口，空间不足时按原始宽度预留，并在非 null 记录的实际结束位置检查扩容阈值。辅助方法返回写入后的窗口、游标和边界，无需扩容时沿用原窗口。如果扩容成功后又有步骤失败，先应用扩容后的窗口，并沿用已提交的游标位置，再重新抛出异常。在内置 UTF-16 长度配置中，调用方持有游标的字符串记录检查失败时，只调用一次不内联的边界方法，按引用传入写入器和游标。该方法提交游标并应用同一短窗辅助方法的结果，再返回更新后的游标。保留缓冲区内的字符串、URI 和精确匹配的 CultureInfo 根可以在确认窗口后使用内置 UTF-16 长度写入器。短 Latin-1 存储可内联，中等和较长记录沿用外移的编码方法。 框架 `Lazy<string>` 的工厂已完成时，可在空窗口中写入对象标记和字符串。尚未完成的工厂、不同配置和追加写入均沿用原写入器。
- **闭合泛型 Union 分派。** 闭合的隐式泛型 Union formatter 精确匹配已知密封 case 的运行时类型，直接调用已有的编译写入槽。类和接口 Union 的二进制读取器对已校验的名称哈希使用 switch。符合条件的本地闭合读取器只在 switch 中列出该构造类型可到达的 case。未知 case、注册回退和受输入限制的投影沿用原分派规则，case 标签及负载保持既有表示。
- **二进制复合成员的内联边界。** 各 switch 分支保留既有负载入口或展开的 case 读取。位置记录可为超出内联预算的复合成员调用独立的非内联读写方法。紧凑的嵌套记录沿用内联路径。边界保留原有配置、状态、校验、复用及发布顺序。
- **带标记的可空值写入**。独立有效负载采用原生存储的可空值可以一次预留标记和值。只含定宽及符合条件的可空成员的顺序记录，可以一次证明整条记录可写。剩余空间较短时，按同一批已捕获的可空值计算精确宽度再预留。保留原有空值标记、存储字节、32 位访问规则与读取校验。
- **演进版本表**。现代 .NET 上，每个生成的接收架构最多保留两个已验证且不可变的第二版表，每个最多 4096 字节。只有字段数一致，且当前读取边界内的表字节完全相等才会命中。命中后复用映射与指纹，照常向本次操作登记该表。映射读取仍逐个检查变长字段的边界，并在失败时恢复外层边界。
- **短 Latin-1 字符串序列**。在支持硬件加速的 64 位目标上，使用 UTF-16 长度格式的连续二进制字符串读取可以共用一个已捕获的读取末端来解码短 Latin-1 序列。每条记录仍检查边界，其他位置的值发生变化时也保留相等的现有字符串。 对于 17–32 个字符的记录，AVX2 先比较前 16 个字符，相等时才加载尾块。两次比较均相等时才复用字符串。
- **保留缓冲区的写入入口与重置**。保留缓冲区的空写入器可以直接从当前托管窗口开始。独立重置只在操作已填充相应表时清理引用或版本状态。缓冲区容量及读写上下文的独立所有权保持不变。
- **Packed 优先队列读取**。已检查范围的 packed 堆读取器可以用 AVX2 一次校验并复制八个有符号 32 位优先级。遇到需要细查的组时恢复四元素或标量校验，违反堆序的后缀仍通过普通入队处理。
- **中型 UTF-16 记录写入**。在支持 256 位向量硬件加速的 64 位目标上，连续的二进制 UTF-16 长度记录在验证每条记录的完整原始宽度上界后，可使用既有的 17 至 32 和 33 至 64 字符内核。两种内核都保留紧凑 Latin-1 和原始 UTF-16 布局。短记录沿用普通写入，长度更大的记录沿用通用编码器，宽度上界超出当前窗口时走既有回退路径。
- **二进制集合接口的暂存**。确认属于框架自身实现的包装类型可以将已验证的后备存储交给现有的连续写入器。框架分组可以为 `ICollection<T>.CopyTo` 租借暂存数组，并按照枚举顺序写入已验证的元素范围。未知实现沿用公共枚举及其发布语义。
- **有界集合暂存**。已知可写前缀的同步集合操作可以为每个闭合元素类型保留一个线程独占暂存槽。租借时从槽中取走数组，归还时清除所有可能写入的引用。保留上限为 4096 个元素和 64 KiB，较大请求沿用共享池。保留外层 `finally` 清理以及集合遍历和构造规则。
- **分层编译的二进制集合读入。** 遍历元素或重建接口目标集合的生成读根可以独立编译，为循环内部保留内联预算。独立读根保留分层编译。紧凑的原始存储读入沿用既有内联策略。
- **外移的集合回退。** 集合根可以保留主循环，把备用遍历或重新填充移到独立方法。在现代 .NET 上，具体数组或列表的紧凑位置记录元素只含定宽标量和字符串且满足读取内联预算时，循环可以使用局部 Reader 状态。共享格式化策略、回调、Union 分发和复合读取使用原 Reader。局部读取成功后发布最终读取状态。失败时调用方游标可能停在更早的位置，目标仍可看到已解析的前缀。可能扩容的循环使用原 Writer，使每次存储迁移都及时更新其状态。已证明的定宽窗口仍可使用局部字节游标。保留原有的头发布、枚举顺序及复用。
- **普通集合的空对象标记。** 若既有定宽负载读取器的存储和校验等效，集合位置元素可只做一次标记校验。无回调的位置对象读取可在目标槽已为空时跳过提前检查。其他复用槽仍提前检查并重置，包括在回调中观察目标的读取器。
- **有界的二进制文本条目循环。** 内置 UTF-16 长度配置下，已验证的密集字符串键字典可保留局部游标，每个条目一次证明键和字符串值或标量值的完整上界。首个需要扩容的条目交给原写入器前，先提交已完成的前缀。跨度和键值对写入复用短 Latin-1 内核，混合长度循环可外移中等记录的写入。
- **带标记的可空集合。** 零起始多维数组为带标记的原生可空值沿用既有的有界输出窗口，按每条记录的实际宽度写入。现代 .NET 的读取器可在经证明互不重叠的窗口内，通过局部游标把带标记的 Int32 解码到矩阵或新建并发队列的暂存跨度。读取前校验完整加载范围，只接受既有的非空及空标记。窗口较短或重叠时使用带校验的标量读取。
- **可空集合存储块。** 在受支持的现代 .NET 目标上，Next 按底层类型选择可空集合元素的布局。经证明的存储可用于任意维数的数组及拥有连续或暂存空间的集合，写入定宽块，保留集合的帧和顺序。`Native` 使用完整可空步幅。`Tagged` 在多模型的非空块写一个标签，读取时可转换其他建模布局。只有单一布局模型时省略标签。准备目标前验证形状、配额、完整负载和布尔存储。发生重叠时，暂存需要布局转换的数据。`Packed`、无法证明的布局，以及逐元素集合中的多模型 Tagged 值使用元素 formatter。
- **可空值的二进制存储。** 在现代 .NET 上，原生读取可在验证负载后填充可空值的负载字段，再发布存在标志。在支持向量加速的小端 64 位目标上，若证明 12 字节负载位于 16 字节可空值的偏移 4，读取器可一次存储 128 位结果。编译器证明负载为非托管类型时，复合值或带回调的读取可以使用临时可空值的存储视图。其他负载及较旧运行时先读入底层类型的局部变量，在负载读取成功后再赋给可空值。仅包含可直接写入的定宽标量或字符串字段的紧凑托管结构体，可以在普通入口和可空入口之间共享一个按值返回的全新读取方法。可空入口通过隔离的 Reader 读取负载，成功后只提交游标。输入窗口和操作状态保留在调用方的 Reader 中。已有值的复用、虚分发负载入口、回调和外层输入策略的带校验投影沿用原读取路径。
- **Memory 布局初始化**。保留优化后二进制 `Memory<T>` 读取器的现代 JIT 消费程序集可以在首次编译读取器前初始化一次精确数组布局探测。进程仍按原先的时机初始化 formatter 注册。其他布局和后端沿用已检查的回退路径。
- **链表的按计数写入**。验证框架节点存储后，符合条件的原生值链表和内置配置字符串链表可以直接沿循环链接写入已观测到的元素数。可能调用用户代码的 formatter 与未知存储沿用公共遍历。
- **原生不可变数组复用**。证明完整输入范围后，生成的原生 `ImmutableArray<T>` 读取器可以保留长度和有效负载字节均匹配的现有数组。不同的负载使用新的后备数组，原有数组保持不可变。默认数组与空数组仍有区别。

### 选项与生成

- **编译期选项。** `[LuminPackOption]` 的作用域（程序集、类型、成员）和无状态的 `ILuminPackOptions` 配置都编译进代码。不存在运行时选项对象或可变的全局默认值。JSON 的编码、深度和语法策略作用于整份文档，由根类型决定。
- **`UntrustedData`** 在编译期选择带检查的二进制读取，默认开启；`UntrustedData = false` 生成的代码与可信代码完全相同。不可信记录使用普通线格式和写入端。对象、版本容忍记录、引用跟踪记录和 Union 的生成读取在实际读取位置检查对象标记、Boolean 值域、回引类型、原始槽位宽度、压缩计数以及已声明的集合和字符串限额，根的限额以常量固化；未声明的限额是不设上限的常量。只在声明了 `MaxDepth` 的递归类型中计数深度；Reader 边界检查和栈保护保持开启。显式的恶意输入声明还会选择严格 JSON 配置。由输入决定的类型直接拒绝。不存在信封、环境计费状态或模式预扫描。
- **`[LuminPackBounded]`** 是调用方的担保：有界记录一次性预留，并去掉内部容器检查。
- **自动生成**发现已声明的模型图和静态所需的闭合操作。旧的生成档位设置被忽略。应用程序和没有友元访问的 Unity 预定义程序集按绑定调用的负载独立保留四种操作，并扩展到成员图与 Union 依赖。编译器拦截与 IL 改写采用相同的操作选择。无法推导更窄范围时，未解析的序列化表达式、注册与直接调用生成的格式化器会保留全部四种操作。库看不到消费方的调用，为已发现的负载保留全部四种操作。注册策略和线格式独立于操作选择。程序集级生成选项可强制保留单个操作。
- **增量缓存**保留精确的语义依赖、设置、诊断和确定性的标识。跨编译的缓存中不能留下任何 `Compilation`、`SemanticModel` 或符号。保留驱动器的输出必须与全新生成的输出一致。

### 可选模块

- Core 不引用 `LuminPack.Unity` 和 `LuminPack.Burst`。
- `LuminPackBurst` Hook 表只存在于 `netstandard2.1`，遵循 [Hook ABI](burst-hooks.cn.md)。空槽位保留 Core 的实现。Burst 代码从 Core 源码投影生成，绝不另外维护第二套算法。

## 3. 安全规则

1. **Release 下保留 Reader 检查。** 前进式 Reader 的 public `EnsureReadable` 及其调用者（`Advance`、固定存储批次、Union 帧）在所有配置下都启用。不得恢复 `Conditional("DEBUG")`、用 `#if DEBUG` 包裹，或为了性能绕过它们。
2. **先检查后访问。** 替代 `Advance` 的生成游标运算，在移动游标之前保留范围检查。标量读取和固定字段回退在任何 unsafe 加载或写入目标之前校验完整范围。
3. **保留动态检查。** 集合、字符串和批量负载的头部与负载校验是必需的。任何按计数分配之前，先用剩余输入长度校验该计数。
4. **独立的不检查契约。** 写入已预留空间的固定 Writer 存储和仅基于地址的原始内核，保持各自现有的不检查契约。这不代表可以删除 Reader 检查，也不代表要给 Writer 一律加检查。
5. **递归。** 递归负载的操作调用 `EnsureSufficientStack`，递归的二进制写入在重入时检查容量。
6. **有符号比较。** 与缓存结束位置的范围比较使用有符号 64 位距离，这样在所有目标上都能拒绝越过末尾的游标和负数计数。
7. **异常**通过 `LuminPackExceptionHelper`（运行时）或生成器自己的辅助类抛出。保留异常类型、参数名、清理逻辑和原始调用栈。

## 4. SIMD

- 每次 SIMD 改动都要审查标量、128 位、256 位、512 位和 ARM64 路径。
- 每个特定指令集的操作都用其精确所需的特性来保护。向量宽度偏好不等于硬件支持。
- 保留有界尾部处理、标量或可移植回退、零长度行为以及完全相同的字节结果。绝不读写已校验完整范围之外的内存。
- 固定宽度的算法只有在有书面理由时才能保留其自然宽度。
- 本地没有的硬件需要在 CI 上执行。编译通过或合成的掩码不算硬件验证。

## 5. 性能证据

- 主要证据是 LuminPack 耗时除以参照库耗时，在同一台机器、同一份数据、同一运行时和选项下于同一次运行中测得。越低越好。
- 报告相对同一参照的改动前后比值、多次采样及离散度，以及分配量。绝对时间作为辅助证据保留。
- 不要从单个纳秒数字推断提升，也不要假设所有负载的波动方式相同。
- 机器负载导致计时不可靠时，改为比较保留的 IL 和原生代码，并说明这一点。
- 可复用缓冲区的基准要把每条独立记录前的重置计入测量。

## 6. 仓库规则

- 代码、注释、XML 文档、诊断、测试和维护文档使用英文。README 和 `*.cn.md` 中文版是例外。
- README、CONTRIBUTING 以及功能指南都有英文版（`name.md`）和中文版（`name.cn.md`）；两个版本一起修改。`AGENTS.md` 只有英文版。所有中文版统一放在 `docs` 下：根目录页面译文直接放在 `docs`，模块 README 译文放在 `docs/modules/<模块名>.cn.md`，功能指南译文与英文版放在一起。英文文档保留原有位置。
- README 只放介绍、安装和使用。发布说明、版本历史、迁移通知和实验报告既不放 README 也不放 `docs`，这些记录不纳入版本控制。
- 不要仅凭调用点搜索就删除外部可用或生成代码使用的成员。
- 生成器改动只进入 `src/LuminPack.Generator.Next`。旧版生成器（`src/LuminPack.Generator`）已冻结，不再维护：不要修改它，不要把 Next 的改动同步过去，也不必维持它的对照测试。
- 维护的源码中每个方法都要有 XML 文档（由 `tools/LuminPack.RepositoryChecks` 检查）。生成的 XML 仅用于可直接调用的 `LuminPackSerializer` API 和门面类型。执行根方法、保留的内部状态转发方法、布局辅助方法、派发槽及私有辅助代码不生成 XML。生成文件对这些有意省略文档的实现细节屏蔽 CS1591。

## 7. 验证

运行 [CONTRIBUTING](CONTRIBUTING.cn.md) 中覆盖本次改动的检查：仓库检查、生成器与生成代码契约、针对性的运行时测试、增量生成、数据格式夹具，以及平台相关代码的运行时兼容性工作流。结构断言和往返测试只能证明已测试形态的覆盖，不能证明对所有模型都成立；请报告未验证的部分。
