### Core 源码布局

运行时入口和游标状态位于 `src/LuminPack.Core/Core`；可选的 `netstandard2.1` Hook 派发位于 `Core/Acceleration`。`LuminPackWriter`、`LuminPackReader`、`LuminPackJsonReader` 和 `LuminPackJsonWriter` 的字段、构造函数和游标辅助方法位于主文件，各类操作位于按类别命名的 partial 文件（`.Values`、`.Strings`、`.Collections`、`.Framing`、`.FusedEntries`）。工具代码按职责放在 `Utility` 下：

| 目录 | 职责 |
| --- | --- |
| `Buffers` | 自有和分段输出、使用池化缓冲区的流输入。 |
| `Collections`、`Collections/Trees` | 集合存储视图和树辅助。 |
| `References` | 引用身份和 Union 映射。 |
| `Memory`、`Memory/Views`、`Memory/Simd` | Marshal 操作、原始数组、非托管视图、复制内核。 |
| `Layout`、`Layout/Simd` | 字段偏移、布局标签、转换与字节重排。 |
| `Text` | `StringSerializer` 和文本内核。 |
| `Compression`、`Pool` | LZ 压缩和池化存储。 |
| `Configuration`、`Diagnostics`、`Protocol` | 选项作用域、异常、协议常量。 |
| `Compatibility` | 生成代码使用的公共转发入口。 |

文件的物理位置不改变命名空间和数据表示。

Core 的复用缓存共用 `Utility/Pool/AtomicSlotPool<T>`：可内联的首槽加有界溢出扫描。各槽独立持有引用，取出/存入提示只决定扫描起点。`ObjectPool<T>` 为每个闭合类型、每个线程保留一个带池身份校验的 TLS 对象，与 writer、不可变 builder、Frozen 构造缓存使用相同的共享存储。详见[缓存池与内存保留](pooling.cn.md)。

## 运行时执行模型

现代 Core 资产为 `DateOnly`、`TimeOnly`、`Int128` 和 `UInt128` 提供带类型的 JSON 写入重载。它们在有界栈缓冲区中格式化，保留原有 JSON 字符串表示（日期和时间使用 `O`，128 位整数使用固定文化的十进制格式）。格式化方法体不展开到生成的调用方中。生成器先检查实际引用的 Core API；引用旧版或 netstandard 资产的项目仍使用原有字符串转换路径，不依赖消费项目的框架编译符号。

私有的标量格式化路径也用于 `DateTime`、`DateTimeOffset`、`Guid` 和 `TimeSpan`。这些确定的格式产生有界且无需转义的 ASCII。在 .NET 8 及以上，UTF-8 配置直接在有界字节暂存区中格式化，通过共用的不内联复制入口发布完整载荷。固定 36 字节的 Guid 表示直接在原有、已验证的目标预留区间中格式化，使用输出回调前按值捕获的值。其他标量仍在回调前完成格式化，并按实际载荷长度预留空间。旧目标保留共用的不内联字符编码入口；UTF-16 直接复制格式化字符。输出容量检查、引号、逗号状态及失败发布行为保持不变。

当实际引用的框架提供 span 版本 `CopyTo` 时，`StringBuilder` 二进制写入直接复制到完整预留的字符区间；旧框架回退仍然保留。JSON 写入在发布输出前取得完整快照，使用有界栈空间或用后归还的池化字符缓冲区。null 和空值不进入快照栈帧。`LuminPackJsonWriter.WriteStringBuilder` 与 `WriteStringBuilder<TOptions>` 提供此操作，不改变 `Write` 对 null 字面量的绑定。对应的 `LuminPackJsonReader.ReadStringBuilder` 重载把解码和构造保留在共享 Runtime 入口中。生成调用依据实际引用的 Runtime API 选择。JSON 读取消费完整且已反转义的 token span。UTF-8 内容通过有界栈空间或用后归还的字符缓冲解码，保留原解码器的替换行为。新建 builder 使用原字符串构造函数的容量，填充完成后才发布；复用 builder 仅在完整解码后清空并追加。池预热后，两种编码均避免中间字符串；池未命中仍可能分配。

`Version` 保留固定二进制记录及两、三、四分量的 JSON 字符串。具名 JSON 操作 `WriteVersion`、`ReadVersion` 及其编译期配置重载不改变 `Write(null)` 的绑定。写入使用有界栈空间：.NET 8 及以上直接格式化为 UTF-8，其他路径格式化为字符。生成的读取代码解析完整 UTF-16 token span；.NET 10 及以上也直接解析 UTF-8 span，旧框架 UTF-8 则通过有界或池化字符 span 解码，再调用 BCL 解析器。现代目标尚未选中 token 的路径同样保留原字符解析器的异常行为，无需创建 token 字符串。格式化与解析位于共享 Runtime 方法中，生成器依据实际 API 选择调用，保留 BCL 验证、新建结果身份和失败发布顺序。

`Type` 写入器将既有程序集限定信息剔除到有界栈空间或可归还的池化字符缓冲区，然后直接编码该字符快照。共享匹配器保留原正则的 Unicode 数字及单词字符类别、版本中的非换行分隔符和 token 分支。二进制继续使用既有 Length/Token/VarInt 和紧凑 Latin-1 表示；JSON 复用普通字符串内容内核。二进制未缩短名称的回退独立成方法，避免普通字符串写入器占用名称处理方法的机器码预算。生成器根据实际 Runtime 元数据同时检查默认及编译配置写入签名，旧资产保留正则替换。类型解析、文化信息实例语义、URI 构造和 Lazy 求值行为保持不变。长名称的池未命中及 BCL 类型解析仍可能分配。

`BigInteger` 保留有符号小端二进制载荷及 invariant 带引号十进制 JSON 表示。二进制读取在引用的 Runtime 提供接口时选择 `LuminPackMarshal.ReadBigInteger`。共享构造入口规范化负数的符号扩展，用有界栈空间或用后归还的池化字节转换仅含符号的高位字，避免 BCL 裁剪产生的临时数组，只分配最终数值存储。较大的负二次幂先扫描已验证的零前缀，再通过公开数值接口构造。正数和已紧凑的表示保留 BCL 构造路径；接近有符号位数上限的载荷也保留该路径，避免改变 Runtime 算术限制行为。向量操作与构造分置于独立方法；32 位访问使用单个四字节值。头部与载荷检查、线格式及失败发布行为不变。具名操作 `WriteBigInteger` / `ReadBigInteger` 及其编译期配置重载不改变数值 `Write` 的重载绑定。格式化使用有界栈空间或用后归还的字符池缓冲。.NET 10 之前，通过公开的数值字节接口及有界或池化工作区转换十进制分组，避免 BCL 格式化器内部数组；完整 UTF-16 token span 直接解析，UTF-8 token 则解码到栈或池中的字符缓冲。旧目标使用有界或池化数值工作区解析常规 invariant 十进制文本，保留 BCL 验证回退及超大数值解析器。生成器依据实际引用的 Runtime 元数据选择这些共享操作，旧 Runtime 保留原字符串回退。null 字符串仍由 BCL 解析器报错，读取失败不会发布替换值。池预热后，复用输出缓冲的写入没有临时托管分配；读取保留 BCL 解析和构造行为，包括某些运行时处理超大数值时的临时分配。池未命中和创建输出缓冲仍可能分配。

`TimeZoneInfo` 的 JSON 读取先将完整解码快照与已有有界缓存比较，再决定是否创建字符串。UTF-16 使用解码后的 token span；UTF-8 对可缓存文本使用 256 字符的目标缓冲区，较长快照保留原字符串解码器。UTF-8 载荷超过字符上限的三倍时，跳过缓存准入所需的字符计数。缓存未命中仍使用原解析器、准入及替换规则。隐藏的 `ReadTimeZoneInfo` 默认及编译期配置入口将这些工作放在生成调用者之外；生成器检查实际 Runtime 引用中的两个 API，不可用时保留字符串回退。已选中 null 的分支、token 验证、解码替换、失败发布及二进制操作不变。预热后的缓存命中避免中间快照字符串；未命中、首次操作状态初始化及反转义工作区扩容仍可能分配。

共享的 UTF-8 到字符 token 解码保留宿主的替换字符分组。便携资产针对旧版默认 `UTF8Encoding` 实现使用有界标量和打包字内核，避免临时替换回退对象；现代或无法识别的默认编码子类保留 BCL 解码器。选择过程没有缓存策略对象，也不增加原生 hook 调用。完整输出窗口无需逐标量检查输出容量；较短且容量受限的 token 先在栈上暂存至多 768 个字符，仅在成功时复制结果。现代目标的有界准入同样使用暂存，避免独立的 BCL 字符计数扫描及其在非法输入上的回退分配；暂存前通过 BCL ASCII 验证器直接拒绝过长的 ASCII 前缀。容量失败保留 BCL 的异常和部分写入行为。这些操作覆盖 builder 和旧目标标量读取、字符读取、时区快照及 UTF-16 属性名，二进制表示不变。池未命中、解析失败和较长的受限 BCL 回退路径仍可能分配。

- **游标。** 新版 .NET 的读写器使用 `ref byte`。`netstandard2.1` 使用长度为 1 的 `Span<byte>` 保存托管游标地址，通过 `MemoryMarshal.GetReference` 和 `Unsafe` 访问及推进。保留的 `Buffer` 窗口提供长度信息和回填位置。
- **双寄存器。** 每个状态在游标旁缓存窗口的结束位置（`_end`，写入器为扩容阈值 `_recordLimit`）。范围检查只需一次减法和一次有符号比较。设置 `Buffer`、`BufferCheckLimit` 或 `Owner`（internal setter）会刷新缓存。
- **生成代码的局部游标写入。** 生成的对象写入代码把游标放在局部变量 `ref byte cursor` 中（JIT 会把它放在寄存器里），并调用返回 `ref` 的写入操作。连续的有界成员共享一次 `ReserveRecord` 检查，之后不再检查。在任何需要使用写入器本身的操作之前，用 `CommitRecords` 发布游标。
- **Reader 检查。** `EnsureReadable(count)` 在每次 unsafe 加载前与缓存的结束位置比较；Debug 和 Release 下都启用。
- **失败路径。** 简单异常辅助方法直接抛出异常，并将内联策略交给运行时。RyuJIT 可以检查这些 IL，识别不会返回的调用，从而缩短正常路径中值的存活区间；强制 `NoInlining` 可能阻止这项分析。JSON 游标诊断所需的受检算术放在抛异常辅助方法内，保留溢出和越界异常语义，避免在每次正常推进中展开。
- **JSON 浮点读取。** 快速数值扫描器保留积极内联提示。单精度缩放尾数在通过 24 位范围检查后使用 Int32 转换。完整数值重扫与回退解析在独立的禁止内联方法中执行，避免其局部状态进入生成的调用方，同时保留语法、舍入、有限值检查和游标发布行为。旧目标中可能出现中间舍入的整数范围交给精确解析器处理。现代目标的 UTF-8 回退对至多十九字节且尾数末位非零的 token 保留原解析器，其他 token 与 UTF-16 使用一致的固定文化浮点解析器，避免未裁剪零尾部造成的舍入歧义。netstandard2.1 将已验证的 ASCII 数值扩大为字符，使用有界栈空间或使用后归还的池化缓冲区。
- **已验证字符的窄化。** ASCII 分类直接检查 UTF-16 通道的高位。短 ASCII 和紧凑 Latin-1 记录共用 128 位窄化原语；已验证的 x86 通道使用 SSE2 无符号饱和打包，无需截断掩码。较长的 ASCII 连续段及紧凑记录也共用 256 位原语。AVX2 打包保持通道顺序，AVX-512BW 则保留平台生成方式。长 ASCII 编码按 64 字符分组验证后窄化；Latin-1 相等比较将尾部位置选择移出完整块循环。有界重叠尾部及可移植回退维持原有输入、输出窗口。Burst 投影同一组 Core 原语和循环。
- **UTF-8 复用比较。** 规范双字节连续段直接在 UTF-16 通道中构造 UTF-8 字节对，SSE2 每次处理八个字符，AVX2 每次处理十六个字符。比较前先验证字符范围；混合文本仍交给验证解码器，非法字节不能复用已有字符串。该路径无需重排表。
- **JSON 容量掩码。** 结构容量提示分类完整 UTF-8 或 UTF-16 块，并在块间传递引号奇偶状态和末尾奇数个反斜杠状态。转义过滤使用固定数量的位操作，同样覆盖整块反斜杠和短尾部。转义过滤的位运算参考 [simdjson 转义扫描器](https://github.com/simdjson/simdjson/blob/master/src/generic/stage1/json_escape_scanner.h)；JSON 语法仍由普通解析器验证。Core 在支持时使用带特性检查的多项式乘法计算引号前缀；Burst 投影 Core 的可移植奇偶回退。
- **选项**是无状态的值类型配置（`ILuminPackOptions`），作为泛型参数传递，配置判断会折叠为常量。
- **缓冲区。** `LuminBufferWriter` 是基于一个 `ArrayPool<byte>.Shared` 数组的 `IBufferWriter<byte>`，同时持有追加会话的二进制和 JSON 引用状态。所有目标都在测量 64 字节对齐偏移前用 `GCHandle` 固定数组，直到归还。逻辑容量和扩容阈值独立于池桶大小。已租数组放得下时原地扩容，换数组时重新计算对齐偏移并刷新游标与结束缓存。

从缓冲区构造的二进制和 JSON Reader 绑定其读取引用上下文。Writer 优先使用显式引用上下文，其次使用关联缓冲区的上下文。`OptionState` 提供已初始化的上下文。

## 生成器

Next 管线的 Formatter 移植流程参见[移植指南](generator-formatter-porting.cn.md)。

| 生成器 | 输出 |
| --- | --- |
| `LuminPackSourceGenerator` | 二进制门面、共享拦截器和编译期配置。 |

三个发布器共享当前编译的程序集级分析，格式化器发布器另行运行逐模型流水线。手动创建 Roslyn 驱动时可注册三个生成器，也可配对使用 `LuminPackSourceGenerator` 和兼容的 `LuminPackAggregateGenerator`，后者提供 JSON 门面和格式化器输出。

主要组件：

| 组件 | 职责 |

| `LuminPackCodeGenerator.*` | 二进制读写、直接记录的长度计算、非托管分组、局部游标写入（`CursorWrite`）。 |
| `LuminPackExtensionGenerator.*` | 操作模板、JSON 辅助、派发片段。 |
| `LuminPackSerializerGenerator.*` | 具体和泛型的 buffer、span、流、异步、JSON 和压缩 API。 |
| `CodeEmitters/` | 每个标量或集合族一个 emitter。 |
| `Api/` | 共享静态绑定、包装方法特化以及编译器/IL 拦截映射。 |
| 各类投影（`SerializerCoreProjection`、`BinaryCursorProjection`、`CompiledOperationProjection`、`RecursionGuardProjection`、`GeneratedOperationScopes` 等） | 改写完成的操作：状态归属、带检查的游标运算、配置传递、递归保护、可读的局部变量名。 |
| `PortableStructPlan`、`PortableStructEmitter` | Packed 和 Tagged 结构体存储。 |
| `Incremental/` | 冻结值、依赖守卫和缓存（`TypeEmissionCache`、`AggregateEmissionCache`、`SerializerFacadeCache`、`RegistrySourceCache`、`PartitionedSourceCache` 等）。 |

### 操作流水线

`NamedBinaryMemberKernels` 为符合条件的源码位置类提供唯一的 `RootWriteMember` 方法体。对应的载荷专用状态转发方法名为 `SerializeMember_<identity>`，调用方只需绑定一个具体方法。成员方法保留原有空值／成员头、相邻字段地址证明、按体系结构选择的定长存储和字符串操作，不用独立根方法的容量融合替换成员写入。该路径要求至少一个字符串字段，其余字段可以是公开原始存储或字符串，排除泛型类型、继承、回调、属性／私有存储和有界声明。其他契约保留既有生成器实现。显式成员配置仍经过已绑定操作路径，不得被调用方的文档配置覆盖。

普通公开字段根对象若仅包含完整运行时记录内核和没有独立配置边界的具名成员，`SerializerCoreProjection` 可以直接使用缓存的类型元数据生成完整写入，保留原有根／成员方法、声明配置及最终存储／游标投影。读取、JSON 和更复杂的写入继续采用既有的检查和操作流水线。成员内核保留积极内联提示；包含成员调用的父对象，即使提取方法后源码调用数量变少，也由运行时决定根方法是否内联。分配型入口继续使用 `AllocateUninitializedArray`，保留缓冲池所有权和清理方式。

每个生成器为每个声明发布一个文件，命名为 `LuminPackGen.命名空间.名称.g.cs`。二进制生成器发布模型的二进制 Root 和 Union 槽位，JSON 生成器发布 JSON Root 和槽位，格式化器生成器发布框架类型和闭合泛型的格式化器、派发、桥接和存储视图。泛型参数写成参数个数，例如 ``LuminPackGen.System.Collections.Generic.Dictionary`2.g.cs``，因此同一泛型定义的所有构造共用一个文件，由发布器合并。同一生成器为同一声明发布的第二种文件带一个角色后缀：`LuminPackSerializer` 重载用 `.Api`，存储视图用 `.Layout`，同时发布 JSON 和格式化器的兼容生成器中 JSON 文件用 `.Json`。程序集级文件按角色命名，例如 `LuminPackGen.LuminPackSerializer.g.cs` 和 `LuminPackGen.FormatterDispatch.g.cs`。内置标量共享 `LuminPackGen.System.g.cs`，所有数组共享 `LuminPackGen.Array.g.cs`。内部生成符号的身份独立于文件名。

每个发布器在输出前独立比较完整文件，因此只影响 JSON 方法的改动可以继续复用对应的二进制文件。同一次编译中，三个生成器共用每个模型的同一份渲染结果。

以负载命名的成员使用负载的可读拼写（`ReadableTypeName`）：`Serialize_ArmorItem`、`LuminRoots_ListOfInt`、`Binary_<assembly>_DictionaryOfIntAndString`。拼写相同的负载（例如不同命名空间中的同名类型）在同一个 partial 容器中成为重载，因为这类成员都以负载作为参数。拦截辅助方法命名为 `Intercept<操作>_<类型>`，有显式配置时再加配置名；特化的源码包装方法命名为 `Wrapper<方法>_<类型参数>`；与已有名称 C# 签名相同的名称按源码顺序编号。Union 槽位名保持原有拼写，因为用户代码可能重写它们。排版阶段把每个模型的 JSON 名称表归入嵌套类，例如 `JsonNamespaceArmorItem.Utf8.ItemId` 和 `Utf8Head.ItemId`，并在方法不使用原名时去掉展开局部变量的编号。

框架字段分类使用 `CodeEmitterTypeCatalog` 中的 CLR 元数据名称，例如 `System.DateOnly`，不包含生成的 C# 源码所用的 `global::` 限定符。直接字段、可空值和集合元素共用该目录，在考虑用户对象的构造函数之前完成分类。

1. 分析类型的规范契约，冻结操作模板。
2. 对符合条件的完整运行时内核写入，直接使用类型事实生成；其余情况绑定根方法并组合嵌套操作，保留递归、`Custom`、虚调用和专用边界。
3. 把调用绑定到序列化器的状态方法体，并传递编译期配置。
4. 规整读取器存储的生命周期和游标槽位。
5. 简化语句块并选择可读的局部变量名（仅影响呈现）。
6. 格式化、添加 XML 文档，并通过缓存边界发布文本。

JSON 辅助方法提取、输入检查插入、操作绑定和序列化器投影之间直接传递不可变语法树，不再把中间模板转成文本后重新解析，也不在绑定前提前格式化。格式化由最终输出负责；外部 JSON 支持代码的文本边界会先规整模板，再进行解析。冻结计划保存语法和纯值数据，不保留使用方的 Compilation、SemanticModel 或符号。方法名和参数数量的语法筛选只排除不可能替换的辅助方法，候选调用仍核对语义身份。这些优化仅发生在生成期，保留生成的方法体和机器码内联策略。

源码组合与机器码内联使用不同的预算。`GeneratedExecutionPolicy` 对包含循环或超过十六处调用的二进制及 JSON 状态方法，交由运行时决定是否内联；小方法保留积极内联提示。移除这一提示不会禁止内联，也不改变嵌套二进制操作的源码展开。包含循环或超过同一调用点阈值的完整 JSON 操作复用已有的具体状态入口，避免把解析状态复制进每个父对象或 Union 分支。二进制 Union 中属于同一程序集生成的封闭类的分支，通过该分支自身的具体 Union 入口读取，不再复制进每个 Union switch（包括展开到集合中的 switch）。输入限额相同时分支直接调用该入口；限额不同时由根唯一的带检查辅助方法应用这些限额；可信父对象只在该入口同样可信时才调用它。定长载荷的入口保留内联提示，变长载荷的入口取代原先外提的分支辅助方法，成为调用边界。Local 存储操作仍在原有访问位置组合。调用点阈值是生成器的启发式规则，并非 RyuJIT 的限制；限制源码展开也有助于避免过于复杂的方法触发运行时的最低优化回退。

二进制根写方法至少有 32 个已绑定操作调用点时，如果其中至少 8 个同级位置写入同一种框架集合，且集合循环中的复合元素还会写入嵌套值，这些位置可以调用已有的闭合类型写方法。统计时排除循环体、局部函数和已预留容量的区域。每次调用沿用原 Writer 和成员配置，让元素循环单独使用 JIT 内联预算。

二进制读方法包含至少 384 个源码局部变量，且至少两个同级成员分支各有 64 个以上局部变量时，生成器可以把这些完整分支分别放进静态局部函数。集合元素循环中的分支也适用。生成器核对类实例及其存储的确切类型，排除依赖外部变量或包含控制转移的分支，并按引用传入原 Reader。每个函数保留原有的校验、对象复用和赋值顺序。

Root 投影完成后，`RootInliningPolicy` 可为体积受限的 JSON 外层方法恢复内联提示，前提是遍历已放入显式禁止内联的辅助方法。语句和局部变量预算不计入这些辅助方法，并拒绝外层仍包含循环或匿名函数的情况，同时保留已有内联策略。这样可以减少空记录和短记录的额外调用开销，让迭代器状态继续保留在独立方法中。预算属于生成器启发式规则，并非精确的 IL 或机器码大小估算。

标量调用绑定后，同一策略为调用密集的 JSON Root 中重复出现的浮点读取提供独立机器码预算。若 Root 在自身方法作用域内有多个浮点解析调用点，且调用总数超过十六处，就按标量类型和编译配置共用一个静态、禁止内联的局部入口。入口调用现有的完整 Reader 操作，让 JIT 在不导入父对象局部变量的情况下内联扫描循环及小型访问器。小 Root 和只有一个解析调用点的集合循环保留原来的调用。局部函数和 lambda 各有自己的作用域，不计入这一源码预算。入口不捕获状态，以引用传递同一个 Reader，并保留校验、游标更新及字段赋值顺序。

固定 Union 游标内核保留积极内联提示：其可选帧头和平台分支会利用调用方的常量进行特化，因此未特化源码的调用点数量不适合用来估计这些内核的大小。

同一执行策略还根据元素契约特化新建的 Union 容器。空列表或数组进入既有的 fresh 操作，复用存储仍进入普通操作。新建列表、数组和不可变数组通过初始化为 null 的局部变量读取每个 Union，成功后再发布到元素槽位。这让 JIT 优化阶段能够直接识别 fresh 值、消除元素复用判断，并避免元素地址跨越负载构造过程保持存活。Union 分派、注册 case 和失败时的发布行为不变。普通对象和 Custom 格式化器继续直接操作元素存储，因为它们较早发生的发布行为可被观察。该策略不推测物理对象布局，也不替代运行时边界检查。

二进制和 JSON 读取不可变列表、队列及其接口时，依据实际引用的 API 签名选择 span 工厂。只有可枚举工厂可用时，恰好填满的池化数组直接传入；部分填充的缓冲仍使用带数量的 `ArraySegment<T>` 适配器。旧版 JSON 列表工厂对单元素仍使用单元素工厂，两到三个元素仍使用 builder 插入。工厂先复制到最终集合存储，再归还缓冲。元素读取、null/空集合、失败时的发布及引用缓冲清理仍保持既有顺序和契约。

便携版 BitArray 二进制操作除字段偏移外，还验证实际后备数组表示。支持的写入直接复制到 writer，并在输出中保留公开 CopyTo 的填充位行为，不租借临时存储、不修改源对象。读取直接填入按整数边界取整的新结果，进行原有公开长度调整后，在载荷读取成功时发布。空值、极端长度和写入时保留多余容量的情况继续使用既有回退。生成器按实际引用元数据检查可选 helper 的完整签名，旧 Core 仍生成原代码。现代目标的复用及两种 JSON 路径不变。其余临时租借继续使用原生 ArrayPool 策略，包括内存压力下的缓存回收。

不可变队列的二进制和 JSON 写入使用经验证的栈视图。前栈和已有反转缓存直接遍历。未缓存的多节点后栈逆序复制到池化缓冲，由生成的不内联辅助方法写出，并在 `finally` 中归还及清理引用。空后栈和单节点后栈不需要缓冲。序列化不建立框架的惰性缓存，应用之后遍历时仍可能创建缓存。不支持布局和任意接口实现保留公共遍历。生成器能力检查要求两个 Runtime 辅助方法的完整签名，并随引用元数据变化失效。零额外分配针对运行时和缓冲池预热之后；初始化及池未命中仍可能分配。

两种格式的不可变列表和队列读取均根据实际引用的 API 选择公开 span 工厂，包括集合包已提供该接口的旧目标框架。缺少无泛型约束 span 重载的引用保留原可枚举或小列表构造。这一共享能力检测覆盖具体类型与接口声明，并在使用方编译变化时重新计算。JSON 不可变栈从已完整读取的缓冲尾部向前 `Push`，与二进制路径一致，无需反转缓冲或装箱枚举器。这些路径保留栈顶优先顺序，仅在结果完整后发布。null/空值、元素回调、验证及引用池缓冲清理行为不变。span 工厂可用时，构造仅分配返回集合及其结果节点；旧工厂回退及池未命中仍可能有临时分配。

直接写入已构造对象的 JSON 读取器会记录识别出的可写字段，直到原有的缺失成员重置位置。四个及以上此类字段共用无符号 32 位存在标记；更小的契约保留 Boolean 标记。已存入默认初始化临时变量的成员无需额外存在标记。这样可以减少生成的局部状态，同时保留字段读取顺序、对象发布、复用、构造器及 Local + As 存储访问行为。

不可信二进制读取（默认）就是普通读取模板，只在读取位置插入检查（`SafeReadProjection`）：对象标记、Boolean 加载和批量读取、集合计数和字符串都调用很小的 `LuminPackInputPolicy` 适配方法，根的限额作为常量参数传入。嵌套类型的计划按根的限额区分，因此嵌套类型继承这些限额。原始基元数组和列表保留运行时内核，计数和 Boolean 检查放在调用之后。不可信记录中的嵌套用户记录保留各自的带检查辅助方法，使每个方法体都在 JIT 内联预算之内。版本容忍、引用跟踪和 Union 模板经过同一个投影；回引会检查类型，压缩计数在分配前检查。未声明的限额是 `int.MaxValue` 常量，会被 JIT 折叠消除。声明了深度限额的递归类型在 Reader 上计数深度。`SafeContract` 拒绝由输入决定的类型，它们的操作直接失败。只写的投影不受输入策略影响，Union 写入槽位使用可信配置标识。若嵌套二进制读取自身的入口使用相同的固化限额，它沿用可信的复用决策并调用该带检查的入口；Boolean 以外的原始框架标量使用共享的 Reader 重载，由 Reader 选择对应架构的标量访问。写入和 JSON 不随输入策略变化。不可信父对象像可信对象一样展开嵌套的普通记录，并在同一分支中检查其成员标记。Boolean 数组由 `ReadCanonicalBooleans` 读取，在一次向量遍历中同时复制和校验存储。若定长字段批次中的所有 Boolean 位于同一个四字节或八字节窗口内，`ReadCanonicalBatch` 用编译期掩码检查它们的输入字节。拒绝辅助方法直接抛出异常，JIT 因此把它们视为不返回的调用并移出热路径。递归栈保护把当前帧地址与该线程上运行时已接受的最低帧比较，只有更深时才询问运行时。不可信入口就是可信入口加上输入上限，显式恶意输入声明的 JSON 入口选择严格且限定深度的配置。

版本容忍写入方复制一个缓存的修订版 2 前缀（头、元数据和成员宽度），单遍写出成员，并为每个变长成员预留和回填 `int` 长度。全部由定宽成员组成的记录是宽度固定的直接记录。版本容忍写入方在每次操作中只在某个模型的第一条记录写表，后续记录只写指纹；演进后的读取方在读取状态中按指纹缓存表。引用跟踪写入方把常量槽位表和引用 id 写入记录的第一次预留空间，并像普通对象一样写出成员。读取方把一致的表按常量字比较后直接读入对象；其他表走另一条路径，把槽位宽度放在局部变量中，并从输入重新读取未知的尾随槽位。引用身份先用短的引用扫描，之后使用开放寻址的身份映射；读取方用数组存储顺序分配的 id。

在支持的 64 位目标上，17–32 字节短块复制使用两次有界的 128 位头尾访问并保持内联，同时避免调用边界和未清理的高位 256 位状态；即使支持更宽向量，此处也有意保持 128 位。更大的短向量块复制不内联：内联到大型调用方的 256 位复制会让高位向量状态保持未清理，调用方下一次调用运行时辅助代码（分配或块复制）时约多出一百纳秒。缓存的版本前缀出于同样原因按字复制。标量、32 位和不支持该能力的目标保留各自回退路径。

复用目标的 256 字节到 32 KiB 块复制：在 256 位向量有硬件加速的 x64 上，使用不内联、按目标对齐的 256 位流程；在 512 位向量有硬件加速的 GenuineIntel 处理器上，改由同一流程的 512 位版本处理，并且从 128 字节就开始。新分配的目标、Arm64 及其他目标仍使用运行时块复制。`LuminPackMarshal.AllocateUninitializedArray` 在 8 KiB 以下返回清零数组，8 KiB 及以上返回未初始化数组。两个阈值都来自 LuminPack 自己在七台主机上的 CI 测量（Xeon 6975P-C、EPYC 9V74、EPYC 7763、Core i7-8700B、Neoverse N2、Cobalt 100、Apple M1）：先按尺寸用探针测出，再用矩阵的原始集合行确认。具体表格和比值写在代码旁，见 `LuminKernelPolicy` 与 `LuminPackMarshal`。

Int32/UInt32 引用长度和 id 保持较小的正数单字节路径，原有带标记转换放在外提的辅助方法中。

不可变接口写入先识别框架的精确实现类型，再选择具体遍历；自定义实现保留接口枚举。静态且禁止内联的局部入口将具体枚举器状态隔离在调用根之外。JSON 覆盖不可变列表、装箱的不可变数组、集合、队列、栈和字典。二进制接口集合与字典使用相同选择；装箱不可变数组保留既有的数量回填和默认值失败路径。

具体类型的不可变列表、有序集合和有序字典，其 JSON 写入器使用下文的树复制方法。通过 `IImmutableList<T>` 访问的框架列表也走这条路径。写入非空集合时，租用能容纳全部元素或键值对的数组，在 `finally` 中归还并清除引用。临时空间为 O(n)，池未命中时可能分配。列表会检查封闭节点类型的字段和空哨兵，再将三个元素的地址与公开方法 `ItemRef` 的结果比较，通过后才启用中序遍历。布局无法识别时使用公开枚举。生成器会检查目标运行时是否提供匹配的复制重载，再生成调用。

哈希集合、哈希字典的 JSON 写入及其接口二进制写入，复用经过检查的 `LuminTreeStorage.CopyTo`，复制到使用后归还的池化数组。这保留不可变集合的枚举顺序和元素格式化，同时避免 BCL 冲突桶枚举器的临时分配。归还时清除数组中的引用，元素写入失败也会归还。具体类型的二进制 raw 与暂存路径仍采用既有选择。在布局已验证且池已预热时避免临时托管分配；池未命中、BCL 首次使用的缓存、自定义实现及布局不可用时保留的公开枚举回退仍可能分配。

二进制 `SortedList<TKey, TValue>` 写入保留原有存储选择和捕获的数量。经过验证的键、值 span 使正常循环无需反复读取数组 out 参数的状态及执行边界检查。兼容复制位于禁止内联的局部函数中，并在 `finally` 中归还两个暂存数组、清除其中的引用；获取第二个数组期间，第一个数组也受到保护。集合容量分析绑定最近函数的负载与数量符号，不引用外层函数的局部变量。对于从零开始的标准辅助循环，只有确认循环体不会改变迭代范围后，才使用其捕获的数量参数。

具体类型的 JSON SortedList 写入仅在所引用的 Runtime 提供完整可选 API 时选择带检查的存储遍历。键值范围由现有存储与修改版本探测验证。每轮在执行任一格式化器前捕获整对键值，并在原有枚举边界检查版本，包括最后一对之后。集合修改仍抛出 `InvalidOperationException`，诊断文字采用库内的集合修改提示。未知布局在外提回退中使用原有公开枚举器；旧 Runtime 引用保留原先生成的操作。布局验证且预热后的写入避免枚举器装箱分配，也覆盖生成对象内部按具体类型声明的字段。首次探测及公开枚举回退仍可能分配。接口声明集合、JSON 读取和二进制操作保留现有契约。

具体类型 `ConcurrentQueue<T>`、`ConcurrentStack<T>` 和 `ConcurrentDictionary<TKey, TValue>` 的 JSON 写入在原有空集合分支使用公开 `IsEmpty` 查询，保留公开枚举器及其快照或并发观察行为，避免仅为判断空集合而遍历完整栈或获取所有字典锁。`ConcurrentBag<T>` 保留数量查询，因为其他线程首次查询 `IsEmpty` 可能初始化线程本地存储。二进制计数遍历、集合构造、元素回调和读取发布保持不变；枚举器及快照分配仍取决于 BCL 和 Runtime。

Set 接口写入器对精确的 `HashSet<T>` 和 `SortedSet<T>` 实现使用公开的值类型枚举器。如果引用框架的实际元数据提供 Frozen 的公开值类型枚举器，`IReadOnlySet<T>` 也采用该路径。具体循环放在独立的静态操作中。派生类型和未知实现使用接口遍历。JSON 保留原有的数量查询与数组 framing，二进制回退路径保留按实际写入数量发布头部的行为。精确 SortedSet 实现为空时，二进制写入在原有头部容量检查后跳过枚举器；非空集合仍保留公开 SortedSet 枚举器内部位于堆上的遍历栈。

空 Frozen 读取在原有二进制头部验证或 JSON token 消费之后返回框架共享的空结果。非空值保留原有构造和失败发布方式。运行时存储构造器与暂存式 JSON 读取器对单元素 immutable hash/sorted set 使用既有的公开单元素工厂，避免中间 builder。多元素构造、重复元素与 comparer 行为、池化暂存，以及现有二进制弱候选缓存均保留各自路径。这些特化不表示所有 Set 读取或任意接口实现都没有临时堆分配。

树构造从取得哈希排序数组起，一直拥有它到比较和节点创建结束，布局自检也遵循此规则。调用方在成功、碰撞回退、空键回退及异常时归还数组；回退 builder 仅在归还之后开始执行。兼容原始值 Set 写入在复制或输出预留失败时也归还暂存数组。这些清理边界保留原异常、回调顺序和结果发布行为，不为预热后的成功操作增加托管分配。

共享哈希排序将有符号哈希保存在原始元素索引的高位。已有序且存在哈希碰撞的键跳过排序，仍选择原有碰撞回退路径。兼容资产在核心库为 `mscorlib` 时使用有边界、非递归的堆排序，避免旧 BCL 区间排序的委托分配；现代核心库保留 BCL 排序。所有读取和移动限于数组已初始化的前缀。哈希回调、重复元素顺序、构造、清理及生成的二进制／JSON 操作保留原有约定。预热后的排序无需托管分配或额外暂存；首次运行时识别及既有布局／池初始化仍可能分配。

不可变树的直接构造保留原有单元素工厂调用，然后完成该新建且尚未发布的结果对象及根节点，避免再次克隆集合外壳和丢弃最初的节点。此优化用于既有的不同哈希值集合／字典路径，以及有序兼容集合／字典路径；现代排序树构造器绑定可用时仍优先使用。共享空节点和已经发布的集合不会被修改。哈希／比较器调用、回退构造、结果发布和二进制候选缓存保留原有行为；JSON builder 路径仍独立。符合条件且预热后的构造仅分配最终集合与结果节点；布局探测、比较器初始化、池未命中、用户回调和回退 builder 仍可能分配。

框架标量和字符串的 `ImmutableHashSet<T>`／`IImmutableSet<T>` 读取还会选择经验证的碰撞桶构造入口。生成器检查元素实际核心库身份及两个 Runtime 重载。双元素接口二进制读取使用两个局部变量，无须暂存；更长输入的池数组在 finally 中归还。完整输入按哈希及原始索引排序，桶内去重保留首次表示，然后链接最终节点。碰撞列表复现顺序 AVL 追加的拓扑，以保持后续删除及枚举行为。便携目标在没有经验证直接分配器时克隆既有空哨兵节点。具体类型二进制缓存和精确复用比较保留，JSON 及接口结果仍按原规则新建。用户自定义哈希和相等比较保留原 builder 及回调顺序，API 缺失或布局探测失败时保留旧路径。预热且支持布局的构造只分配最终集合和节点；首次初始化、池未命中及 builder 回退仍可分配。

不可变序列和字典的 JSON 读取在取得临时存储前消费原有的首个 token。空结果返回同一具体类型的共享 `Empty` 值，无需租借序列缓冲区或创建字典 builder；非空输入保留原 token 循环与构造方式。复用的可变字典在验证元素数为零后消费数组结束标记，清空同一实例并返回，保留其 comparer。空原始值不可变列表的二进制写入及便携 `BitArray` 写入仍调用原空 span 写入操作，但不再租借池缓冲区；便携空 `BitArray` 读取使用共享空暂存数组，仍按原方式创建新结果。新建空并发字典的二进制读取将共享空条目数组传给原构造 helper。非空暂存、公开枚举、默认并发度、边界检查和失败发布均不变。

集合的遍历和构造应按存储布局、格式器能力与回调行为选择。禁止根据基准使用的键值类型组合选择专用算法。JSON 字典生成代码对每项写入或读取数组边界，并分别调用键和值各自的格式器。保留旧生成程序集所依赖的运行时签名。

只读内存和数组切片在 JSON 写入前捕获当前元素。分段序列按位置游标遍历，遇到空段时保留逗号状态。可写内存在分隔符回调之后读取各元素的引用。

顺序集合接口写入器在声明契约允许时，对精确的框架 List、数组、Queue、Stack 和 LinkedList 使用其公开的具体枚举器。各循环保持为独立操作，避免枚举器状态累积到分派方法的内联预算中。经过验证的运行时辅助方法还可以沿精确的 ObjectModel 包装类型找到其公开枚举实际使用的 List 或数组；派生类型、未知布局及更深的包装链保留公开枚举。辅助方法直接返回已有存储引用，不创建适配器。二进制接口 framing 和 Stack 顺序仍区别于具体 Queue、Stack 的表示方式。

同一套序列遍历也可以解包密封类型 `LuminPackGrouping` 已有的可枚举对象，无需构造适配器。密封类型 `LuminPackLookup` 的写入使用未装箱的字典条目枚举器，同时避免 Values 视图和枚举器装箱。原有公开枚举 API 保持可用；其他 LINQ 实现保留公开遍历。生成的未装箱查找表循环与分派主体分离，限制枚举器状态和重复元素格式化展开对方法体的影响。所有类型发现和可达性图均保留分组及查找表操作隐式依赖的闭合可枚举类型。

优先队列 JSON 写入可以使用经过验证的堆数组 Span 和单独验证的修改版本。格式化之前先取得完整的元素/优先级对，并在每一对之前及最后一对之后检查版本。未知布局和旧 Runtime 元数据保留 `UnorderedItems` 枚举。二进制写入仍使用原有节点访问语义。二进制队列及优先队列的复制工厂在消耗完整暂存数组时直接传入该数组，空切片使用共享空数组；部分切片仍使用 `ArraySegment`。构造器选择、批量建堆、容量、复用、暂存清理和发布规则均保持不变。ConcurrentBag 的 JSON 写入直接遍历原本相同的 `ToArray` 快照，保留原有 Count 判断，省去数组枚举器对象。快照数组和并发队列迭代器仍会产生分配。

分组、`Complex` 和 `Plane` 的固定 JSON 属性名通过隐藏的 `ReadStringChoice` 操作，与读取器已解码的 UTF-8 或 UTF-16 token Span 比较。在下一个 token 使 Span 失效前保存匹配结果。根据实际 Runtime 元数据同时选择默认及编译配置重载；旧资产保留字符串比较。转义名称、未知名称、重复属性以及原有失败发布行为保持不变。

Observable JSON 读取器仅在实例为精确框架类型、已验证的集合与属性监听器槽位均为空，且底层存储为精确 List 时，省去通知参数构造。每个元素格式化完成后重新检查资格；订阅者、派生重写及不可用布局保留公开插入操作。新的只读 Observable 结果先填充尚未发布的底层 List，再创建包装对象。二进制新建 Observable 使用构造器创建的 List，复用仍保留原有清空并替换存储的行为。预热后的无监听复用可避免临时堆分配；通知订阅者、首次布局探测、JSON 容量增长和未知实现仍可能分配。

二进制状态局部化保留操作入口快照，以及仅在成功完成时发布状态的边界。无额外 byref 参数、返回 void 或整数的局部辅助方法，在顺序调用之间共用一个调用方临时状态，并保留调用前后的两次发布复制。计数式顺序遍历辅助方法返回实际遍历的数量，调用方持有原有头部预留和最终回填职责，从而避免每个具体循环重复完整的 Writer 快照与 framing。未知调用及可能返回别名的辅助方法保留独立存储。该决策依据生成的操作图，不依赖 Benchmark 类型身份。

`UnmanagedRootSharing` 在一个调用批次的格式器贡献全部完成后运行。它按非 unmanaged 实参，把同一泛型定义（或同一秩数组）的闭合构造分组，将每个 Root 的语法与其他成员对齐，只允许拼写 unmanaged 实参的类型节点存在差异。能够对齐的成员归入同一簇。每个簇生成一个泛型 Root，先用代入验证，再把泛型 Root 和全部成员的 Root 放进同一个编译中绑定比较；证明失败的成员被移出，直到剩余成员全部通过。通过证明的 Root 移入与载荷容器并列的 `LuminShared_<Type>` 容器，各闭合 Root 改为转发方法。结果按成员的完整贡献文本和元数据引用缓存。

只替换节点的重写遍历继承 `NodeRewriter`，直接返回原 token，不再为每个 token 重建 trivia 列表；需要重命名 token 或修改 trivia 的遍历仍直接继承 `CSharpSyntaxRewriter`。生成器为自身决策而绑定的生成语法会带上临时的 `#nullable disable` 指令（`GeneratedBinding`），使符号查询不会对生成方法运行消费方的可空流分析；该指令在语法继续使用前移除。各投影中的语义查询放在语法前置条件之后执行。

### 增量边界

生成过程把当前的语义分析与冻结的输出值分开。每个根类型的源码、布局和诊断在产出源码前都会比较；值没变就不会触发输出回调。跨编译缓存只保存描述、语法树标识、复制的设置和生成的字符串，绝不保存 `Compilation`、`SemanticModel` 或符号。失效判断覆盖项目级事实（引用、语言设置、别名、扩展方法签名）和源码闭包（观察到的类型、成员、特性、partial 声明）。`IncrementalGenerationMetrics` 为增量测试提供内部计数。

类型发现使用 Roslyn 的特性索引（`ForAttributeWithMetadataName`），只绑定特性名称可能匹配的声明，并得到实际携带可序列化特性的 partial 声明。发射器按成员缓存写入类别、按程序集缓存布局选项，不再为每次查询重新读取特性。应用程序的操作选择按值比较，因此不改变选择的编辑会让每个类型的已发布文件保持缓存。多个输出缓存共享所属编译内的依赖闭包。项目守卫仅弱引用元数据引用的标识，避免编译引用保留旧项目。IDE 中保留源码的项目引用也由引用标识控制失效；外部项目的语法树不会传给消费方的语义模型，也不会作为本地源码依赖保留。完成输出批次后丢弃不再使用的文件包装缓存。编辑后，编译级守卫和聚合规划仍会检查当前项目事实；增量生成不代表每个阶段在无关编辑后都完全不执行。

在同一次编译中，类型管线与聚合管线会为相同类型、完整生成设置及流式读取选择共享冻结的操作模板。并发请求只发布一个延迟构造的模板，语义构造期间不持有发布锁。这些上下文以编译为弱键，对已完成模板也使用弱引用，并丢弃失败的构造任务；只有不含符号的模板进入保留驱动的输出缓存。未改变值的声明配置叠加会复用不可变值，仅显式叠加输入设置时才复制输入策略。临时操作语法跳过 XML 解析，最终供调用者使用的 API 文档仍保持完整。共享门面分析也跳过 XML 解析，仅在保留完整文档的原始文本中替换可执行方法的范围。最终投影语法在丢弃前提供不含符号的 Root 导航信息，避免再次完整解析；含条件指令的源码继续使用文本解析回退。可打包根的序列化器投影与其操作模板来自同一段发射器文本，`EmitterSyntax` 在每次编译中只为两者解析一次。

生成器会在变更类型分析前，以及聚合格式器和门面贡献之间检查 Roslyn 取消请求。过期工作被取消时会传播取消状态，不会报告为生成器故障。已完成的贡献仍可复用，被取消的聚合批次不会发布。正在处理的单个贡献或项目级语义守卫可能需要完成后才会到达下一个取消边界。

### 模型直出

`DirectTypeModel` 把可打包类型归约为字符串：类型写法、可读载荷名、扩展容器、JSON 辅助类、JSON 读取方式、状态入口是否带载荷名（启用拦截器时，如 `Serialize_Model`），以及每个成员的名称、存储类别、标量、声明写法、宽度和集合格式化器。模型按值比较，不持有编译或符号。对已覆盖的形状，`DirectBinaryEmitter` 和 `DirectJsonEmitter` 直接根据模型写出最终的二进制文件和 JSON 文件，跳过发射器文本、语法投影、生成代码绑定和发布排版。类型发射携带模型，发布时按使用方可用的别名掩码渲染，因此别名集合变化时只需重新渲染，无需重新分析。换行和空行复用发布排版的行布局（`GeneratedSourceLayout.LayOutLines`）。

覆盖的形状是普通的公开或内部类，可以是顶层类型，也可以嵌套在公开或内部的非泛型类中：没有接口、回调、对象池、泛型参数、带参数的构造函数，除不带参数的 `[LuminPackable]` 外没有其他 LuminPack 或框架特性。其他库的特性（特性类名及最外层命名空间都不叫 LuminPack、System、Microsoft 或 Unity，例如其他序列化库的 `[Key(0)]`）从不被分析读取，类型及其成员上都可以带。实例存储全是公开、可写的字段，名称为 ASCII 标识符，不以下划线开头，转成首字母小写后仍互不相同。被序列化的成员可以带 `[LuminPackOrder]`（它只决定分析出的成员顺序），带 `[LuminPackIgnore]` 的公开字段被排除。没有实例存储且不带上述特性的其他声明成员可以存在（普通方法可带 `[MethodImpl]`）：方法、运算符、无参构造函数、计算属性、静态属性、索引器、静态字段、常量和嵌套类型。访问器均为公开的公开自动属性同样覆盖。其后备存储通过根私有布局镜像（`LuminLayout_<hash>_<slot>_<Local>`，声明在二进制文件中）访问，与原操作完全一致：写入通过 `LuminPackMarshal.As` 查看输入，读取查看实例，镜像字符串仅在解码出的实例不同时才赋值，JSON 读取先暂存成员，公开字段由对象初始化器发布，镜像成员通过镜像发布。同一类型的公开字段仍直接按名访问。镜像调用计入内联预算。

基类同样覆盖，条件是每一层都是同一程序集中的普通或抽象、非泛型类，没有接口，除不带参数的 `[LuminPackable]`（可有可无）、Union 分支（带标签和类型的 `[LuminPackUnion]` 或 `[Union]`）、System.Text.Json 的多态特性和其他库的特性外没有其他特性，且只有公开字段。Union 基类的分支列表只影响基类自己的分派文件，因此其分支类型的文件就是普通派生类型的文件。基类字段排在该类型自身字段之后，与原记录一致。派生类型没有具名成员写入，快照局部变量与其他绑定操作一样采用首字母小写，字符串加标量的记录仍走已证明对象写入。带自动属性的派生类型保留原流水线。抽象可打包基类的本地分支若记录全是原始定长存储（`FixedUnionCursorPlan.CanUsePayload`），还带有定长 Union 游标内核 `SerializeUnionAt`，与 `FixedUnionCursorProjection` 的结果相同：Union 写入体改为通过指向缓冲区的局部字节索引寻址，索引在本地推进，整块复制使用 `LuminPackMarshal.CopyBlockUnaligned`，单独存储返回的宽度加到索引上，只有在预留容量之前才发布索引。该分支的 `RootWriteUnion` 随后发布内核返回的索引。

原始非托管结构体（无填充，存储即线格式）在只有公开标量字段时同样覆盖。其 Root 整体复制值，读取入口不经读取 Root、直接调用读取器的原始值读取，宽度为结构体大小，所有入口按引用传递结构体且不带配置；JSON Root 按引用传递，没有 null 处理。有填充的标量结构体走 `PortableStructPlan` 的可移植路径：每个字段经位置存储视图按紧凑线偏移复制，64 位目标使用类型化非对齐存储，其他目标使用写入器的存储，读取经读取 Root。当每个位置视图名同时也是结构体的字段名时，与原投影一样直接按名访问字段。每个字段是原始标量（`bool`、整数、`char`、`float`、`double`）、底层为非 Boolean 整数的枚举、`string`，或非 Boolean 原始标量的一维数组或 `List<T>`。枚举按其底层标量存储，写法用枚举本身；JSON 经底层标量转换。同一程序集的原始非托管可打包结构体，作为定长 Union 分支记录（至少两个成员且不含 Boolean）的成员同样覆盖。其宽度是运行时大小 `Unsafe.SizeOf<T>()`：宽度在遇到第一个运行时大小之前折叠常量，之后的项按顺序追加；运行时大小的游标推进写成无符号本机偏移；写入器的存储复制结构体；每次取大小调用都计入内联预算。JSON 通过其二进制格式化器所有者读写，这要求该结构体自身的 JSON 写入超过十六次调用的预算，否则外层操作会把它内联复制；调用次数由该结构体的直出模型给出，这一计量忽略其构造函数。记录测量入口（`MeasureRecord`）仅在 `SupportsRecordWidth` 为定长记录选中时生成。任何被覆盖的类型都可以带 `[LuminPackOption(StructLayout = ...)]` 声明：只有 `PortableStructPlan` 读取它，而模型已经使用该计划；用在类上会产生诊断，因而保留原流水线。原始结构体可以有其他构造函数；当分析选中带参数的构造函数时，其 JSON 读取用它构造新值（每个参数对应成员的临时变量或 `default`，其余成员用对象初始化器），并且访问被复用的值时不带容空运算符。可变成员全是字符串时，该类型还带有具名成员写入（`SerializeMember`/`RootWriteMember`），其预留记录写入走已证明对象路径：在运行时自带的 64 位配置下，可证明放得下的记录由共享的记录体直接写入；其他配置和冷路径先预留，与 `ProvenObjectWriteProjection` 的结果相同。所有目标框架、Unity、不允许不安全代码的项目和所有语言版本都被覆盖；这些设置只选择同一文本的不同变体。没有 .NET 8 时，状态和负载参数不带 `scoped` 修饰，JSON 通过原始片段写出每个属性头；只有 .NET 8 且 C# 11 及以上时 JSON 属性头才是 UTF-8 字符串字面量属性，否则是 `byte[]` 和 `char[]` 表；已证明对象写入需要 .NET 8、不安全代码且项目没有 `UNITY` 符号，具名成员写入则保留。项目除 `LuminPackGeneratorOptions` 的生成模式外不得有其他 LuminPack 程序集特性。其他类型完全保留原流水线。

闭合应用同样覆盖。发射器接收该负载被选中的操作，省略其他操作的成员，即 `GeneratedOperationFilter` 会从成品文件中删除的成员；只有调用了 JSON 操作时才发布 JSON 文件。状态转发检查已覆盖类型未经筛选的渲染结果（不使用别名，与原文本排版前的写法一致），并在每种别名渲染中省略已证明的转发方法；省略后成为块内第一个成员的声明会去掉它与被省略成员之间的空行，与原文件经发布排版的结果一致。

直出发射器逐字复现原输出：记录分组与容量预留、相邻定长字段证明及其回退、Boolean 批量掩码、Union 读取把第一个单独 byte 成员当作成员标记检查、Root 容器和入口顺序、按展开模板计数的十六次调用内联预算（包括无法使用批量掩码的定长段中每个 Boolean 的检查）、JSON 属性头、按长度或哈希分派的名称查找、有序属性读取以及隔离的浮点解析函数。内部开发开关 `DirectEmission.Mode` 可以关闭该路径，或切换为校验模式：发布原流水线的文件，并逐一与直出结果比较。改动发射器或投影时，若影响已覆盖形状，必须同步修改直出发射器；用随机形状语料做校验即可发现差异。

### 生成的文件

`LuminPackGen.LuminPackSerializer.g.cs` 存放共享泛型 API。启用[静态拦截](generation-modes.cn.md#静态拦截)时，`StaticSerializerBinding` 绑定固定大小的签名树，记录编译器提供的调用位置，在 `LuminPackGen.Interceptors.g.cs` 中生成共享方法。显式配置同时指定负载和选项类型，此路径不增加负载专属的配置重载。具体便捷方法放在 `LuminEntry_<Type>` 容器中，状态转发方法使用负载专属名称。IL 后端输出相同入口及构建期签名映射，`LuminPack.ILPostProcessor` 在编译后替换本地调用。主动关闭两种接入时，兼容后端保留具体重载文件。每个生成的程序集都拥有 public 的 `LuminPackSerializer`，生成文件屏蔽 CS0436，以遮蔽引用程序集中的同名类型。Root 继续位于 `LuminRoots_<Type>` 容器中。负载已知的推进调用直接指名 `Binary_<assembly>_<Type>` 扩展类，转发扩展与便捷方法都调用已记录的同一个 Root。供用户使用的 `Write`/`Read` 扩展签名继续保留。不新增 Plan struct。

在启用编译器拦截的封闭可执行项目中，`StateForwardingPlan` 会在发布前汇总已经生成的类型、格式化器、Union 和门面代码。确认状态拦截器可以直调其嵌套 Root 后，省略无引用的单调用内部转发。用户源码中的名称、生成代码中的调用和方法组引用，以及有歧义的声明，都会使相应的转发方法保留下来。IL 后端继续使用原有转发链与映射。

源码静态包装方法通过反向调用图索引闭合，每个完整方法构造只复制一份方法体。迁移保留原有方法绑定与参数转换，固定调用者信息的默认常量，拒绝不支持或不可访问的方法体。兜底边界保留原源码与注册规则。编译上下文中的语义对象使用弱关联持有；聚合缓存标识包含拦截位置及所有特化方法体，包括嵌套依赖。Root 与便捷入口的标识不依赖源码位置。

生成器把彼此独立的工作放到多个线程上执行：为全编译范围的类型索引逐文件观察语义；按源文件绑定 API 用法；在 Roslyn 的逐类型步骤按顺序读取结果之前，先分析发生变化的可打包类型；构建各负载的贡献代码；渲染、共享并重定向根调用各负载的 `LuminPackSerializer` 重载。带缓存的依赖事实在锁外计算，以先发布的结果为准。结果按原始顺序合并，因此输出与线程调度无关。在启用动态堆适配（DATAS，.NET 9 起编译服务器的默认设置）的 Server GC 下，这些工作保持串行执行，因为实测中并行分配会让生成明显变慢。

私有共享门面辅助方法和适配器使用符合标识符规则的 26 字符 base-32 后缀，保留原有身份的全部 128 位。这样可以缩短生成源码及元数据中的名称，而不截断身份，也不改变 API 签名、操作方法体、文件标识或派发方式。

泛型兜底方法体仅调用已注册的强类型委托，被拦截的闭合泛型调用绕过这些方法体。`LuminPackGen.FormatterDispatch.g.cs` 包含与负载类型列表无关的固定大小派发代码和程序集策略辅助方法；不再生成 `LuminPack.Dispatch.Lazy.g.cs`、每种负载的工厂或委托缓存。其缓存仅依赖程序集常量以及泛型暂存是否需要输入上限。具体 Root 及其 XML 导航信息独立于注册机制。

通过可达性分析发现的闭合泛型负载会在状态调用投影之前加入索引。生成代码对这些已知类型的调用绑定具体状态操作，不经过仅注册的泛型公共 API。泛型 Union 覆盖保留原有虚调用与缓存槽；已知闭合成员使用相同的线上标签并调用其闭合的具体操作。

### 生成代码的文档

`GeneratedSourceDocumentation` 和 `LuminPackSerializerDocumentation` 只为可直接调用的 `LuminPackSerializer` API 和门面类型添加紧凑 XML 文档。API 注释来自同一份类型分析，包含类型、成员顺序与筛选、CLR 布局与线上布局、缓冲区语义和返回值单位。内部状态转发方法、执行根方法、Union 槽、布局辅助方法和私有门面适配器省略 XML，可执行代码保持不变。生成文件屏蔽 CS1591，启用文档警告时也无需为这些实现细节补 XML。

具体模型 API 和已识别到执行根方法的内置重载，通过编译器绑定的 `cref` 直接链接到对应的嵌套二进制或 JSON Root。内置格式器的导航复用已完成贡献中不含符号的转发信息，并将这些信息纳入门面缓存标识。没有独立 Root 的原始非托管二进制读取、Custom 入口以及大小计算不会获得不存在的读写链接。最终展示会移除已证明归属的局部变量角色中的内部前缀，为记录成员快照使用描述性名称，并用字段注释标记游标记录组。用户成员名和可执行语句保持不变。

局部辅助函数使用 PascalCase 命名，以数字后缀避开名称冲突。标量和 Union 调用投影保留原始操作数的语法及标记，使展示阶段仍能证明哪些标识符属于生成的局部变量；通过 `nameof` 观察到的名称保持不变。

生成的标识符不使用连续两个下划线，因为 C# 规范将其保留给实现。名称净化器把一串标点映射为一个分隔符；以下划线开头的成员，其 JSON 支持字段通过单射映射加上 `U` 前缀。最后一个投影会重命名残留的保留局部变量；只在投影过程中存在的标识可以在生成器内部保留原有写法，用户声明的名称保持原样。

发布之前，序列化器单元、Serializer 门面、JSON 支持代码和共享的非托管根由 `GeneratedWhitespace` 排版。它沿用编译器 `NormalizeWhitespace` 的换行、缩进和空格规则，但只列举一次词元，而不是从每个词元导航到后继词元；注释、文档注释和指令保持原样。在它之前运行的投影自身不做格式化。它按解析器读取打印文本时的方式放置琐碎内容（trivia）：词元的尾随琐碎内容止于第一个换行，其后空行的换行归入下一个词元的前导琐碎内容。

各发布阶段之间交换按值比较的文本，语法树随文本一同传递，而不再重新解析。`PublishedSyntax` 把语法树附加到由它打印出的那个字符串实例上。格式划分、合并、操作过滤、状态转发和 `GeneratedSourceLayout` 取出输入的语法树，为输出附加语法树；只有未附加时（例如缓存步骤之后）才解析。取出即释放，因此驱动保留的输出只持有文本。含条件指令、或文档注释被解析为普通注释的文件，排版阶段会重新解析。以这种方式传递的语法必须与其文本的解析结果一致；例如限定名或泛型名应构造为解析得到的名称语法，而不是单个标识符词元。

发布时，`GeneratedSourceLayout` 在名称可用时为重复出现的框架辅助类型添加文件作用域别名。生成的 Union `switch` 中，内部无注释或指令的 case 各占一行。若存在 `default(TFormatter)` 调用，每次调用也各占一行。其余超过 140 列的行可以在最外层的逻辑链、条件表达式、实参列表、形参列表或表达式主体处换行。XML 注释的每个段落各占一行。含多行字面量的文件跳过换行。生成代码合约测试的断言若依赖原有代码形态，可以关闭这层排版。

静态入口类、Interceptor 和特化包装方法按每层四个空格缩进。`GeneratedSourceIndentation` 将已有语法片段放到目标层级，不再为此整文件解析或规范化。多行字符串 token 和非活动源码的内容保持原样，XML 注释与所属成员对齐。编译器和 IL 两种后端采用同一套排版规则。

写入证明的适用性只在当前投影内、类型及设置未变的前提下复用。规范运行时配置的检查以编译对象为弱键，仅保留布尔结果；新的编译仍会检查自己的配置标识，包括消费者声明的同名遮蔽类型。

最终契约文档通过仅替换方法前导注释的文本修改来输出，避免构造随即又转换回文本的 XML 语法树，同时逐字保留注释、条件指令、缩进和可执行源码。

Root 链接使用相对于所属序列化器的名称，避免在每个重载上重复命名空间。编译器将其绑定到同一个方法，并在导出的文档 XML 中写入完整的规范方法标识。

## 异常

生产代码中的异常在 `LuminPackExceptionHelper` 中构造。生成的写缓冲区 catch 路径会重置缓冲区，并通过 `ExceptionDispatchInfo` 重新抛出，保留原始调用栈。
