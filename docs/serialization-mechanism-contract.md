# LuminPack mechanism contract

This is a mandatory project constraint, covering the entire library rather than a short list of examples. Compatibility work must preserve the mechanisms, representations, supported shapes, performance paths, and failure boundaries below. A smaller file or a passing round trip is not sufficient justification for replacing an implementation strategy.

The historical reference is `c4dcc27b5671142ba9e6c7c1c9947ec5f3592b2e`, before standardization and generator restructuring. Source at that revision is the authority for details not restated here. If this document, current code, and historical code disagree, report the discrepancy and its evidence. Do not silently choose a new design. Explicit user authorization takes precedence over these maintenance constraints.

## Model analysis and generated execution

| Mechanism | Hard constraint | Main implementation and regression anchors |
| --- | --- | --- |
| Member contract | Preserve declaration/base-to-derived order, explicit orders, Include/Ignore, automatic-property detection, static/computed-member exclusion, duplicate-name diagnostics, accessibility, and supported member limits. | `LuminPackSourceGenerator.Metadata/Fields/TypeAnalysis`, `TypeMetaChecker`; `ModelBoundaryTest`, documentation regressions. |
| Private storage | Generate Local replicas and use `LuminPackMarshal.As` / `Unsafe.As`. Preserve every necessary slot, including ignored/private padding and automatic-property backing fields. Do not replace storage views with reflection, CLR accessor invocation, or `UnsafeAccessor`. Ref-return helpers whose bodies use Local + As are permitted. | `LuminPackLocalLayoutGenerator`; shallow/deep private, layout, and binary inline regressions. |
| Inherited and explicit layouts | Preserve each inheritance level, slot order, alignment, packing, explicit offsets, type parameters, and constraints. Do not flatten a hierarchy or omit a slot because it lacks ordinary references. CLR layout and serialized member order are separate contracts. | Local layout generator and unmanaged emitters; `LocalLayoutInvariantTest`, `LayoutKindPrivateTest`, `OnDemandLocalLayoutTest`. |
| Ordinary Object mode | Preserve its existing null/member headers, field ordering, inline nested-field representation, fixed groups, and normal versus polymorphic payload distinctions. Do not insert a separately framed formatter call into a previously inline field. | `LuminPackCodeGenerator` parts; code-generation, fixed-field, wire, and inline regressions. |
| Explicit formatter selection | `[LuminPackableObject]` selects the field type's formatter contract instead of ordinary nested field analysis. Preserve that representation, including specialized mode headers. Expansion may substitute the complete selected operation but may not substitute the ordinary Object contract. | Metadata processing and operation templates; complex/model and specialized-mode regressions. |
| VersionTolerant | Retain explicit stable order slots, slot-count/object header, the VarInt length/delta table, zero-length absent slots, and payload order. Unknown fields are skipped by their recorded lengths; absent fields receive the established defaults. Keep both the fixed/unmanaged and buffered variable-length write paths and their size accounting. Do not replace this with names, schema ids, reflection, or ordinary Object framing. | `LuminPackVersionTolerantCodeGenerator`; `VersionTolerantSerializationTest`, historical mechanism regression. |
| CircleReference | Retain object identity tracking, reference-id markers, new-object slot/delta framing, and reference reuse. Register the allocated/rented object before reading its children so self-cycles and shared aliases resolve to that exact object. JSON retains its existing id/reference representation. Preserve tracking scope and reset rules. | Circle-reference emitter, optional states, JSON emitter; circle, reentrancy, and historical mechanism regressions. |
| Ordinary class/interface Union | Writes, JSON writes, and size evaluation call the hidden virtual/interface slot once. The selected case forwards to its concrete Serializer state body. Do not replace known-case virtual dispatch with a type/MethodTable map, pattern chain, or tag switch. | Union code/dispatch generators; Union shape, runtime, and historical regressions. |
| Generic Union | Preserve the virtual/interface hop and, when `RequiresClosedGenericDispatch` requires discrimination, its switch on `__LuminPackUnionDispatchSlot_*`. Resolve the slot once per closed case/root family. Preserve closed-case precedence over open-family registrations and constraint compatibility. An open-only family can retain its original direct case body. | Union dispatch generator; generic/constraint/open-family regressions. |
| Union reads and external fallback | Reads retain their tag switch. Unknown or registered external runtime cases retain the registry-backed virtual fallback, inherited case behavior, and missing-case failures. Preserve narrow/wide tags and their selection rules. Do not confuse this fallback with the known-case fast path. | Union generators and `LuminUnionFormatterEntry`; `BinaryUnionSafetyTest`, manual registration tests. |
| .NET 11 language Union structs | Preserve feature detection, case map, `IUnion`/case extraction, tag framing, value handling, and reconstruction through the case constructor. Do not apply class virtual dispatch rules to a struct Union. | Source union analysis and Union generator; `Net11UnionTest`. |
| Value types and unmanaged values | Preserve raw unmanaged storage copies, including padding/ignored storage where the original binary contract copies the complete value. Managed structs keep their field representation. Preserve by-ref writes/reads, nullable value presence markers, enum backing widths/signedness, native integers, and constrained-generic distinctions. JSON still uses its own filtered member contract. | Unmanaged/nullable/enum emitters, `.Unmanaged.cs`/`.tt`; primitive, special-value, layout, enum, and historical regressions. |
| Fixed field groups and sizes | Preserve eligibility, fixed-offset writes, grouped reads, runtime-sized type contributions, offset width/extension, and exact evaluator advances. Do not replace grouped memory operations with per-field dispatch or use an estimated size as an exact length. | Binary generator parts and evaluator; `SizeEvaluationMergeTest`, `GeneratedFixedFieldWriteTest`. |
| Generic definitions | Build a generic operation from its original definition, then substitute type arguments. Reanalyzing a closed construction must not change unmanaged classification, headers, or wire layout. Keep nullable annotations distinct from nullable-value wrappers. | Operation plan and closed-type substitution; generic/inline regressions. |
| Custom | Keep method-pointer registry invocation for each supported operation. The formatter owns fields, null handling, framing, and representation. Nested values and collection elements must not bypass it. Preserve operation availability, signature validation, and registration gates. | Custom analyzer/registration and concrete registry state bodies; Custom regressions. |
| Constructors and object pools | Preserve constructor selection/argument matching, initializer versus Local assignments, pool-rent selection, by-value/by-ref rent semantics, and callback timing. Register cyclic objects before populating children. Do not introduce reflection allocation or bypass a selected constructor/pool. | Constructor analysis and binary/JSON mode emitters; object-pool/model regressions. |
| Merge and fresh reads | Preserve each API's root identity, allocation/replacement decisions, null behavior, collection/object reuse, and consumed-byte units. A ref-value read must not silently become an allocate-and-replace read. Fresh and polymorphic operations remain distinct. | Read generators; `DeserializeMergeTest`, sequence/buffer/inline regressions. |
| Callbacks and delegate attributes | Preserve static/instance callback selection, before/after ordering, receiver identity, invocation counts, delegate target/instance/singleton selection, and exception propagation. Inlining must not duplicate or reorder user calls. | Metadata, constructor and mode emitters; complex serialization, Union callback, and historical regressions. |
| Collections and wrappers | Preserve each collection's own null/count framing, item order, stack/queue reconstruction, comparer and mutation behavior, sparse dictionary handling, dimensional bounds, capacity/reuse, immutable/frozen reconstruction, and temporary-pool clearing. Keep array/List/unmanaged fast paths, managed-element handling, tuple, memory, lazy, and interface-wrapper semantics. | All `CodeEmitters`, collection views/marshal helpers; collection, queue/stack, interface, multidimensional, and inline regressions. |
| Special framework values | Preserve each supported scalar/framework formatter, encoding, exact representation, parse/format rules, and fallback. Do not infer an ordinary member layout for a type with a dedicated emitter. | Emitter registry/catalog and scalar emitters; `SpecialTypesSerializationTest`, formatted scalar/number tests. |

`NonGenerator` remains an existing enum value with its existing dispatch behavior. It is not permission to invent an undocumented generation policy. Preserve enum numeric values and public spellings even when they appear unusual.

## Generator, API, and mapping boundaries

- Each retained concrete type has one complete state body per operation on `LuminPackSerializer`. Previously approved convenience/compatibility methods may thin-forward. Ordinary field bodies can be expanded; recursion, unknown generic/runtime types, Union slots, Custom, and explicitly selected specialized contracts keep their required semantics. Preserve argument evaluation order, ref aliases, cursor synchronization, independent local/label names, and caller state.
- Full keeps the approved complete concrete API policy. Light additionally roots declared packable types. Minimal starts from actual serializer/API calls. Formatter dependencies remain separate from convenience-overload reachability. Generic fallback shapes remain callable; one generic operation owns one compact-id switch, rather than copying switches into wrappers.
- Assembly-level `[LuminPackable(typeof(...))]` declarations opt ordinary or generic referenced types into the same analysis and pruning. Repeat the attribute for several types; an open definition selects observed closed constructions. Read complete metadata for Local storage and retain the declared cases of an imported Union. Generate overrides only into eligible current-assembly partial cases, never a second metadata-type declaration.
- The approved visibility expansion makes generated class Union slots and overrides `public` with `EditorBrowsable(Never)`. Virtual dispatch, slot switches, framing, and sealing policy remain unchanged. Imported roots from older binaries with only internal slots need rebuilding for this path. Already compiled case bodies retain their own generic/runtime fallback boundaries.
- Incremental caches must preserve exact semantic dependencies, API overload binding, settings, diagnostics/locations, deterministic type/file identities, and retained-versus-fresh output. No live `Compilation`, `SemanticModel`, or symbol may escape into a cross-compilation frozen cache. Preserve cancellation, concurrency isolation, and collection of discarded compilations.
- Mapping is part of this contract: preserve automatic/manual mapper selection, member matching/conversions, ignored/missing members, generated partial signatures, constructor/binding behavior, mapper registration, and diagnostics. Serializer restructuring does not authorize mapper behavior changes.
- XML documentation must describe the actual selected type, overload, filtered members, storage versus wire layout, option ownership, and return units. Documentation generation must not change runtime dispatch or determine serialization independently of the canonical analysis.

## Change control and verification

Any mechanism replacement requires explicit authorization and a reviewable explanation of its behavioral and performance impact. Refactoring, dead-code removal, caching, or reducing IL/metadata is not such authorization. An uncovered historical correctness bug may be fixed while preserving its intended protocol/algorithm; record it as a bug fix, with a reproducer, rather than claiming the implementation was unchanged.

Review every new emitter, runtime subsystem, attribute, setting, and conditional path against this inventory. Add an entry when a mechanism is introduced. For details omitted here, compare the relevant source at the historical reference; absence from the table never permits redesign.

Run [CONTRIBUTING](../CONTRIBUTING.md)'s checks. `SerializerMechanismRegression` can additionally execute both analyzer versions on identical models and compare Union virtual bodies after only API-owner renaming, exact binary bytes, JSON text, version gaps, cycles/shared aliases, values/layouts, nullable/enums, collection order, callbacks, and size results:

```text
dotnet run --project tests/LuminPackDocumentationTest -c Release -- --verify-mechanisms <absolute-path-to-historical-LuminPackGenerator.dll>
```

The historical comparison separately records the corrected sparse-slot size result: the original analyzer omitted one zero-length slot-table byte, while both analyzers write identical bytes. `SerializerSpecialModeBoundaryRegression` covers trailing additions/removals, complete consumption, gaps, and empty schemas in both specialized modes. `SerializerCustomFormatterRegression` checks that an actual unmanaged Custom argument retains its formatter while an ordinary constrained argument in the same compilation retains raw copying.

Structural assertions, historical wire comparisons, specialized regression suites, current-versus-fresh incremental comparisons, concurrency, and multi-target execution complement each other. They establish coverage for tested shapes, not a proof for every possible consumer model. Record unverified boundaries and unresolved issues explicitly.
