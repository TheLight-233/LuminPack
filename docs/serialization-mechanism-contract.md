# LuminPack mechanism contract

This is a mandatory project constraint, covering the entire library rather than a short list of examples. Compatibility work must preserve the mechanisms, representations, supported shapes, performance paths, and failure boundaries below. A smaller file or a passing round trip is not sufficient justification for replacing an implementation strategy.

The historical reference is `c4dcc27b5671142ba9e6c7c1c9947ec5f3592b2e`, before standardization and generator restructuring. Source at that revision is the authority for details not restated here. If this document, current code, and historical code disagree, report the discrepancy and its evidence. Do not silently choose a new design. Explicit user authorization takes precedence over these maintenance constraints.

JSON still uses its own filtered member contract. | Unmanaged/nullable/enum emitters, `.Unmanaged.cs`/`.tt`; primitive, special-value, layout, enum, and historical regressions. |

Keep nullable annotations distinct from nullable-value wrappers. | Operation plan and closed-type substitution; generic/inline regressions. |

| Constructors and object pools | Preserve constructor selection/argument matching, initializer versus Local assignments, pool-rent selection, by-value/by-ref rent semantics, and callback timing. | Merge and fresh reads | Preserve each API's root identity, allocation/replacement decisions, null behavior, collection/object reuse, and consumed-byte units. | Callbacks and delegate attributes | Preserve static/instance callback selection, before/after ordering, receiver identity, invocation counts, delegate target/instance/singleton selection, and exception propagation. | Collections and wrappers | Preserve each collection's own null/count framing, item order, stack/queue reconstruction, comparer and mutation behavior, sparse dictionary handling, dimensional bounds, capacity/reuse, immutable/frozen reconstruction, and temporary-pool clearing. `NonGenerator` remains an existing enum value with its existing dispatch behavior. It is not permission to invent an undocumented generation policy. Preserve enum numeric values and public spellings even when they appear unusual.

## Generator, API, and mapping boundaries

- Each retained concrete type has one complete state body per operation on `LuminPackSerializer`. Previously approved convenience/compatibility methods may thin-forward. Ordinary field bodies can be expanded; recursion, unknown generic/runtime types, Union slots, Custom, and explicitly selected specialized contracts keep their required semantics. Preserve argument evaluation order, ref aliases, cursor synchronization, independent local/label names, and caller state.
- Full keeps the approved complete concrete API policy. Light additionally roots declared packable types. Minimal starts from actual serializer/API calls. Formatter dependencies remain separate from convenience-overload reachability. Generic fallback shapes remain callable; one generic operation owns one compact-id switch, rather than copying switches into wrappers.
- Assembly-level `[LuminPackable(typeof(...))]` declarations opt ordinary or generic referenced types into the same analysis and pruning. Repeat the attribute for several types; an open definition selects observed closed constructions. Read complete metadata for Local storage and retain the declared cases of an imported Union. Generate overrides only into eligible current-assembly partial cases, never a second metadata-type declaration.
- The approved visibility expansion makes generated class Union slots and overrides `public` with `EditorBrowsable(Never)`. Virtual dispatch, slot switches, framing, and sealing policy remain unchanged. Imported roots from older binaries with only internal slots need rebuilding for this path. Already compiled case bodies retain their own generic/runtime fallback boundaries.
- Incremental caches must preserve exact semantic dependencies, API overload binding, settings, diagnostics/locations, deterministic type/file identities, and retained-versus-fresh output. No live `Compilation`, `SemanticModel`, or symbol may escape into a cross-compilation frozen cache. Preserve cancellation, concurrency isolation, and collection of discarded compilations.
- Mapping is part of this contract: preserve automatic/manual mapper selection, member matching/conversions, ignored/missing members, generated partial signatures, constructor/binding behavior, mapper registration, and diagnostics. Serializer restructuring does not authorize mapper behavior changes.
- XML documentation must describe the actual selected type, overload, filtered members, storage versus wire layout, option ownership, and return units. Documentation generation must not change runtime dispatch or determine serialization independently of the canonical analysis.

## Change control and verification

README remains project introduction, installation and usage documentation. Do not add release notes, version-change summaries, upgrade/migration notices or development/performance experiment reports there; keep those records out of version control rather than in `docs`. Installation examples may state the current package version without narrating changes. This documentation boundary is mandatory and applies to release preparation as well as implementation work.

The owner explicitly requested evaluation of a unified `LuminBufferWriter` operation context on 2026-10-17, including both binary and JSON read/write contexts, subsequently making retention conditional on demonstrated performance value. The proposed scope covered migrating Core APIs and generated state parameters to the buffer class and using pooled contexts in convenience entries; it did not authorize changing any other serialization mechanism. That evaluation records the isolated implementation, storage lifetimes, root/Core ownership, API breakage, native evidence and repeated measurements. The experiment did not establish a net performance benefit, and the owner explicitly declined adoption. Existing context implementations remain the production authority; the earlier evaluation does not authorize a production migration.

Performance reviews must account for local machine variability. Use same-machine, same-run ratios against reference libraries such as MemoryPack and Nino as the primary comparison, with identical fixtures, API semantics, runtime, encoding/options, and allocation accounting. Report `LuminPack time / reference time` (lower is better), compare this ratio before and after an optimization, and retain absolute timings, repeated samples, dispersion, and environment details as supporting evidence. Shared machine fluctuations often affect all libraries, but cancellation is imperfect: interleave reference measurements where possible, repeat runs, and investigate regressions rather than attributing them automatically to noise. Do not mix results from different encodings, allocation policies, datasets, or machines into a claimed ratio.

When substantial competing machine load makes timing unreliable, use retained-image IL and native-code comparisons with identical runtime/JIT settings. Inspect stack frames, register saves and frame moves, reference-store helpers, instruction/call sites, local lifetimes, and tiering/PGO behavior. Distinguish static counts from executed work and non-tiered FullOpts from profiled Tier1. Structural improvement does not prove a latency target or replace later same-run reference ratios and allocation measurements. Avoid running throughput benchmarks while this measurement suspension is in effect.

Any mechanism replacement requires explicit authorization and a reviewable explanation of its behavioral and performance impact. Refactoring, dead-code removal, caching, or reducing IL/metadata is not such authorization. An uncovered historical correctness bug may be fixed while preserving its intended protocol/algorithm; record it as a bug fix, with a reproducer, rather than claiming the implementation was unchanged.

The established mechanisms may be replaced by a faster design after the user explicitly approves a concrete proposal. Before requesting that approval, prepare an isolated experiment, repeated before/after ratios against the same references, dispersion and allocation counts, and generated IL/native evidence where applicable. Explain successful and exceptional behavior, public API and wire compatibility, state ownership/cleanup, and target-platform effects. Keep unapproved alternatives outside the production implementation. A request to optimize a benchmark or reach a latency target does not itself authorize removing exception cleanup, reference tracking, or another established mechanism. Record the exact approved scope here when a replacement is accepted.

On 2026-10-17 the owner explicitly approved the fixed Union cursor proposal. Dense 64-bit dictionaries with independently proven raw keys may pass a local byte index through an additional hidden virtual slot of a local, non-generic, narrow class Union. Qualifying callback-free public raw fixed cases write the original tag and ordered fields through one shared Serializer implementation and return the absolute next index. The loop publishes it before the existing mutation/buffer checks. Original void slots remain; their existing tag wrappers forward to the same field implementation with no second tag. An exact-type guard must preserve inherited old-slot overrides. Unsupported, registered and caller-code paths publish the pending index before the original virtual/registry operation, then read back the resulting index, including after growth. Known non-fixed cases may provide a thin returning override with that same publish/call/read sequence, avoiding an extra root bridge without bypassing the original virtual slot. Preserve all exception cleanup and operation ownership. New public slots remain hidden with EditorBrowsable(Never), and retain the original sealing decisions.

Select this protocol using the canonical Union members and filtered field analysis, not an independent attribute scan. Private/property storage, volatile access, nullable fields, managed fields, serialization callbacks, Custom or specialized contracts do not acquire the fixed body. Generic virtual/cached-slot dispatch, wide-tag dispatch, imported roots, JSON, reads, size evaluation and the 32-bit dictionary enumerator retain their original boundaries. The shared body retains packed 32-bit block copies and 64-bit adjacency proofs/fallbacks. A future state-observing field operation must keep its publications rather than being silently converted into a local-cursor body. Root/case plans and their symbols remain compilation-local; frozen output caches must track nested Union cases, eligibility edits and automatic candidate relationships. The approved scope does not authorize buffer-context unification, a public configuration tier, new blanket bounds checks, or Git commits.

Review every new emitter, runtime subsystem, attribute, setting, and conditional path against this inventory. Add an entry when a mechanism is introduced. For details omitted here, compare the relevant source at the historical reference; absence from the table never permits redesign.

Run [CONTRIBUTING](../CONTRIBUTING.md)'s checks. `SerializerMechanismRegression` can additionally execute both analyzer versions on identical models and compare Union virtual bodies after payload API-owner renaming and normalization of optional `in` call-site syntax, exact binary bytes, JSON text, version gaps, cycles/shared aliases, values/layouts, nullable/enums, collection order, callbacks, and size results:

```text
dotnet run --project tests/LuminPackDocumentationTest -c Release -- --verify-mechanisms <absolute-path-to-historical-LuminPackGenerator.dll>
```

The historical comparison separately records the corrected sparse-slot size result: the original analyzer omitted one zero-length slot-table byte, while both analyzers write identical bytes. `SerializerSpecialModeBoundaryRegression` covers trailing additions/removals, complete consumption, gaps, and empty schemas in both specialized modes. `SerializerCustomFormatterRegression` checks that an actual unmanaged Custom argument retains its formatter while an ordinary constrained argument in the same compilation retains raw copying.

Performance optimizations may pass a class reference by value to the internal `SerializeUnion` state body. That body still snapshots the same reference before reading members. Public convenience APIs keep their signatures, Union slots remain virtual, generic slots retain their cached switch, tags remain in the virtual wrapper except for the approved returning-cursor path above, and each type retains one Union payload body. Value-type and unresolved generic `in` parameters retain their original convention; omitting an explicit `in` at those call sites still binds the original parameter. `SerializerCodegenPerformanceRegression` asserts this structure and exact output with repeated padded unmanaged structs. It also requires the existing 32-bit packed-view fallback for direct struct field batches and verifies null, empty, covariant, and multidimensional array reference behavior.

A 64-bit grouped copy of public unmanaged fields must prove every field's actual byte offset matches its original wire position before copying. Preserve all padding belonging to each raw struct, exclude gaps between fields, and retain typed field accesses when storage is noncontiguous. Private/property storage retains Local + As. Groups containing volatile fields retain field access semantics and cannot use the grouped memory copy. Never assume Auto layout is sequential or cache field-layout assumptions across types or compilations. Keep these operations exclusively in the 64-bit branch; the 32-bit branch retains the packed block-copy core for IL2CPP compatibility. The code-generation regression checks padded contiguous and noncontiguous models, volatile eligibility edits, and retained/fresh output after such an edit.

This adjacent-field optimization can include primitive-only groups and can copy input bytes into already constructed public field storage. Reading must prove every destination offset, preserve fresh/merge identity and constructor/callback timing, and retain the existing grouped fallback for noncontiguous structs. Constructor/pool temporaries and Union payload reads remain on their original paths; expanding additional interior-reference groups inside Union switch arms regressed the measured original graph despite reducing native instructions. Private/property storage and volatile loads/stores must not be bypassed. Inter-field alignment gaps and ignored storage do not become wire data merely because every selected field is unmanaged. The class field-copy review, retained outside version control, records native/IL tradeoffs, repeated reference ratios and an additional historical x86 header/aggregate failure reproduced with the original analyzer.

Ordinary object APIs may cache their cursor in a local between state-observing boundaries. Publish the cursor before invoking a formatter, Union/recursive operation, callback, or existing capacity/buffer check, and resume from the resulting state after operations that consume bytes. Preserve the original check/publication order and refresh buffer references after growth; do not retain a buffer byref across a resize. Compression retains its original shared writer cursor convention. Fixed field-only entries read their cursor once and publish it at completion. Fresh reads may skip copying a newly constructed result back into itself; merge reads must still populate the original instance after successful parsing, and private/property fields still use Local + As.

Source expansion must respect existing explicitly marked `MethodImplOptions.NoInlining` helper boundaries, such as sparse dictionary enumeration. Preserve their cleanup, mutation checks, independently renamed local identities, and fully expanded field operations inside the helper. Ordinary unmarked formatter helpers still expand. Runtime JIT hints are separate from source expansion: loop-bearing binary state bodies may let the JIT choose whether to inline them, while retaining one complete source implementation per type and operation.

Fresh dictionary entry storage starts with default keys and values. Its reader may use default-initialized local roots and then populate the unpublished entry array; keep element order, constructors, callbacks, reference identity, the existing bucket rebuild, duplicate/collision fallback, and final publication timing. A hash smaller than the bucket count can return itself as the exact remainder; all other hashes retain the original reduction algorithm. Fresh unmanaged lists may expose their existing backing array to the raw array read core. Keep their allocation, payload validation, count, version, and subsequent mutation behavior; reusable or compressed paths retain their separate semantics. On modern .NET, publishing the same list count must still invalidate existing enumerators.

The buffer-owned operation cursor is initialized before publication, and both owners must receive its exact storage address. BeginWrite initializes that storage through its internal out parameter; constructor cleanup and completion retain the original ownership and ordering. Binary and JSON constructors do not need a second assignment to the same cursor after BeginWrite returns.

Fresh reference-element lists may retain their exactly sized backing array and acquire an element address only after parsing the element into its existing default-initialized local. Preserve allocation, count/version, element order, nulls, constructors/callbacks, GC barriers, and publication timing; do not apply this path to reusable lists or managed value elements. On supported modern targets the array data-reference intrinsic avoids covariance checks and long-lived interior references. Legacy targets retain their established storage accessor. When an element symbol proves reference or value classification, emit only the applicable existing loop; undetermined generic elements retain the runtime classification and both storage paths. Do not expand a second complete formatter graph for a statically unreachable branch.

Generated architecture gates may use `Unsafe.SizeOf<IntPtr>()` so the JIT can fold the unchanged bitness decision without spending its method-inlining budget. Keep both source branches and the original 32-bit storage operations. This is not permission to remove the architecture fallback from generated IL.

Only compiler-marked integer cursor locals in mutually exclusive binary reader switch sections may share a local slot. Preserve every initializer at its original execution point, keep nested switches independent, and reserve collision-free names without renaming user fields. Never coalesce byrefs, simultaneously live cursors, or cursors across loop/function boundaries.

A compiler-marked binary writer or reader alias of its state's `GetCurrentSpanOffset()` may instead use that exact ref-return expression at each use. This removes an alias of the same stable cursor field; it does not merge distinct byref storage or reuse an old cursor value after a call. Preserve all writes, reads and publication boundaries. Keep rebound references, name observations and ambiguous nested bindings unchanged, and never identify a generated symbol solely by its spelling or rewrite a user member with the same name. Fewer source getter calls are not sufficient evidence of faster native code; retain required reloads after unknown operations and validate arithmetic substitutes against actual JIT output and repeated reference ratios.

Dictionary string recording widths may be cached inside a loop only when each element operation is the established string formatter or a proven raw unmanaged operation. Managed, Union, unresolved generic, and Custom element boundaries retain their own state observations. Keep key/value evaluation order, per-string advancement and buffer checks, sparse enumeration, and mutation detection. A 64-bit raw key/value pair may use the existing two-value core; exclude storage gaps between entries and preserve padding inside raw values. The 32-bit independent-value path remains unchanged. A dense unmanaged writer may publish its accumulated cursor after its callback-free loop and before the existing mutation check; reserve the complete variable-length destination first.

Dense 64-bit mixed dictionary writers may copy a proven raw Key or Value directly from its Entry field independently of the other member. Use canonical unmanaged storage eligibility, including nested Custom exclusions, and exclude specialized root contracts from this optimization. Ordinary unmanaged structs are eligible, including their complete padding. Preserve key-before-value evaluation and cursor publication before managed element operations. Never copy managed references, Entry hash/next metadata, inter-member gaps or entire mixed Entry arrays as wire data. Keep sparse enumeration, mutation detection, GC-tracked entry references, refreshed destination references after growth, and the 32-bit packed per-value fallback. Readers retain their fresh local roots, late entry publication, hashing, collision checks and duplicate-key fallback. An unmanaged key does not imply that its bits are its hash code or that buckets may be persisted.

Optional-state initialization may skip assigning the same options reference, but cleanup still resets reference tables and restores the same defaults. An empty writer reference state may skip clearing its empty map; nonempty and exceptional cleanup remain required. A cached binary string mode must track every public option mutation, preserve unknown-enum mapping and record-copy behavior, and remain a writer-construction snapshot. Flush releases a managed start reference by ref assignment; assigning default through that reference corrupts the caller's first byte. Preserve empty/repeated Flush and the legacy pointer release path.

The empty-reference test may remain inline while a nonempty writer table is cleared in a non-inlined helper. Preserve map clearing before the reference-id reset, invocation at the original successful/exceptional boundary, option ownership and allocations. This is code placement, not permission to omit cleanup or alter exception-filter visibility.

Short ASCII SIMD paths may use scalar lanes on 64-bit to avoid temporary stack staging, retaining the original 32-bit vector path. Validate all bytes and exact overlapping ranges before publishing a string. Tiny ASCII readers retain validating UTF-8 fallback and unchanged cursor behavior on failure. Computed-length UTF-16 writers may copy the exact validated raw code units directly; supplied-length and token overloads retain their separate truncation, termination, and error behavior.

The architecture audit found older direct typed accesses in scalar/enum state emitters and unmanaged sequence reads, predating this performance pass. These now follow the explicitly confirmed 32-bit constraint: scalar/enum operations reuse the architecture-aware Reader/Writer cores, and direct, stack-staged, and pool-staged sequence reads use block copies on 32-bit. The 64-bit typed fast paths remain. Record this as a compatibility correction to historical implementation gaps, rather than claiming those old emitters already obeyed the constraint.

The performance review also corrected two historical collection bugs without changing their wire format: raw unmanaged struct arrays/lists must reserve capacity before copying at the actual collection cursor, and their readers must skip the four-byte count before copying elements. Raw collection reads validate the complete variable-length payload in Release; fixed values retain the bounds policy above. The regression covers a 176,021-byte object, repeated nested collections, preserved padding and tail values, and truncated collection input.

The continuation also corrects the read-only-span writer constructor's accidental copy of its first byte: retain the caller's actual data reference, including empty spans, rather than constructing writable storage over a local byte. Raw unmanaged dictionary readers validate their count header and complete checked payload at the collection boundary in Release; their per-value cores remain unchecked. These are historical correctness fixes, not representation changes or new blanket fixed-value guards.

String boundary reservations include the entire dynamic record and its length header or token terminator. Grow an owned buffer and refresh its storage before accessing the new range; fixed caller spans must fail without overwriting their boundary. Do not silently truncate a computed UTF-16 token payload to available capacity or write a UTF-8 terminator past an exactly filled buffer. Keep UTF-8 conversion/retry, explicit supplied-length partial-copy rules, raw UTF-16 code units, null/empty normalization, cursor ownership, and check/publication ordering. Raw primitive/header helpers remain separate from these string-entry checks. The 2026-10-16 review found and corrected historical gaps here, reproduced by a fresh-buffer/fixed-span four-mode matrix and the larger dictionary string tests.
